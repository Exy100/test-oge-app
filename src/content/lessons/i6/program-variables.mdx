<Theory>
  <h3>Переменная хранит текущее значение</h3>
  <p>
    Строка x = int(input()) считывает целое число и записывает его в x.
    Следующий input() получает следующее число. В учебной лаборатории два числа
    вводятся в одном поле через пробел, но программа получает их как два
    последовательных ввода.
  </p>
  <svg role="img" viewBox="0 0 400 150" aria-label="Как работает присваивание">
    <title>Как работает присваивание</title>

    </text>
    <text x="14" y="119" fill="currentColor">
      {'Заменить только левую переменную'}
    </text>
  </svg>
  <h3>Сначала вычисли правую часть</h3>
  <p>
    В x = x + y сначала берут текущие x и y, вычисляют сумму, затем заменяют
    только x. Это присваивание, а не математическое равенство. Переменная y не
    меняется автоматически вместе с x.
  </p>
  <svg role="img" viewBox="0 0 400 150" aria-label="Последовательность строк">
    <title>Последовательность строк</title>

      {'x = x + y → новое x'}
    </text>
    <text x="14" y="77" fill="currentColor">
      {'y = x − y → используется новое x'}
    </text>
    <text x="14" y="119" fill="currentColor">
      {'print(x) → текущее x'}
    </text>
  </svg>
  <h3>Строки выполняются последовательно</h3>
  <p>
    Следующая строка использует уже обновлённые значения. Таблица трассировки
    должна сохранять все переменные после каждой выполненной строки. Вывод
    print(x) показывает значение в момент достижения этой строки, а не исходный
    ввод. Отдельный запуск начинает чтение входа заново.
  </p>
</Theory>

<Mistakes>
  <Mistake title="Выполнять строки одновременно">
    <p>
      После каждой строки обновляй таблицу. Следующая строка читает уже новое
      состояние.
    </p>
  </Mistake>
  <Mistake title="Путать = и ==">
    <p>
      В Python = присваивает значение, а == сравнивает. В условии это разные
      операции.
    </p>
  </Mistake>
  <Mistake title="Менять обе переменные после одного присваивания">
    <p>
      Изменяется только имя слева от =. Остальные значения остаются прежними.
    </p>
  </Mistake>
</Mistakes>
