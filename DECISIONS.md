# Архитектурные решения

## Формат записи ADR

Каждая запись содержит номер, дату, статус и связанные требования, затем:

- **Контекст:** исходная проблема, ограничения и источники решения.
- **Решение:** что именно меняется и на каком основании.
- **Последствия:** влияние на функции, проверки и оставшиеся обязательства.
- **Как откатить или обновить:** конкретные условия и действия для пересмотра.

Если решение принято владельцем, записать его ответ. Если оно следует из
проверенного документа, указать источник и отличать факт от инженерного выбора.

## ADR-001. GitHub Pages на текущем этапе

- Дата: 2026-10-04.
- Статус: принято по прямому указанию владельца «пока в пейджес».
- Связанные требования: `spec.md §4.1`, `§11.1`, `§12`; вопрос Q1.

### Контекст

Приветственная страница уже опубликована на GitHub Pages. Спецификация предполагает
Cloudflare Pages и Worker с API на том же домене. Владелец выбрал GitHub Pages
для текущего этапа разработки.

### Решение

Статическую часть тренажёра собирать с помощью Astro и размещать на GitHub Pages.
При настройке проекта учитывать адрес `https://exy100.github.io/test-oge-app/`
и префикс `/test-oge-app/` для страниц, ресурсов и клиентской навигации.
Способ размещения серверной части ИИ выбрать отдельно перед её подключением.

### Последствия

GitHub Pages обслуживает статические файлы; Worker там не исполняется.
Файл Cloudflare `_headers` не задаёт заголовки ответа GitHub Pages. Поэтому нельзя
объявлять требования к API на том же домене и всем заголовкам безопасности
выполненными на GitHub Pages. Их реализация и проверка остаются отдельными задачами.
Ключ OpenRouter по-прежнему должен храниться только на сервере.

### Как вернуться к исходной архитектуре

Перед переносом настроить Cloudflare Pages и домен, изменить базовый путь сборки,
проверить ссылки и ресурсы, подключить Worker на `/api/*`, проверить заголовки и
работу приложения. Переезд и отключение существующего сайта согласовать отдельно.

## ADR-002. Распределение потока 50/50

- Дата: 2026-10-04.
- Статус: принято владельцем («нормально - вперед» в ответ на предложение 50/50).
- Связанные требования: `spec.md §9.4`, `tasks.md T4.1`; вопрос Q2.

### Контекст

Исходное требование минимум 5 % на каждый выбранный номер невыполнимо при выборе
всех 25 номеров. Нижняя граница `min(5 %, 1/N)` убирала бы адаптивность при N >= 20.

### Решение

Половину вероятности распределять равномерно между выбранными номерами,
половину — пропорционально частоте ошибок по этим номерам. Для N номеров и
весов ошибок wᵢ при их положительной сумме:

`pᵢ = 0.5 / N + 0.5 × wᵢ / Σw`, где `wᵢ = 1 − точностьᵢ`.

При отсутствии статистики либо нулевой сумме весов выбирать равномерно.
Одинаковые веса также дают равномерное распределение. Это вероятности следующего
случайного выбора, а не обещание точного количества задач в короткой сессии.
Расписание отдельной очереди повторения ошибок (3/10/30) сохраняется.

### Последствия

Все выбранные номера продолжают встречаться, а слабые темы получают больший вес.
При N = 16 каждый номер имеет нижнюю долю 3.125 % (текущий предмет — информатика). Новый минимум заменяет 5 %
в спецификации и приёмочных проверках T4.1. Реализация и тесты относятся к Фазе 4.

### Как изменить решение

При изменении доли равномерного выбора совместно обновить спецификацию, критерии
T4.1, реализацию и тесты. Возврат к фиксированным 5 % требует ограничения N <= 20
и отдельного согласования с владельцем.

## ADR-004. Информатика — первый предмет

- Дата фиксации: 2026-10-05.
- Статус: принято по прямому указанию владельца «сначала для информатики делаем сайт».

### Контекст

Фаза подготовки математики завершилась в коммите `3d18075`. Владелец изменил
очерёдность предметов до начала реализации приложения.

### Решение

Текущий проект целиком ориентировать на ОГЭ по информатике. Предыдущие девять
документов сохранены побайтово в `docs/archive/mathematics/`. Активные spec/tasks,
модель данных, шкала, типы ответов, планы уроков, интерактивы, ИИ и статусы
пересмотрены под 16 номеров, 150 минут и максимум 21 балл.

Предметный объём: 45 уроков по 14 разделам информатики, 18 двумерных интерактивов,
5 трёхмерных учебных игр, 58 структурных подтипов генераторов и 24 кураторских
набора для двух альтернатив №13. Это проектные минимумы, не нормы ФИПИ.
Математические банки, 25 номеров, таймер 235 минут и геометрический порог в новый
предмет не входят. Общие требования приватности, доступности, детерминизма,
тестов, производительности и безопасности сохраняются.

### Последствия

Нужны файловые наборы ZIP/ODF, слова и буквенные последовательности, интерпретатор
«Робота», программирование, критерии на 3 балла для №14. Появились отдельные
задачи T2.10 и T2.11. Генератор файлов должен создавать реальные форматы,
а не менять расширение текстового файла. Минимумы математики не считаются
достижениями информатики, старые отчёты не выдаются за готовность нового приложения.

Сохраняются GitHub Pages и схема потока 50/50. Пример для всех 16 номеров:
нижняя вероятность каждого — 3.125 %. №13.1/13.2 считаются одним номером.

### Как вернуться к математике

Создать отдельный согласованный этап из архива, обновить официальную сверку
и оценить повторное использование общих компонентов. Не заменять активные
документы математическими без нового указания владельца.

## ADR-005. Рабочие настройки первой версии практики

- Дата: 2026-10-05.
- Статус: рабочий выбор агента; вопросы о языке и офисных редакторах заданы,
  ответы владельца пока не получены. Это не утверждение о пользовательском согласии.

### Контекст

Информатика содержит файловые работы и программирование. Их способ тренировки
в исходном математическом задании не описан. Приёмка структуры экзамена при этом
не зависит от выбора конкретного языка или офисного приложения.

### Решение

Основной учебный язык — Python 3. Офисная практика — скачиваемые наборы,
инструкции для LibreOffice, эталоны и самооценка по критериям. Для «Робота» —
локальный браузерный интерпретатор. Для Python — редактор, выгрузка исходника,
тестовые данные и инструкция запуска в локальной среде ученика.

### Последствия

GitHub Pages остаётся достаточным для статического интерфейса и файлов.
Полная офисная среда и исполнение произвольного Python в браузере не объявляются
реализованными возможностями. Учебные интерактивы отдельных операций обязательны.
Эталоны Python запускаются в среде разработки; это отличается от исполнения
пользовательского кода на сайте. ИИ не получает офисные файлы и не выдумывает
оценку их содержимого. Выбор библиотек ZIP/ODF оформить отдельной записью до установки.

### Как изменить решение

При ответе владельца обновить spec §1, §3.5, задачи практики и соответствующие
проверки. Для встроенных редакторов/исполнителя Python отдельно определить
ограничения, безопасность, производительность и зависимости до их реализации.

## ADR-006. Основа Astro и порядок подключения инструментов

- Дата: 2026-10-05. Инженерное решение для T1.1.

### Контекст

T1.1 требует рабочую команду verify, а предметные проверки описаны в следующей
задаче T1.2. GitHub Pages уже публикует main / (root), без отдельной сборки Astro.
Изменение исходников не должно оставлять сайт с неработающими путями ресурсов.

### Решение

- Node 24 LTS зафиксирован в `.nvmrc`; зависимости и lock-файл фиксируют версии.
  TypeScript 6.0.3 выбран по совместимости с Astro Check и typescript-eslint;
  переход на TypeScript 7 выполняется после поддержки обоими инструментами.
- На T1.1 verify выполняет настоящие lint, format check, typecheck, unit и build.
  T1.2 добавляет check:forbidden и check:coverage; пустые успешные команды не создаются.
  Полный состав verify из spec §17 обязателен к Gate 1.
- Сборка находится в dist. `npm run pages:prepare` копирует только готовую главную
  страницу, favicon, `.nojekyll` и `_astro` в корень. Эти результаты временно входят
  в коммит, чтобы существующая публикация main / (root) продолжала работать.
  Скрипт отклоняет неизвестные файлы dist, а не теряет новые страницы молча.
  Автоматизация и переход к публикации артефакта сборки относятся к T1.3.
- ESLint Astro, Prettier Astro, Astro Check, определения типов, Vite, globals и
  eslint-config-prettier — инструменты интеграции уже утверждённого стека;
  они не добавляют клиентские запросы или сторонние сервисы.
- Playwright поддерживает стандартные браузеры и явный путь к системному Chromium
  для облачной среды. Проверка только Chromium не выдаётся за прогон Firefox/WebKit.
- `dev` и `preview` используют `--ignore-lock`: Astro 7 автоматически переводит
  сервер в фон при обнаружении агента. Явный foreground необходим тестовому runner'у
  для управления запуском/остановкой и изоляции разных портов.

### Исправления зависимостей Lighthouse CI

У последнего Lighthouse CI 0.15.1 зафиксирован старый Lighthouse 12.6.1.
Первый `npm audit` нашёл 11 high, 1 moderate, 2 low в цепочке его инструментов.
Применены точные overrides: Lighthouse 13.5.0 (с актуальным Puppeteer без
уязвимого extract-zip), basic-ftp 6.2.2, tmp 0.2.7 и uuid 11.1.1.
UUID 11 сохраняет CommonJS API, используемый LHCI. Это зависимости разработки;
совместимость проверяется реальным `npm run lh`, а не только разрешением lock-файла.
Повторный audit после установки: 0 vulnerabilities. При обновлении LHCI overrides
удаляются только после повторного audit и прогона Lighthouse с прежними порогами.

### Последствия и откат

Исходник главной страницы — `src/pages/index.astro`, текст — MDX. Корневой index.html
не редактируется вручную. Временно изменён только промежуточный состав verify,
критерии завершения фазы сохранены. Для отката использовать прежнюю статичную
страницу из Git; для перехода к Actions согласованно изменить источник Pages,
workflow и удалить только сгенерированные файлы из корня.

## ADR-007. Автоматические проверки качества и поэтапного покрытия

- Дата: 2026-10-05. Инженерное решение T1.2.

### Контекст и решение

Скрипты должны обнаруживать неполноту по реальным исходникам, не по вручную
записанным числам. Реестры будущих генераторов/банков/интерактивов пока отсутствуют.

Минимумы spec §6.3, §9.5, §10.1–10.3 хранятся в coverage.config.ts без снижения.
Фазы накопительные: генераторы, банки и V01–V10 — с 3; уроки и их блоки — с 7;
каталог интерактивов, уровни 3D и живые встраивания в уроки — с 8. --phase=final
проверяет всё. currentPhase обновляется после приёмки gate фазы. Отсутствующие будущие
каталоги показываются как ноль и отложенное требование, не готовый контент.

Реестры — реальные TS-модули с именованными экспортами; код уроков не исполняется.
Для разбора MDX подключается официальный @mdx-js/mdx, для frontmatter — yaml
как прямые devDependencies. Это инструменты проверок утверждённого MDX-стека;
они не входят в клиентский бандл. Форматы подробно описаны в docs/quality-checks.md.

check:forbidden сканирует src, worker/src, tests. В тестах строковые/регулярные
литералы с отрицательными примерами не считаются заглушками; TODO в комментарии,
настоящие test.only/skip, any и подавления типов проверяются. Архив, документация,
зависимости и сгенерированная сборка не являются рабочими исходниками.
Директивы eslint-disable требуют ADR с конкретным путём; ts-expect-error — файла
теста и объяснения, затем tsc обязан проверить ожидаемую ошибку.

### Последствия и откат

Скрипты показывают количество и структуру зарегистрированного контента. Они не
доказывают математическую верность генераторов, качество текста, работоспособность
офисных файлов или учебный смысл игры; соответствующие тесты и ревью остаются в плане.
При изменении формата реестра адаптер, документация и тесты меняются вместе.
Снижение минимумов и отключение проверок не являются способом исправления ошибок.

TypeScript исключает только сгенерированные `_astro`, dist и отчёты проверок,
как уже настроенные ESLint/Prettier. При повторной проверке после pages:prepare
обнаружилось, что Astro Check анализировал минифицированный React из корня.
Исключение результата сборки исправляет область анализа; строгость и проверка
всех исходников приложения и Worker сохраняются.

Tailwind сканирует только src (`source('../')` от src/styles), чтобы тексты скриптов,
документации и отрицательных тестов не добавляли классы в production CSS.
Это обнаружено сравнением сборок после добавления проверок; страница проверяется
повторно в Chromium на desktop и экране 360 px.

## ADR-008. Первый полезный экран раньше оставшейся инфраструктуры

- Дата: 2026-10-05. Основание: владелец отметил, что видит только приветствие
  вместо работающего сайта. Приоритет изменён на видимый учебный результат.

### Решение

Отдельный шаг T1.8: главная с реальной практикой тем №1, №3 и №10, проверкой целого
ответа, тремя подсказками, вычисляемыми решениями, следующими задачами и краткой
теорией. Astro рендерит страницу; React управляет практикой. Прогресс только за
открытую сессию, без cookies, внешних запросов и фиктивной статистики.

Это авторские базовые упражнения по темам экзамена, не полный экзаменационный
вариант или официальные задания ФИПИ. Формулы и ответы вычисляются, перебираемые
наборы детерминированы. Функции находятся в src/lib/practice.ts; они ещё не заявлены
как полноценные Generator-контракты и не увеличивают минимум 58 подтипов в реестре.

### Последствия и возврат к плану

Изменяется порядок: T1.8 выполняется перед T1.3. Требования остальных задач,
включая CI, полный UI-кит, темы оформления, 45 уроков и финальные проверки,
сохраняются. Эта поставка не закрывает T1.4/T1.5/T1.7 или фазы генераторов/потока.
Текущие системные шрифты не требуют внешнего сервиса; self-hosted шрифты и полная
дизайн-система остаются в T1.4. Для расширения практики переиспользовать проверенные
функции через будущие типы, RNG и общий харнесс; не поддерживать два независимых
потока задач. При проблеме откатить один коммит T1.8, сохранив предыдущую сборку.

## ADR-009. CI и безопасный переход на публикацию артефакта Pages

- Дата: 2026-10-05. Шаг T1.3, следующий после первого полезного экрана.

### Решение

GitHub Actions проверяет каждый push и pull request: полный verify, npm audit,
Playwright Chromium/Firefox/WebKit/mobile, Lighthouse и Gitleaks по полной истории
Git и dist. Действия закреплены за commit SHA; бинарник Gitleaks — за версией и
SHA-256 из официального release manifest. npm ci сохраняет lock-файл; setup-node
кеширует npm. Отчёты хранятся в Actions семь дней, секреты в диагностике скрываются.

Публикация только из main и только после всех проверок: dist передаётся как Pages
artifact в отдельный job с pages:write и id-token:write. У job проверок только
contents:read. Pull request и другие ветки никогда не получают права публикации.
Главные публикации не прерываются следующей отправкой; для веток устаревшие
прогоны отменяются. Пороги, проверки и минимумы не ослабляются.

### Переход и проверка отказа

Намеренно неверный unit-тест проверяется в отдельной временной ветке, затем
удаляется. Ошибка должна остановить verify, не допустив публикацию. Исправленная
ветка проходит полный CI; в main переносится только исправленное состояние.

Переход выполняется несколькими коммитами T1.3: сначала workflow при сохранённой
старой сборке в корне, исправление обнаруженных ограничений прав, затем удаление
старых артефактов после успешного деплоя.
Это обоснованное исключение из правила одного коммита: удаление корневого HTML
до смены источника Pages создало бы промежуток с недоступным сайтом.
Уточнение 2026-10-06: попытка смены build_type штатным API с GITHUB_TOKEN получила
HTTP 403 Resource not accessible by integration. Поэтому deploy-job только
проверяет источник. Владелец однократно выбирает GitHub Actions в Settings → Pages.
Права workflow не расширяются, пользовательский PAT не запрашивается. До первой
успешной публикации артефакта старая корневая сборка остаётся в main.

### Последствия и откат

В репозитории остаются исходники; dist больше не копируется вручную в корень.
Новые маршруты Astro публикуются целиком, ограничение на единственную страницу
снимается. При красном CI опубликованная версия сохраняется. Для отката приложения
нужно вернуть нужный исходный коммит новым коммитом в main и дождаться зелёного CI.

## ADR-012. CSP на GitHub Pages и проверка HTTP-заголовков локально

- Шаг T1.6. Продолжение принятого владельцем ADR-001.

Astro 7.3.5 формирует meta-CSP с SHA-256 для собственных inline-блоков.
Хук сборки переносит meta до первого скрипта и добавляет объединение хэшей
в dist/_headers на основе public/_headers. Политика не использует unsafe-inline
или unsafe-eval. Referrer-Policy имеет также meta-эквивалент.

Документация установленного Astro (`security.csp` в config.d.ts) прямо указывает
на несовместимость ClientRouter с CSP. Маршрутизатор удалён; вместо него
используются обычные ссылки и нативные CSS View Transitions с reduced motion
и обычным переходом как fallback. Тест перехода сохраняет проверки темы до body,
туда/обратно и работоспособности практики; проверка внутреннего события Astro
заменена проверкой результата обычной навигации. Theme учитывает pageshow/bfcache.

Wrangler 4.147.0 — закреплённая dev-зависимость из предусмотренного стека
Cloudflare. Playwright запускает локальный pages dev и проверяет все заголовки,
затем работу приложения под CSP. Аккаунт Cloudflare и удалённый deploy не нужны.

nosniff, HSTS, COOP и Permissions-Policy остаются ограничением хостинга.

При переносе на совместимый хостинг нужно повторно проверить реальные ответы.
Подробности и команды — docs/security.md. Откат — revert коммита T1.6;
это удалит CSP, поэтому возврат ClientRouter требует пересмотра защиты.

Проверка npm audit обнаружила GHSA-wq5f-xc86-pv6w в sharp 0.35.4,
транзитивной зависимости Miniflare. Scoped override обновляет только этот sharp
до 0.35.5, уже используемого Astro. Порог high/critical не снижается;
дополнительный коммит T1.6 фиксирует исправление зависимости до публикации.

Полный CI T1.7 обнаружил различие loopback в Safari: upgrade-insecure-requests
применяется к HTTP-ресурсам localhost, в отличие от Chromium/Firefox.
Production-прогоны Playwright переведены на HTTPS с локальным краткоживущим
сертификатом OpenSSL в .cache. Самоподписанный сертификат допускается только
тестовым браузером и readiness-проверкой этих серверов; системное доверие и
проверка TLS установки зависимостей не меняются. CSP и её директива не ослаблены.

## ADR-014. Версионированный RNG и сравнение сред исполнения

- Шаг T2.1, spec §6.1.

Выбран FNV-1a по явно определённым UTF-16LE байтам и Mulberry32. Это небольшой
платформенно независимый код с эталонными последовательностями. Для целых
чисел используется rejection sampling; fork зависит от исходного seed и
JSON-пары с меткой. Публичные контракты и ограничения точности — docs/rng.md.

Miniflare закреплён как прямая devDependency в той же версии, которая уже
приходила с Wrangler. Тест запускает настоящий workerd; библиотека RNG
подключена отдельным ES-модулем к обработчику fetch. Это проверяет исполнение
исходного алгоритма в Workers, а не имитацию окружения Node. Браузерный тест
сравнивает тот же сценарий с Node во всех проектах Playwright.

После успешного Gate 1 currentPhase повышен до 2; количественные минимумы
следующих фаз сохранены. Интерфейс сайта и текущий банк практики этот шаг
не меняет. Откат — revert T2.1, миграции пользовательских данных не нужны.

## ADR-017. Проверка кратких ответов сохраняет смысл каждого формата

- Шаг T2.4, spec §7.1–7.2.

Одна функция ядра возвращает correct/incorrect/format_error и признак counted.
BigInt сравнивает целые точно; слова и последовательности не превращаются в
числа. Внешние пробелы удаляются через trim. Только последовательности допускают
внутренние обычные/неразрывные пробелы и обязательно получают уведомление
о записи на бланке. Unicode NFC и регистр применяются явно; похожие символы
разных алфавитов не подменяются. Полный контракт — docs/answer-checker.md.

У word в spec нет поля alphabet: печатный текст сравнивается без удаления
внутренних пробелов и пунктуации. Недопустимые управляющие символы отклоняются.
У sequence алфавит проверяется до сравнения. Приоритет верного ответа выше
commonMistakes; совпавшая типичная ошибка даёт локальное объяснение без ИИ.

Существующая практика использует новый checker через адаптер прежнего API
и сохраняет свой лимит 32 символа. Артефакты по этому API не оцениваются.
fast-check закреплён devDependency 4.10.2 согласно стеку и требованию T2.4;
добавлены воспроизводимые property-тесты без снижения проверок.
Откат — revert T2.4; сохранённые пользовательские данные не меняются.

## ADR-018. Неполный результат не имеет итоговой отметки

- Шаг T2.5, spec §7.3 и §9.7.

scoreVariant валидирует вариант и ответы, перепроверяет №1–12 и использует
только явно заданные оценки практики. Отсутствие оценки представлено null;
ноль — полноценная оценка. При неполной практике primaryScore/grade null,
отдельно возвращаются известная сумма и диапазон возможного результата.
Пропущенный краткий ответ даёт 0 в итоговом срезе; его format_error/counted
сохраняются отдельно и не изменяют статистику тренировочных попыток.

Явно принятое предложение ИИ имеет приоритет над исходной самооценкой,
но её значение и происхождение принятой оценки сохраняются. Сам текст
программы или запись локального запуска не дают баллов. Неизвестные задания,
повторы и доказательства от другой ветки №13 отклоняются на границе.

Год, источник и ограничения шкалы возвращаются из конфига вместе с результатом;
практика не объявляется официальной экспертной оценкой. Контракт — docs/scoring.md.
Откат — revert T2.5; новых зависимостей и миграций пользовательских данных нет.

## ADR-019. RichText с общей очисткой и нативным MathML

- Шаг T2.6, spec §4.1, §12 и §16.

Markdown-it и KaTeX из разрешённого стека формируют HTML, затем DOMPurify
очищает результат. HTML в Markdown отключён, ссылки/изображения не становятся
активными элементами. KaTeX работает с trust false и strict warn; ошибки
показывают безопасный исходник. Ограничены раскрытие макросов и размер формул.

Выбран KaTeX output mathml. Нативный MathML даёт доступную семантику формул
и не требует разрешать inline style в действующей CSP. Формула на главной
рендерится при сборке; браузерный KaTeX подключается только потребителям
React RichText, сейчас это исключённая из production служебная галерея.

Дополнительная зависимость вне буквального списка стека — isomorphic-dompurify
4.5.0, адаптер DOMPurify для Node и браузера. На Node он использует jsdom,
в браузере — собственный DOM. Это позволяет иметь единый санитайзер для SSR
и клиента без ручной очистки HTML. Все версии закреплены в package-lock;
аудит high/critical прошёл. Типы markdown-it/KaTeX — devDependencies.
При замене адаптера нужно сохранить серверную очистку и повторить XSS-тесты.

Серверный и React-компоненты копируют code.textContent через Clipboard API,
не исполняют содержимое и сообщают об отказе. Служебная страница доступна только
в dev. Контракт и ограничения — docs/rich-text.md. Откат — revert T2.6;
пользовательские данные не мигрируются.


Полный CI T2.6 выявил intrinsic width MathML в Firefox/WebKit при увеличении
текста 200% на 360 px. Явный min-width 0 у карточек сетки и ограниченная локальная
прокрутка контейнеров предотвращают растягивание страницы. Inline/display
размещение различается через display MathML; требования адаптивности не ослаблены.
Исправление публикуется дополнительным коммитом T2.6 без переписывания main.

## ADR-020 — Детерминированные рисунки и визуальные регрессии

T2.7 реализует FigureSpec средствами React, SVG и HTML без новых зависимостей.
Нативные таблицы и списки сохраняют доступность текста. SVG даёт векторную
чёткость; большие схемы имеют локальную прокрутку вместо уменьшения подписей.
Каждое ребро получает полосу и отдельные точки подключения; вес занимает

## ADR-021 — Версионированное хранилище и настройки

T2.8 использует строгие Zod-схемы семи областей spec §8 и namespace
`oge:informatics:v1:`. Legacy `oge.theme` переносится в settings; поддерживается
минимальная settings v0. Ранний маленький скрипт применяет безопасные параметры

доступа переводят состояние в память с явным уведомлением. Удаление использует
только известные ключи; соседние проекты на общем origin не затрагиваются.

старые версии приложения их игнорируют, восстановление возможно из JSON-экспорта.

## ADR-023 — T2.10: воспроизводимые ZIP и минимальный профиль ODF

библиотеки входят в lockfile; замена требует сохранения формата и проверок.

XMLValidator устаревшим. Для синтаксической проверки XML выбран отдельный
fast-xml-validator 1.4.2 (MIT), рекомендованный его API. Парсер остаётся для
проверки структуры документа; предупреждение deprecated не отключается.

## ADR-025 — T3.8: кураторские презентации и внутренние PNG в ODP

Дата: 2026-10-15 (Asia/Novosibirsk). Банк №13.1 содержит 12 фиксированных авторских

набор и побайтово сравнивают ZIP, а Office-проверка сверяет все файлы и манифесты.

## ADR-027. Генераторы №14 и проверка реального пересчёта ODS

Дата: 2026-10-15. Четыре подтипа используют собственные данные по 240 записей.
Исходные и эталонные файлы — ODS; CSV служит независимой копией данных для проверки,
а не подменой формата. Новых зависимостей нет. Реестр и численные модели остаются
чистым TS; изготовление ODS подключается лениво, отдельно от метаданных генератора.

OpenFormula объявляется только внутри новых таблиц, старые офисные примеры и
кураторские материалы не меняются. Эталон содержит построчные IF и три итоговых
формулы. Кэшированные результаты вычислены из данных; Office-проверка удаляет кэш
в проверяемых копиях и требует повторного расчёта в Calc. Простого совпадения
кэшированных чисел недостаточно. Исходные A:D, диапазон A2:D241 и ответы H2:H4
сверяются независимо. Чек-лист на 0/1/2/3 — учебная самооценка.

Тест 12 экспортов разделён на отдельные случаи с прежним стандартным лимитом
времени на случай. Кампания из 500 уникальных seed каждого нового подтипа
разбита на четыре последовательных пакета по 125: полное V8-покрытие делает XML
и хеширование существенно медленнее обычного запуска. Каждый seed проходит
тот же полный харнесс; ни один не пропускается. Лимит 60 секунд на пакет
сохраняется, прежние лимиты тестов не меняются.
Calc запускается пакетами по четыре файла, а не одним большим запросом: локальная
сборка LibreOfficeDev тратит значительное время на пересчёт; лимит 120 секунд на
вызов сохранён. `samples/14-files/` исключены только из форматирования, поскольку
их точные байты входят в манифест и проверяются тестами.

Совместимость XML в браузере: прямой импорт fast-xml-validator 1.4.2 загружает
транзитивный XML-парсер с глобальным Buffer. Браузерный тест подтвердил отказ
экспорта ODS. В production-проверке используется переносимый XMLValidator из уже
зафиксированного fast-xml-parser 5.11.2. API помечен deprecated в пользу нового
пакета; это временное осознанное исключение ради работы без Node-полифиллов и
новых зависимостей. Дополнительно явно проверяются недопустимые Unicode/control
символы и знак < внутри атрибутов; разрешены только пять предопределённых XML-экранирований.
DTD, пользовательские/числовые сущности, комментарии, CDATA и внешние ссылки запрещены ограниченным
профилем. Новые отрицательные тесты защищают эти ограничения. В Node золотые ODS
дополнительно проходят SyntaxValidator, в Calc — независимый пересчёт.
Вернуться к новому API после исправления переносимости его транзитивных зависимостей,
подтвердив браузерный экспорт и все отрицательные тесты. Единственное точечное
подавление `@typescript-eslint/no-deprecated` разрешено на вызове XMLValidator.validate
в `src/core/datasets/odf.ts`; остальные lint-правила и конфигурация не меняются.

## ADR-028. Семейства задач №15 и независимая проверка эталонов

Дата: 2026-10-15. Четыре подтипа используют существующий ограниченный интерпретатор

вместо вызова pixel для каждой точки; байты существующих PNG и архивов презентаций

тестов и пороги не меняются. Новые пакеты по 125 seed имеют лимит 60 секунд.
`samples/15-files/` исключены только из форматирования, точные байты проверяются.

20 минут: verify прошёл за 10 минут 29 секунд, офисные файлы и независимый
исполнитель Робота проверены, полный браузерный этап был прерван лимитом.
Двух ошибок аннотаций достаточно для установления причины: превышение времени
задания и отмена операции. Отказ конкретного теста этим прогоном не установлен.

`quality` и `browsers` теперь работают параллельно на одном коммите. Первый
сохраняет полный verify, audit, сканирование истории, офисные проверки и Робота;
второй — весь Playwright, axe, Lighthouse и сканирование готового dist.
Оба устанавливают зависимости по lock-файлу. Лимит каждого остаётся 20 минут;
таймауты тестов, retries, пороги и эталоны не меняются. Права проверок остаются
contents:read, действия и бинарник Gitleaks закреплены как прежде.

Pages-артефакт загружает браузерное задание из своей проверенной сборки.
Deploy требует успеха обоих заданий через needs: [quality, browsers].
Ошибка любой группы блокирует публикацию. Отчёты браузеров остаются в
quality-reports; покрытие и проверенные офисные файлы — в source-reports,
оба артефакта сохраняются семь дней даже при ошибке. Это уточняет ADR-009.

При обновлении состава проверок каждый новый обязательный job добавляется в
needs публикации. Объединять задания снова можно после измерения, подтверждающего,
что полный набор стабильно укладывается в общий лимит; проверки не удаляются.

## ADR-030. №16: четыре алгоритма, реальные Python-эталоны и проверка локальных запусков

- Дата: 2026-10-15.
- Статус: принято в рамках T3.12 по spec §6.2 и критериям tasks.md.

### Контекст и решение

№16 требует создания программы, полных входных данных и результатов, вычисленных
по фактическому вводу. В первой версии Python выполняется локально (spec §4.1,
§6.2), полный клиентский движок не предусмотрен. Выбраны четыре структурно разных
алгоритма: отбор с суммой, цифры числа, соседние пары и непрерывная цепочка.
Параметры, эталон, условие и десять тестов воспроизводятся по seed. Все входные
ограничения, поведение при отсутствии подходящих данных и формат вывода заданы явно.

Чистый TS-оракул вычисляет ответы из входа. Эталоны используют потоковые Python-циклы
с постоянной памятью и реально исполняются CPython в проверках. Ноль как число,
отрицательный максимум, перекрытие пар и цепочка в конце входят в граничные тесты.
У каждого подтипа 500 различных seed и три золотых снимка. Двенадцать наборов
с 27 файлами каждый сохранены в samples/16-files с CC0-1.0 и SHA-256.
Побайтовые payload исключены только из форматирования; их целостность проверяется.

Экспортированный check.py запускает отдельный процесс стандартного Python через
sys.executable -I, без shell, с временным рабочим каталогом и лимитом 2 секунды
на тест. Возвращённый код, таймаут и числовой вывод участвуют в оценке. Это обычный
локальный запуск доверенного файла с правами пользователя, не песочница для
чужого кода. Это прямо объяснено в README каждого набора. Память и файловые права
этого локального скрипта не объявляются изолированными.

assessProgramRuns в ядре принимает только сведения о внешних запусках и не
исполняет Python: exitCode должен быть 0, timedOut — false, stdout должен
совпадать с вычисленным ответом. Учебные баллы 0/1/2 соответствуют отсутствию,
части и всем успешным тестам. Сохранение файла не засчитывается. Критерии не
называются официальными, конечная выборка не выдаётся за доказательство.

### Проверки и последствия

Тестовый CPython-исполнитель для доверенных эталонов запускает 20000 случаев
за отдельный ограниченный процесс: 20 секунд CPU, 256 MiB памяти, 30 секунд
внешнего времени. Эти POSIX-ограничения принадлежат Linux-тестам, а не
экспортированному Windows/macOS/Linux скрипту ученика. Программа не входит в
клиентский runtime. check:python отдельно проверяет 324 файла, 120 реальных
запусков, все экспортированные check.py и отрицательные сценарии. Команда добавлена
в source-job CI, deploy по-прежнему требует обе группы проверок.

Новые зависимости, suppressions, изменение порогов и ослабление прежних тестов
не понадобились. Файловый формат py уже поддержан существующей схемой. Публичный
редактор и серверное выполнение не добавляются на этом этапе; T3.13 остаётся
следующей задачей, Gate 3 и currentPhase не закрываются этим решением.

### Как обновить

Изменение алгоритма seed, условий или файлов требует новой версии генератора
и повторной проверки эталонов, хешей и архивов. Будущий запуск чужого Python
на сервере или в браузере требует отдельного решения об изоляции и ресурсах;
локальный check.py нельзя использовать как серверную песочницу.

## ADR-031. Детерминированный сборщик вариантов и отдельный комплект для разбора

- Дата: 2026-10-15.
- Статус: принято в рамках T3.13, spec §6.4 и §9.5; завершение фазы 3.

### Контекст и решение

Существующая VariantSchema и подсчёт баллов хранят ровно 16 заданий с одной
выбранной работой №13. Обе альтернативы должны быть доступны в комплекте,
но нельзя создавать семнадцатое задание или включать вторую работу в сумму.
Схема Variant, хранилище и scoring не меняются. buildVariant(seed, selection)
собирает generated, buildFixedVariant(id, selection) — fixed из V01–V10.
variant13Alternatives(seed) отдаёт обе работы вне массива scoring.
API по умолчанию выбирает presentation для просмотра/разбора; явный выбор
ученика и предупреждение при смене самооценки относятся к UI фазы 6.

Именованные RNG раздельно выбирают генератор каждого номера и набор каждой
ветки №13. Переключение работы не меняет остальные задачи. Генераторы проходят
свои verify; максимум проверяется по конфигурации. Кураторские задания глубоко
копируются, реестр фиксированных id/seed заморожен. Версия informatics-variant-v1
и seed каждого номера дают воспроизводимость без часов и случайности платформы.

### Файлы и границы интерфейса

createVariantDataset проверяет VariantSchema и соответствие канонической сборке
по id/seed/ветке, затем объединяет семь исходных наборов как самостоятельные ZIP
с манифестами. Комплект содержит 19 файлов, включая условия, решения и обе
альтернативы №13. Существующие лимиты 100 записей/1 MiB на файл/8 MiB суммарно/
10 MiB на ZIP не увеличиваются; исходные пути, данные и хеши сохраняются.
Архив предназначен для разбора, это явно написано в README, документации и
служебном просмотре. Его нельзя выдавать за исходные материалы экзаменационного
режима с закрытыми до конца эталонами; такая проекция относится к фазе 6.

CLI выгружает один фиксированный/генерируемый комплект или все десять. Сохранены
ZIP, манифест и читаемый Markdown каждого V01–V10. JSON-манифесты исключены
только из автоформатирования как воспроизводимые генерируемые данные. Их содержимое,
архивы и реальные файлы проверяются. /dev/variants существует только при разработке;
таймер, экзаменационные маршруты и история попыток в этот шаг не входят.

### Проверки и последствия

1000 различных seed для обеих работ №13: 16 номеров, 21 балл, детерминизм,
согласованность verify, неизменность прочих номеров при выборе. Все 58 подтипов
действительно встречаются в кампании. Файлы всех десяти фиксированных вариантов
проверяются с обоими выборами, сохранённые ZIP воспроизводятся побайтово.
Проверены полный и неполный результат, отклонение чужой ветки №13, изоляция банков,
ошибки id/seed/номеров/ответов, CLI и одинаковость Node/Worker/браузеров.

Первый общий прогон выявил дорогой общий matcher больших ZIP и повторную сборку
тысячи вариантов ради проверки выбранных подтипов. Байты теперь сравниваются
через точный Buffer.equals, а наличие всех 58 подтипов проверяется внутри каждого
пакета из 250 seed основной кампании. Число seed, обе ветки, CRC, SHA-256 и
сравнение всех байтов сохранены; лимиты тестов не повышались.

check:variants использует существующие независимые Python-оракулы и проверяет
975 вложенных файлов: 100 реальных запусков Python и 80 полей Робота. Calc
открывает 20 новых ODS, исходные ячейки сохранены; кэш результатов удалён,
пересчитаны 2430 формул и 30 ответов. Кураторские файлы побайтово совпадают
с уже проверенными ODT/ODP. Команда и отчёты добавлены в source-job CI.

После достижения минимумов фазы 3 currentPhase повышается с 2 до 3;
текущий verify теперь требует все реестры этой фазы. Пороги, прежние таймауты,
retries, визуальные эталоны, права workflow и лимиты архивов не ослабляются.
Новых зависимостей и suppressions нет. Закрытие Gate 3 требует функциональных
проверок и полного зелёного CI, а не одного количественного отчёта.

Первый CI коммита 0ed8feb прошёл все 386 браузерных тестов и Lighthouse,
но прежняя кампания file-quote-v1 на 500 seed превысила 30 секунд.
В file-search.test.ts общий matcher Uint8Array заменён точным Buffer.equals
для распакованных файлов и повторного ZIP. Все 500 seed каждого из трёх
подтипов, SHA-256, CRC, независимый поиск и проверки детерминизма сохранены.
Локальный профильный прогон всех 16 тестов ускорился с 20,88 до 6,39 секунды;
лимит 30 секунд, общий CI и пороги остались прежними.

### Как обновить

Изменение выбора генератора, схемы taskSeed или фиксированного seed требует
новой версии сборщика и повторной проверки снимков, архивов и миграции сохранённых
попыток. Для будущего экзаменационного UI передавать только разрешённые исходные
материалы, а решения открывать после завершения; пакет для разбора остаётся отдельным.

## ADR-032. Семантика адаптивного потока и повторений

- Дата: 2026-10-15.
- Статус: принято в T4.1; уточнение spec §9.4 и ADR-002.

### Контекст и решение

Формула 50/50 уже согласована, но для реализации нужно определить вес номера
без наблюдений и точку отсчёта интервалов. Наблюдения по такому номеру остаются
отсутствующими: accuracy=null. Для планирования используется средний вес ошибок
изученных выбранных номеров. При отсутствии наблюдений и нулевой сумме весов
распределение равномерно. Неизученный номер не получает выдуманный вердикт.

Чистое ядро хранит automatic attempts/correct и отдельные self/aiAccepted
attempts/credit. Практический credit увеличивается на score/maxScore из examConfig.
Номер 1–12 принимает автоматический результат, 13–16 — оценку практики.
Отсутствие оценки и пропуск не добавляют попыток. Форматная ошибка оставляет
активное задание и все счётчики прежними. Ядро принимает уже полученную оценку,
не выдаёт её за запуск программы или автоматическую проверку офисного файла.

Ошибка/неполный балл ставят конкретную ссылку generatorId+seed в очередь.
dueAfter — число других завершённых задач, оставшихся до возврата. После трёх
таких задач выдаётся первая проверка. Её полный успех назначает интервал 10,
следующий успех — 30, третий успех удаляет запись. Ошибка обнуляет продвижение
до интервала 3. Пропущенный или неоценённый возврат сохраняет ступень и ждёт
три другие задачи. Интервалы считаются последовательно, не все от первой ошибки.

Готовые подходящие повторения обслуживаются в порядке очереди перед случайной
выдачей. Скрытые выбранными номерами/веткой №13 записи остаются в очереди.
Одна ссылка имеет одну запись; новая ошибка заменяет её расписание. Правильное
случайное попадание той же кураторской ссылки не закрывает назначенный возврат.
Конечные банки допускают естественные случайные повторы.

### Детерминизм, границы и последствия

Версия informatics-stream-v1, seed сессии и индекс случайной выдачи создают Rng;
fork разделяют выбор номера, источника и seed кураторского набора. Повторения
не расходуют индекс случайной выдачи. Seed генерируемого задания содержит версию,
hashSeed сессии и индекс; это короткая воспроизводимая ссылка, не криптографический
идентификатор. Исходный порядок номеров/источников не влияет на результат.
Состояние проверяется, копируется и поддерживает JSON round-trip с активной задачей.

Каталог связывает ядро с реальными 58 генераторами и обоими банками №13,
не переносит UI, браузерное хранилище или Node API в двигатель. Повторный next
не меняет карточку. Смена выбора снимает её, сохраняя очередь и статистику.
Лимит очереди 1000 совпадает с существующим хранилищем; переполнение и небезопасные
целые отклоняют переход целиком. UI уведомлений и адаптер хранения — следующие
задачи фазы 4. Схема существующего localStorage в T4.1 не изменяется.

Проверяются точная формула и реальная частота выборов, интервалы, фильтрация,
самооценки, ошибки границ, восстановление и одинаковые сценарии в Node/Worker/браузере.
Правило вероятностей относится к случайным выдачам; очередь не обещает точных
долей в короткой сессии. Новых зависимостей, изменения порогов и таймаутов нет.

### Как изменить

Изменение нейтрального веса, интервалов, сброса ступени или схемы task seed требует
новой версии двигателя, обновления документации/снимков и миграции сохранённой
сессии. Изменение самой формулы 50/50 требует пересмотра ADR-002 с владельцем.

Первый CI T4.1 (f481a43) подтвердил 390 браузерных тестов и Lighthouse, но
монолитная кампания 500×20 переходов превысила 30 секунд с coverage на сервере.
Кампания разделена на четыре пакета по 125 seed. Во всех пакетах сохранены
20 переходов на seed, оба сравниваемых состояния, JSON-восстановление,
неизменность входа и уникальность ссылок. Общий matcher заменён стандартным
Node isDeepStrictEqual: сравнение всех полей/значений остаётся строгим,
включая прототипы и знаковый ноль. Лимит каждого теста 30 секунд и всего job
20 минут не менялись. Алгоритм и схема сессии остались прежними.

## ADR-033. Процесс со сверкой с экзаменом и вертикальными срезами

- Дата: 2026-10-15.
- Статус: принято по указанию владельца («перепиши PROMPT.md и tasks.md») после аудита
  качества кода и реализации.
- Связанные документы: `PROMPT.md`, `tasks.md`, `STATUS.md`; `spec.md §3`, `§6`, `§10`, `§18`.

### Контекст

Аудит 2026-10-15 показал высокий инженерный уровень (строгие типы, 500 seed'ов
на генератор, независимые оракулы, безопасность), но и расхождения с реальным
экзаменом, которые прежние критерии не ловили. Интерпретатор «Робота» отклоняет
составные условия; у №5 нет формата с неизвестным параметром; наборы №11
слишком малы, чтобы тренировать поиск; `difficulty` — константа. Кроме того,
ядро почти не используется сайтом: главная работает на отдельной модели задач.
Критерии «Готово, когда» измеряли форму (число подтипов, отсутствие заглушек,
покрытие), а не соответствие экзамену и пользу для ученика. Агент выполнял их
добросовестно, но цель за ними не проверялась.

### Решение

1. Реальный экзамен — первый источник истины о предмете. При расхождении spec/tasks
   с форматом ОГЭ — вопрос владельцу, а не буквальное выполнение.
2. Матрица форматов `docs/exam-matrix.md` и экзаменационные фикстуры
   `tests/fixtures/exam/` (данные о формате с указанием источника, без копирования
   текстов в банк, spec §3.6) становятся частью приёмки генераторов и проверок.
3. Фаза — вертикальный срез до опубликованного сайта. Новое должно использоваться.
4. Предметное ревью человеком (`docs/reviews/phase-N.md`) и пилоты с учениками
   входят в Gate. Gate, ожидающий только человека, получает `[~] ждёт ревью`
   и не блокирует следующую фазу до Фазы 10.
5. Добавлены запреты выполнения «для галочки» и построения «на будущее» (PROMPT.md §4.11–12).
6. `STATUS.md` — короткое текущее состояние. Прежний файл перенесён без изменений
   в `docs/status-history.md`.

Изменения плана. Принятые задачи T0.1–T3.13 и T4.1 и их тексты не меняются. Номера задач
Фаз 3 и 4 сохранены, потому что в них идёт работа: новые задачи сверки добавлены
в конец Фазы 3 и выполняются до T4.2. В остальных фазах работа не начата, номера перестроены.

## ADR-034. T3.18: правила React-хуков, доступности JSX и ревизия зависимостей

- Дата: 2026-10-15. Задача T3.18 (ADR-033). Выполнена раньше T3.14: у среды владельца
  нет доступа к doc.fipi.ru, а T3.18 от источников не зависит.

### Решение

- Новая dev-зависимость `eslint-plugin-react-hooks` 7.1.1 (PROMPT.md §4.9): конфигурация
  `flat['recommended-latest']` для `**/*.tsx`. Подключён и ранее неиспользуемый
  `eslint-plugin-jsx-a11y-x` 0.2.0 (`recommended`).
- Найдено 10 нарушений, все исправлены кодом, без отключения правил:
  - флаг «остров готов» (`useEffect(() => setReady(true))`) в шести компонентах заменён
    общим `useHydrated` на `useSyncExternalStore`: `false` в серверном HTML и при гидратации,
    `true` после неё — та же семантика без лишнего рендера из эффекта;
  - `Settings` читает хранилище через `useSyncExternalStore`. Для стабильного снимка
    у `LocalStore` появился счётчик `revision`, который растёт при каждом оповещении;
  - object URL наборов в dev-галереях создаются вместе с набором, эффект их только освобождает;
  - `Disclosure` фиксирует начальное `open` через `useState`, а не чтением ref при рендере.
- Единственная настройка правила: `jsx-a11y-x/no-noninteractive-tabindex` дополнительно
  разрешает роль `region`. Прокручиваемая область рисунка с `role="region"` и подписью
  обязана получать фокус с клавиатуры (axe `scrollable-region-focusable`). Это расширение
  списка ролей, а не отключение правила: `tabIndex` на других неинтерактивных элементах
  по-прежнему ошибка.
- Ревизия зависимостей: каждая используется кодом, тестами, конфигурацией или скриптом
  `package.json`; `@types/*` — компилятором TypeScript. `fast-xml-validator` нужен только
  тесту `spreadsheets.test.ts` и перенесён в `devDependencies` (версия та же).
- Tailwind v4 подключён одной строкой `@import 'tailwindcss'` и даёт только базовый сброс
  стилей; utility-классов в коде нет. Стек spec §4.1 без владельца не меняется: вопрос Q-I7.

### Последствия и откат

Новые правила входят в `npm run lint` и verify. Откат — удалить плагин и блок `**/*.tsx`
в `eslint.config.mjs`; исправления кода остаются корректными и без правил.

- Время полной проверки сохранено: тяжёлые кампании файлов запускаются первыми
  через `scripts/test-sequencer.ts`, чтобы новая кампания без кеша длительности
  выполнялась одновременно с остальными. Ни один тест не исключается. Примеры
  каждого балла №14 проверяются отдельными тестами с прежним таймаутом 5 секунд;
  сравнение полных байтов через Buffer.compare заменяет затратное сравнение
  каждого элемента средствами assertion-библиотеки. Лимит CI 20 минут сохранён.

- Первый CI T3.16 выявил тот же затратный поэлементный обход в двух золотых
  и трёх сохранённых архивах №14. Все сравнения полных архивов нового набора тестов
  используют Buffer.compare, включая повторную генерацию. Это проверка каждого
  байта, без замены на выборку/размер/хеш; прежние 5 секунд сохранены.

- Повторный CI T3.16 ([39009671165](https://github.com/Exy100/test-oge-app/actions/runs/39009671165))
  превысил 20 минут в verify; одновременно выявлен таймаут объединённого CLI-сценария
  списка/выгрузки №13. Проверка XML теперь использует Unicode-проверку запрещённых
  символов и сканирует только разделители разметки, сохраняя обработку кавычек и
  запрет `<` внутри атрибута. Парсер не строит неиспользуемые пути обратных вызовов
  и не преобразует текст ячеек в числа. Границы Unicode и атрибуты с `>`/`<`
  проверены отдельно; формат и байты генерируемых файлов не меняются.
- Уточнение ADR-029: полный набор unit-тестов распределён штатным Vitest `--shard`
  на три непересекающиеся группы. Все группы собирают V8 coverage и blob-отчёт;
  отдельное обязательное задание требует три непустых blob и объединяет результаты
  через `--merge-reports` с исходным `vitest.config.ts` и порогом строк 90%.
  Порог 0 в частичной группе означает только сбор данных: такая группа сама
  не разрешает публикацию. Независимые проверки офисных файлов/Робота/Python/
  вариантов вынесены в отдельный обязательный job. Все прежние команды verify
  исполнены группами, локальный `npm run verify` сохранён целиком. Deploy требует
  quality, все unit-группы, общий coverage, файлы и браузеры. Лимиты 20 минут,
  прежние таймауты отдельных тестов и остальные пороги сохранены.
- В `src/core/datasets/odf.ts` допускается ровно одно локальное отключение
  `no-control-regex`: шаблон намеренно перечисляет запрещённые XML 1.0 управляющие
  символы для их отклонения, а не для включения в документ. Остальные lint-правила
  действуют; границы разрешённых и запрещённых символов проверяются тестами.

## ADR-040. T4.2: публичная карточка на обновлённом ядре

- Дата: 2026-10-17, Asia/Novosibirsk. Продолжение по плану владельца.
- `/stream/` соединяет движок T4.1 с актуальным реестром. С главной есть явная
  ссылка; доступны №1–16 и обе альтернативы №13. Подробные фильтры/URL — T4.3.
- `TaskCard` использует `checkTaskAnswer`; текстовое поле сохраняет точные числа,
  кириллицу и ведущие нули. Ошибка формата не отправляет результат. Корректно
  оформленный ответ отправляется один раз; переход применяет событие к движку.
  Схемы берутся из `task.figure`, файлы — из общего `createTaskDataset`.
- Самооценка №13–16 требует подтверждения; отсутствие оценки сохраняется как null.
  Учебный запуск Робота не становится официальным баллом. Python редактируется
  и выгружается для локального запуска с готовым checker; браузерный Python не добавлен.
- Редактор — доступный textarea: Enter вводит строку, Tab переводит фокус.
  Кнопка выгрузки создаёт Blob из текущего текста; URL освобождаются при повторном
  скачивании/смене карточки. Асинхронная подготовка файлов игнорируется после
  размонтирования. HTML-корпус показывается текстом; бинарные форматы не декодируются.
- Первая задача уже находится в статическом HTML; сервер и гидратация используют
  один начальный seed. До гидратации fieldset отключает действия. Первый переход
  получает crypto.randomUUID для следующих выборок, сохраняя текущий ответ, счётчики
  и очередь повторений. useHydrated включает действия без подмены условия;
  эффекты не выполняют синхронные setState. Место потока зарезервировано.
- Сессия, код и черновик пока живут до перезагрузки/смены задачи — это прямо
  объяснено ученику. Постоянное хранение относится к T4.5, замена старой практики
  на главной — к T4.7. Новые недоступные пункты меню не показываются.
- Dev-галерея проверяет 36 официальных фикстур только по параметрам/ответам;
  условия ФИПИ не копируются в приложение. Галерея исключена из production.
  Сохранённая заготовка 043cc95 адаптирована к v2, новым схемам и правилам React.
  Q-I6 (предметное ревью) и Q-I8 (расхождения №16) остаются открытыми.

- Первоначальный Lighthouse показал нагрузку KaTeX/Markdown на первый просмотр.
  Astro передаёт безопасный HTML начального условия, RichTextView сохраняет
  прежний DOM/копирование кода; полный renderRichText загружается только при
  переходе. TaskCard принимает только результат этого форматтера, не сырой HTML.
  Переход блокирует конкурирующие действия и атомарно меняет состояние и HTML;

  с динамического импорта по кнопке. Порог LCP 2,5 с и performance 90 сохранён.

## ADR-041. T4.3: фильтры, ограниченный подбор и ссылки

- Дата: 2026-10-17, Asia/Novosibirsk. Продолжение по плану владельца.
- Фильтры страницы хранятся в URL отдельно от состояния движка: номера, тема,
  вычисленная сложность, повторение ошибок и ветка №13. Проверка выполняется по
  `TaskInstance.topics/difficulty`, а не по названию генератора. Форматы экзамена
  и правила вычисления сложности T3.15/T3.16 не меняются.
- Подбор конечен: до 16 детерминированных seed на генератор и все существующие
  seed выбранного банка №13. Первый подходящий экземпляр каждого генератора
  образует пул; у банка сохраняются все подходящие наборы. Номер выбирается
  по прежней формуле 50/50 среди номеров с кандидатами, затем источник и seed.
  Число подходящих генераторов не увеличивает вероятность номера. Номера без
  кандидатов перечисляются на странице; пустое пересечение показано отдельно,
  подмена темы/сложности запрещена. Это ограниченный поиск, не доказательство
  отсутствия подходящего seed во всём пространстве. Повтор подбора меняет seed
  сессии; успешные случайные выдачи увеличивают прежний счётчик draws.
- Очередь ошибок проверяет те же фильтры. Режим «только повторение» выбирает
  только готовые записи, сохраняет интервалы 3/10/30 и объясняет пустую очередь
  либо оставшееся ожидание. Выдавать новые задачи за ошибки или искусственно
  уменьшать ожидание при нажатии «Повторить подбор» нельзя. До T4.5 очередь
  остаётся в памяти вкладки, что указано в интерфейсе.
- `task/seed` задают точный экземпляр, включая кураторский seed. Минимальная
  ссылка выводит номер/ветку из задания; явные противоречащие фильтры отклоняются.
  Проверяются дубликаты параметров, длины, источники, формат номеров и сложность.
  Режим повторения переносится, история ошибок и оценки через ссылку не передаются:
  получатель видит конкретную задачу, а последующие повторы используют его очередь.
- При смене фильтров добавляется запись History, при следующем задании адрес
  обновляется без роста истории. Back/Forward восстанавливают задачу и фильтры,
  сохраняя статистику вкладки без фиктивного ответа. Подходящая неотвеченная
  текущая задача, в том числе готовое повторение, сохраняется при применении фильтров.
  Ошибка загрузки сохраняет URL, карточку, ответ, черновик, очередь и статистику.
- Первая карточка остаётся в статическом HTML; query восстанавливается после
  гидратации, поскольку Pages не исполняет серверный код. Форматтер остаётся
  отложенным. Clipboard API имеет доступный fallback с полем ссылки; pathname
  берётся из текущего URL, поэтому префикс GitHub Pages сохраняется.
- Проверки и пороги не ослабляются. Для полного поиска вместо ограниченного
  потребуется отдельный конструктивный API генераторов; число 16 не используется
  как оценка полноты экзаменационных форматов. Существующие пробелы №16 и
  предметное ревью Q-I6 этим интерфейсным шагом не закрываются.

## ADR-042. T4.4: последовательная помощь и группы браузерного CI

- Дата: 2026-10-17, Asia/Novosibirsk. Следующий шаг по плану владельца.
- `TaskGuidance` раскрывает три подсказки по порядку и по одному элементу
  `TaskInstance.solution`. Решение можно начать независимо от подсказок; ученик
  сам выбирает глубину помощи. Чтение не отправляет результат и не очищает код,
  ответ или черновик. При смене задания/попытки компонент сбрасывается вместе с карточкой.
- Текст, код и формулы решения выводятся через общий безопасный форматтер;
  он загружается при первом раскрытии, сохраняя быстрый статический первый экран.
  Длина ограждения блока кода превышает любую последовательность обратных кавычек
  внутри него. Копирование не исполняет код и не подменяет программу ученика.
- Пояснение неверного краткого ответа берётся из результата `checkTaskAnswer`.
  Нормализация совпадает с проверкой, а правильный ответ/допустимая альтернатива
  проверяются раньше ошибок. Для неизвестного ответа персональная причина не
  выдумывается. Список типичных ошибок можно раскрыть отдельно, включая №13–16;
  это справка из задания, а не автоматическая оценка практической работы.
- Фокус переходит на открытый шаг; кнопки объявляют состояние и контролируемую
  область. Анимация применяется только к новому шагу и отключается общими
  `prefers-reduced-motion` и пользовательской настройкой. Асинхронная загрузка
  не обновляет размонтированную карточку и не стирает прежние данные при отказе.
- Несколько формул прежде создавали повторяющиеся landmarks «Формула».
  Обёртка MathML теперь имеет `role=group` и сохраняет название/tabindex:
  формулы доступны клавиатурой и больше не засоряют список областей страницы.
  Блоки кода получили tabindex=0 для клавиатурной прокрутки; обе реализации
  кнопки копирования распознают pre с атрибутами. Проверки структуры и доступности
  сохранены, включая прежний сценарий вариантов.
- Браузерный CI T4.3 приблизился к лимиту 20 минут. В T4.4 тесты выполняются
  двумя обязательными Playwright-группами, `fail-fast=false`. Список каждой
  проверен через `--list --shard`: объединение равно полному набору, пересечений нет.
  Lighthouse обеих страниц выполняется в первой группе, сохраняются все прежние
  пороги, браузеры, снимки и таймауты. Pages получает сборку этой группы, а deploy
  требует успеха всей матрицы вместе с quality/unit/coverage/files.
  Отчёты групп имеют разные имена. При необходимости вернуться к одному job
  можно убрать матрицу/аргумент shard, не меняя тестов; увеличение времени не требуется.

## ADR-044. T5.6: восстановление варианта без блокировки интерфейса

- Дата: 2026-10-21. Холодная загрузка полной сохранённой попытки выявила
  блокировку основного потока при проверке генераторов: Lighthouse Performance
  79–85, несмотря на проходящий пустой шаблон результата. Пороги не менялись.
- Для сохранённой попытки канонический вариант восстанавливается в модульном
  Worker. Он вызывает тот же сборщик с проверками всех генераторов, включая
  проверку Робота; ни один verify не исключается. Ответ Worker проходит
  VariantSchema, а scoring сверяет идентичность и выбранную ветку №13.
- После завершения уже открытого экзамена передаётся его проверенный вариант.
  Изменение самооценки использует этот же экземпляр без повторной генерации.
  Проверка сохранённых ответов и обновление истории остаются общими и локальными.
- Worker получает только идентичность варианта, а не пользовательскую программу.
  Он завершается после ответа/ошибки, при смене варианта или размонтировании;
  таймаут ограничен 15 секундами. При отсутствии Worker есть обычная асинхронная
  загрузка сборщика; при ошибке доступны скачивание ответов и перезагрузка.
- Форматтер условий и сами разборы загружаются при раскрытии номера,
  `ResultTaskBody` сохраняет управление самооценкой и повторную загрузку после
  сетевой ошибки. Печать независимо подготавливает все 16 разборов.
  Это исключает форматтер из начальной цепочки полного результата.
- Стили результата, текста, рисунков и файлов объединены локальными CSS imports
  в один stylesheet оболочки, чтобы не создавать лишние блокирующие запросы.
- Первый экран сразу содержит сведения о локальной истории; для статуса и
  загружаемого результата предусмотрено место. Это устраняет сдвиг подвала,
  без задержки готового содержимого и без ослабления Lighthouse.
- Вернуться к сборке в основном потоке можно после устранения её стоимости
  и повторного замера полной попытки с теми же бюджетами, а не только пустого URL.

## ADR-045. T5.6: отдельный обязательный Lighthouse job

- Дата: 2026-10-21. Матрица выросла до 1078 браузерных проверок и 30 замеров
  Lighthouse. Первая группа браузеров занимает около 14 минут, Lighthouse —
  ещё около 6 минут; вместе с установкой это превышает прежние 20 минут job.
- Lighthouse выделен в самостоятельный параллельный `performance` job.
  Сохранены все URL, три замера каждого, пороги assertions, два браузерных
  shard, все четыре браузерных проекта и прежние таймауты. Нет пропуска тестов
  и `continue-on-error`; deploy явно зависит от `performance` и остальных gates.
- Pages получает сборку первого браузерного shard сразу после его проверок
  и сканирования секретов. Lighthouse проверяет собственную production-сборку
  того же коммита с тем же lockfile; все jobs обязательны до публикации.
  Отчёты Lighthouse сохраняются отдельным артефактом, трассы — по shard.
- Контракт публикации проверяет `tests/unit/ci-release-gate.test.mjs`:
  обязательность всех gates, безусловный Lighthouse, оба shard и источник
  артефакта Pages. Для возврата к одному job нужно сначала уложить полный объём
  проверок в лимит, сохранив их состав и зависимость публикации от успеха.

## ADR-046. T5.6: восстановление прерванного импорта в WebKit

- Дата: 2026-10-21. Полный CI выявил два сбоя WebKit после прерванной загрузки
  результата/печати. Смена URL страницы и ожидание навигации оказались недостаточны:
  WebKit сохранял отказ для прежнего URL модуля. Остальные 1076 проверок проходили.
- Применён уже используемый случайными вариантами механизм `?module-url`:
  Rollup выдаёт URL production-entry с сохранением экспортов, клиент добавляет
  `load=UUID` при каждой загрузке. Общий `importFreshModule` используется результатом,
  печатью и сохранённым разбором на странице варианта. Имена entry в плагине
  берутся из имени исходного файла, прежнее имя RandomVariantContent сохраняется.
- Стили подключены в загружающей оболочке, поскольку нативный импорт по URL
  не запускает Vite preload CSS. После загрузки компонент не импортируется заново
  при каждой самооценке: открытые разборы, фокус и состояние помощи сохраняются.
- Кнопки восстановления дополнительно выполняют новую навигацию через
  `location.replace` с параметром `restore`; путь, попытка, режим и seed
  сохраняются, fragment очищается. История и ответы не изменяются; новый
  экзамен не запускается. URL восстановления покрыт unit.
- Браузерные проверки прерывают запрос ленивого ESM-entry, ждут новой навигации
  и реального запроса с новым URL файла, затем проверяют содержимое и печать.
  Короткий WebKit smoke выполняется перед полной второй браузерной группой;
  все 1078 сценариев остаются в обязательной матрице, таймауты сохранены.
- Обычный импорт без нового URL можно вернуть только после подтверждения
  восстановления прерванных модулей в WebKit теми же сценариями.

## ADR-047 — ускорение времени T5.7 только в Playwright

- Вместо флага отдельной тестовой сборки из T5.7 используется `page.clock`:
  часы останавливаются перед запуском, затем переводятся к последней секунде
  150-минутного экзамена. Последний тик запускает настоящее автозавершение.
- Причина: проверяется та же production-сборка, которую публикует CI; отдельная
  длительность могла бы скрыть ошибки границы и попасть в публикуемый артефакт.
  Код приложения, URL, localStorage и длительность экзамена не меняются.
- Сценарий заполняет все ответы через UI, восстанавливает работу и проверяет
  сохранение последней правки без очередного автосохранения. История не подменяется.
- Последствие: тест проверяет обработку виртуального времени, а не ожидание
  150 реальных минут; реальный пробный экзамен остаётся задачей T5.8.
- Возврат: если потребуется отдельная тестовая сборка, выделить её выходной каталог
  и обязательную проверку, что она не может стать артефактом Pages.

## ADR-048 — отчёты повторённых unit-групп в CI

- При повторе job GitHub сохраняет артефакты прошлых попыток. Прогон
  39747207175 подтвердил: новая группа прошла, но `download-artifact`
  с выбором по имени взял старый blob и повторно показал старые таймауты.
- Имена unit-артефактов включают `github.run_attempt`. Coverage получает
  метаданные только текущего workflow run, выбирает самый новый `created_at`
  для каждого из трёх shard и скачивает три конкретных ID. Числовой порядок ID
  не используется как время: у наблюдавшегося нового отчёта ID оказался меньше.
- История попыток сохраняется; успешные группы прежней попытки используются,
  если не были повторены. Отсутствующие, истёкшие, повреждённые и неоднозначные
  отчёты приводят к ошибке. Все три blob, результаты тестов и порог 90% обязательны.
- Только coverage-job получает `actions: read` для списка метаданных GitHub.
  Права на запись не добавляются; новый сервис и зависимости не нужны.
- Возврат к выбору по имени допустим после подтверждённого исправления
  обработки повторов самим `download-artifact`; проверки порогов сохраняются.

## ADR-049 — T9.2: измерение INP реальным вводом

- Lighthouse navigation не измеряет INP. Его timespan-аудит в версии 13.5.0
  ищет `Responsiveness.Renderer.UserInteraction`, тогда как Chromium 151
  выдаёт `Blink.Responsiveness.UserInteraction.MaxEventDuration`. Проверка
  с настоящими кликами и вводом подтвердила `notApplicable` даже при наличии
  EventTiming. Отсутствующее значение нельзя считать успешным нулём.
- Для обязательного лабораторного INP добавлена dev-зависимость Google
  `web-vitals` 6.2.3. Она выполняется только в проверочном браузере, не входит
  в сборку сайта и не отправляет данные. Lighthouse 13.5.0 и его уже установленный
  Puppeteer Core 25.16.0 объявлены прямыми dev-зависимостями для публичных API.
  Это обоснование расширения инструментов spec §4.1, согласно PROMPT §4.9.
- `npm run lh` сохраняет все прежние URL и пороги, добавляет about/privacy/settings,
  затем запускает 17 сценариев по три раза с mobile-эмуляцией и реальным
  DevTools CPU/network throttling Lighthouse (4× CPU, slow 4G). INP вычисляет
  официальная библиотека, а не собственная аппроксимация. Настоящий перевод
  вкладки в фон завершает измерение; требуются записи метрики и доверенный ввод.
  Любое измерение >200 мс, отсутствие метрики или ошибка сценария блокируют CI.
- Отдельная заведомо медленная кнопка (260 мс) в изолированной проверочной
  вкладке доказывает, что сборщик видит задержку и gate её отклоняет.
  Этот результат не смешивается с метриками продукта. Полные сохранённые результаты
  дополнительно проходят холодную navigation с прежними категориями/LCP/CLS.
- 404 проверяется настоящим HTTP 404 и взаимодействием; SEO-индексация страницы
  ошибки не требуется. Её InfoLayout также проверяется navigation на about/privacy.
  Шрифтовой лимит относится к двум текстовым семействам интерфейса;
  специализированные глифы KaTeX остаются частью математического рендеринга §13.
- Это лабораторная проверка выбранных действий, не полевые перцентили всей
  аудитории и не измерение FPS на физическом телефоне. Человеческие Gates открыты.
  Возврат к одному Lighthouse для INP допустим после исправления парсера
  и подтверждения того же отрицательного сценария; бюджеты сохраняются.

## ADR-050 — T9.2: первый кадр перед островом результата

- Холодная полная попытка показала LCP 2,56–2,87 с при пороге 2,5 с,
  хотя пустой шаблон проходил. Порог и отказ на любом превышении не изменены.
  Начальная цепочка результата включает React, хранилище, валидацию и Worker.
  Ранние запросы попадали в граф LCP до завершения отрисовки текста/шрифтов.
- `client:after-paint` отдаёт приоритет текстовым шрифтам, затем предоставляет
  браузеру кадр до импорта острова результата. PerformanceObserver подтверждает
  FCP; затем загрузка начинается через два кадра (fallback при отсутствии Paint API).
  Ожидание самого события FCP тоже ограничено 200 мс: WebKit задерживает его
  при зависшем WOFF2, даже когда API заявлен как поддерживаемый. По истечении
  этого предела используются кадры, наблюдатель отключается; импорт однократен.
  Если WebKit задерживает также rAF при незавершённой загрузке шрифта, ещё один
  предел 200 мс запускает гидратацию без ожидания кадра. Поздние callbacks не
  запускают повторный импорт. Unit одновременно задерживает шрифт, paint и rAF;
  существующий браузерный тест удерживает настоящие WOFF2 во всех движках.
  Ожидание `document.fonts.ready`
  ограничено 200 мс: это крайний срок, а не фиксированная задержка; после него
  интерфейс загружается даже при зависших шрифтах. Загрузка запускается один раз.
  Текст страницы остаётся серверным и доступным сразу; результат не требует
  прокрутки/клика. Двойной requestAnimationFrame не подменяет метрику и не скрывает DOM.
- Браузерные проверки сравнивают FCP со стартом запроса VariantResult и отдельно
  удерживают настоящие WOFF2-запросы: сохранённый результат всё равно открывается.
  Сценарий полного экзамена возобновляет виртуальные часы после всех проверок
  150-минутного дедлайна: остановленный `page.clock` замораживает также rAF
  последующих страниц. Проверки срока, записей, баллов и истории сохранены.
- Логотип использует SVG вместо загрузки JetBrains Mono ради `>_` (около 40 КБ).
  У декоративного контейнера удалено прежнее font-правило: WebKit запрашивает
  гарнитуру и для такого контейнера без текстовых глифов. Браузерный бюджет
  запрещает этот лишний запрос во всех профилях, включая WebKit.
  Оба используемых подмножества Golos Text предзагружаются. Bootstrap темы и
  41-байтовый стиль переходов встроены с точными SHA-256 через Astro CSP API;
  `unsafe-inline`/`unsafe-eval` не добавлены. Переключение анимаций работает
  с HTMLStyleElement; сохранение настроек до body и запрет чужого inline остаются.
- Стили результата/экзамена/вариантов объединены в stylesheet результата.
  Общий CSS остаётся внешним и кешируемым; глобальная политика inlining сохранена.
  Локальные шесть холодных повторов после исправления: P 100, LCP 1,50–1,51 с,
  CLS 0; полные отчёты сохраняются, проверяется также раскрытие разбора.
- Возврат к `client:load` допустим после сокращения начального графа и повторной
  проверки полных попыток с теми же порогами; Worker/валидация не исключаются.

## ADR-051 — T9.2: официальный Ubuntu archive для системных зависимостей CI

- В [прогоне 40316758907](https://github.com/Exy100/test-oge-app/actions/runs/40316758907)
  Azure-зеркало загружало пакет 3,5 МБ около 90 секунд, а запрос libglib 1,5 МБ
  повторялся после почти четырёх минут. В следующем итоговом прогоне две
  установки браузерных библиотек заняли почти весь 20-минутный лимит задания.
  Это установка системных зависимостей, до исполнения браузерных тестов.
- `scripts/ci-apt-mirror.sh` перед установкой LibreOffice/Playwright заменяет
  только хост `azure.archive.ubuntu.com/ubuntu` на официальный
  `archive.ubuntu.com/ubuntu` в apt-mirrors.txt, sources.list и deb822/list-файлах
  Ubuntu 24.04. Текущий runner-images использует `mirror+file:/etc/apt/apt-mirrors.txt`;
  это подтверждено журналом и [скриптом образа](https://github.com/actions/runner-images/blob/main/images/ubuntu/scripts/build/configure-apt-sources.sh).
  Схема URL, suites, components, signing keys и проверка подписей сохраняются.
- Все тесты, шесть браузерных и четыре performance-группы, таймауты заданий,
  пороги, обязательность успешного CI и проверенные артефакты Pages сохранены.
  Повторные прогоны проверяют итоговый SHA. Новые зависимости и права GitHub
  не добавлены; изменение относится только к одноразовым Ubuntu-runner CI.
- Возврат к стандартному зеркалу возможен после подтверждения стабильной
  скорости; проверки и лимиты при этом остаются прежними.

## ADR-052 — T9.4: полный мобильный прогон трёх движков и десять CI-групп

- Полный mobile-профиль раньше был только Chromium. Добавлены `mobile-firefox`
  (360 × 800, touch, без неподдерживаемого Firefox флага `isMobile`) и
  `mobile-webkit` (360 × 800, touch, iPhone descriptor с `isMobile: true`).
  Настольные Chromium/Firefox/WebKit и визуальные эталоны сохраняются.
- Каждый из шести обычных профилей проходит полный набор e2e, axe и защитных
  проверок. Сценарии сцен выбирают tap по `hasTouch`, а не имени `mobile`.
  Два новых сценария проверяют доверенные touchstart, ввод, смену размеров,
  настоящий автосейв и восстановление, без подмены часов и хранилища.
- CLI обнаруживает 706 × 6 + 54 = 4290 сценариев вместо 2870. Полный набор
  делится на десять обязательных browser-групп через `--shard=N/10`; исходные
  тесты и четыре performance-группы не фильтруются. Это распределяет выросший
  объём, сохраняя прежние 20-минутные лимиты, `retries: 0`, forbidOnly и пороги.
  Unit-контракт проверяет профили, viewport/touch и release gate.
- Перед полной группой WebKit и mobile-webkit по пять раз проходят переход
  через уроки №5/6 в поток. Каждый запуск обязателен; `--repeat-each=5` не
  повторяет сбойную попытку, `retries` остаётся 0. Нативная прокрутка мгновенная,
  чтобы получение фокуса не меняло режим прокрутки между pointerdown и pointerup.
- Deploy ждёт все десять browser-групп и прежние quality/unit/coverage/files/
  performance. Права GitHub, закреплённые действия и проверка секретов сохраняются;
  отчёты десяти групп хранятся семь дней. Новые npm-зависимости не добавляются.
- Эмуляция не подтверждает физический телефон, системную клавиатуру, реальный
  поворот устройства, screen reader или FPS. Ручные Gates остаются открытыми.
  Матрица и сценарии описаны в `docs/cross-browser.md`.


## ADR-053 — T9.5: проверка настоящих печатных A4 PDF перед публикацией

- Печатные стили и print-media в браузере не доказывают, что PDF сохраняет
  содержимое на границах листов. Добавлена отдельная обязательная группа
  `printing` с Chromium и уже используемыми системными инструментами Poppler.
  Новых npm-зависимостей нет. Лимит 20 минут, `retries: 0`, строгий CSP
  и прежние quality/unit/coverage/files/browser/performance gates сохраняются.
- 49 сценариев экспортируют 94 PDF: шпаргалка и справочная версия каждого
  из 45 уроков, карта и полный список уроков, памятка о файлах, два сохранённых
  результата (№13.1/13.2, полный и неполный). Сверяются видимый текст, размер A4,
  поля 15 мм и границы каждого слова; пустые страницы запрещены. Формулы и SVG
  проверяются вместе с их текстом, выбранные страницы преобразуются в PNG.
- PDF-набор живёт в `tests/print`, отдельно от прежнего полного e2e-набора.
  Четыре новых сценария жизненного цикла печати проходят все шесть обычных
  профилей: 710 × 6 + 54 = 4314 запусков. Экспорт PDF выполняет Chromium,
  поскольку Playwright не предоставляет его для Firefox/WebKit.
- Выбранная шпаргалка или памятка печатается в исходном DOM: общие идентификаторы
  MathML/SVG не клонируются. После печати восстанавливаются раскрытые блоки
  и фокус. Преждевременный Safari `afterprint` не снимает печатные стили
  до завершения print-media. На бумаге применяется светлая палитра и 11 pt,
  независимо от экранной темы и увеличения текста.
- Deploy зависит от `printing`: 21 обязательная проверка и отдельная публикация
  main. PDF/PNG и трассы сохраняются в `print-reports` семь дней.
  Физический принтер, ручной системный диалог и предметные Gates остаются
  задачей человека; автоматический экспорт не подменяет их.

## ADR-054 — T9.6: автономный аудит языка и формул

- В обязательную проверку качества добавляется аудит опубликованного HTML,
  текстов интерфейса, всех активных подтипов генераторов и кураторских наборов.
  Ошибки орфографии и формул блокируют публикацию; прежние проверки и пороги
  сохраняются. Результат дополняет ручную редактуру, а не заменяет учителя.
- Для русской орфографии нужны морфологический словарь и обработка его правил.
  Добавлены только dev-зависимости `nspell@2.1.5` (MIT) и `dictionary-ru@3.0.0`
  (BSD-3-Clause). Это дополнение к стеку spec §4.1 по PROMPT §4.9.
  Версии и integrity закреплены в lockfile. Словарь работает автономно,
  тексты не отправляются во внешние сервисы; клиентский bundle его не импортирует.
- Профессиональные слова и собственные имена проходят отдельный проверяемый
  словарь проекта с объяснением. Фрагменты кода и имена файлов отделяются от
  русской прозы; для обычных слов нет общего разрешения ошибок.
- Аудит проверяет реальные результаты общего rich-text renderer и сборки,
  включая MathML и сообщения об ошибках KaTeX. Детерминированные образцы
  сохраняются для проверки формулировок на конкретных данных задания.
- Автоматический отчёт не закрывает человеческие Gates; выводы о качестве
  объяснений подтверждаются описанной редакторской выборкой и предметным ревью.

## ADR-055 — T3.19: форматы №16 и проверка среднего

- По подтверждённому владельцем следующему шагу (Q-I8, 2026-10-28) экзаменационный
  подбор №16 содержит все три формата D25/D26/D27: среднее положительных и их
  количество, сумму по последней семеричной цифре 1 и ввод до нуля с отбором
  четырёхзначной восьмеричной записи на 5. Четыре прежних упражнения сохранены
  в учебном реестре с прежними идентификаторами и доступны в галерее.
- Минимум четырёх учебных подтипов spec §6.3 сохранён. Как для №1–12/14,
  `examFormats[16]` требует каждый подтверждённый формат; учебный инвентарь
  не подменяет покрытие экзамена. Это уточняет приёмку, не снижает пороги тестов.
  Полнота и частотность по недоступному открытому банку не установлены.
- Среднее сравнивается с абсолютной погрешностью ≤10⁻⁶, без относительного допуска.
  Допустимы точка и экспоненциальная запись; количество проверяется как точное
  целое. Для остальных подтипов сохраняется строгое сравнение целых токенов.
  Политика записана в tests/index.json, условии и README; обе реализации
  TypeScript/Python проверяются на одном наборе правильных и ошибочных выводов.
  Это учебный допуск, не новое утверждение о критериях ФИПИ.
- Python выполняется локально по spec §3.5/7.3. Новых зависимостей или браузерного
  движка нет; учебные 0/1/2 не заменяют экспертную оценку. D27 остаётся проектом.
- Новые попытки получают `pythonFormatVersion: 1`; отсутствие поля означает
  прежний подбор №16. Черновики и история восстанавливают старую задачу, код
  и самооценку; worker и основной поток учитывают ту же версию. Совместимость
  проверяется по десяти настоящим заданиям из main `99b2e72`, а не по заново
  сформированным ожиданиям. Остальные номера и seed V01–V10 не меняются.
  Четыре учебных подтипа №16 остаются обязательной проверкой Фазы 3 наряду
  с тремя подтверждёнными форматами; порог инвентаря не становится справочным.

## ADR-056 — T6.0: заменяемый источник демонстрационных ответов

- Владелец 2026-10-28 прямо поручил заполнить блок тестовыми ответами и позднее
  заменить его реальным ИИ API. Это узкое разрешённое исключение из запрета
  фиктивных данных PROMPT §4.1; остальные проверки, требования и запреты сохраняются.
  Для этого локального среза не требуются домен сервера, аккаунты и ключи.
- `FeedbackProvider` выдаёт Markdown фрагментами и получает `AbortSignal`.
  Контракт запроса содержит только generatorId, seed, краткий ответ и черновик
  с пределами spec §11.3. Выбор адаптера и описание режима вынесены в
  `src/lib/ai/provider.ts`; карточка не зависит от способа получения ответа.
- Локальный адаптер выбирает одну из двух явно обозначенных заготовок по
  существующей детерминированной проверке. Он не отправляет данные, не меняет
  прогресс и не оценивает практические работы. Панель доступна после проверки
  №1–12 в общей карточке: поток, главная и тренировка используют один компонент.
- Вывод ограничен по длине и проходит существующий безопасный rich-text renderer
  после каждого фрагмента. Остановка, смена задания/черновика и размонтирование
  отменяют получение. Запоздалые фрагменты не обновляют интерфейс. Загрузка
  модулей использует существующий механизм свежего URL для повторения после отказа.
- Это не выполнение T6.1–T6.10 и не закрытие Gate 6. Для реального подключения
  нужны Worker, серверная пересборка задачи, лимиты и бюджет, OpenRouter, явное
  согласие на передачу данных и остальные пункты spec §11. Источник и описание
  режима заменяются вместе; регистрация и ключи не добавляются в клиент.
- Откат: убрать подключение панели из TaskCard и демонстрационный адаптер;
  ответы, самооценки, генераторы и схема сохранённых данных не менялись.
