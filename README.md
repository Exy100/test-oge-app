# Тренажёр ОГЭ по информатике

Учебный сайт с материалами, потоком задач и вариантами экзамена.
Сейчас доступны базовые упражнения по объёму текста, логике и системам счисления:
проверка ответа, три подсказки, решение по шагам и краткая теория с примерами.
В шапке можно выбрать светлую, тёмную или системную тему; выбор запоминается.
На [странице практики](https://exy100.github.io/test-oge-app/stream/) доступны
карточки всех 16 номеров: краткие ответы, файлы, критерии самооценки,
локальный Робот и редактор Python с экспортом кода для запуска на компьютере.
Фильтры, ссылки на задания и постоянная статистика работают в практике.
В [каталоге вариантов](https://exy100.github.io/test-oge-app/variants/) доступны
V01–V10 и случайный вариант по воспроизводимой ссылке. Все 16 номеров и обе
работы №13 можно прочитать; каждый номер ведёт к тому же заданию в практике.
На странице варианта можно начать экзамен на 150 минут: ответы, черновики и
отметки сохраняются, незавершённая работа восстанавливается из каталога.
Время продолжает идти после закрытия страницы. После завершения открываются
проверка №1–12 и разбор; итоговый балл ожидает оценки практических работ.
Для №11–14 скачиваются исходники без эталонов. Каталог показывает историю
сохранённых попыток этого браузера. Практическое рабочее место №13–16 и
каталог уроков — следующие задачи [плана](tasks.md).
Математическая версия плана сохранена в [архиве](docs/archive/README.md).

Сайт: **https://exy100.github.io/test-oge-app/**

## Установка и запуск

Требуется Node.js 24 LTS (проверенная версия в `.nvmrc`) и npm 11.
Перейди в каталог репозитория:

```bash
npm ci
npm run dev -- --host 127.0.0.1 --port 4321
```

Сайт работает по пути `/test-oge-app/`, включая локальный запуск.
Проверка из другого терминала:

```bash
curl --fail --silent --show-error http://127.0.0.1:4321/test-oge-app/
```

Ожидаются HTTP 200 и заголовок «ОГЭ по информатике». Остановка — `Ctrl+C`.
Для просмотра production-сборки:

```bash
npm run build
npm run preview -- --host 127.0.0.1 --port 4321
```

В облачной среде перед npm-командами задай доступный каталог кеша и отключи
служебную телеметрию Astro (домашний каталог здесь недоступен для записи):

```bash
export npm_config_cache=/tmp/oge-npm-cache
export ASTRO_TELEMETRY_DISABLED=1
```

## Проверки

| Команда                  | Назначение                                                        |
| ------------------------ | ----------------------------------------------------------------- |
| `npm run lint`           | ESLint и проверка форматирования                                  |
| `npm run format`         | Форматирование исходников и конфигурации                          |
| `npm run typecheck`      | Astro Check и TypeScript strict                                   |
| `npm run check:python`   | Запуск Python-эталонов №16 и проверка экспортированных тестов     |
| `npm test`               | Unit-тесты Vitest                                                 |
| `npm run verify`         | lint → typecheck → unit → forbidden → coverage → contrast → build |
| `npm run check:contrast` | Контраст текстовых токенов в обеих темах                          |
| `npm run e2e`            | Сборка, браузерные тесты и axe                                    |
| `npm run lh`             | Сборка, Lighthouse и реальные сценарии INP по spec §15            |

`npm run sample:variant` выгружает один вариант или все V01–V10;
`npm run check:variants` проверяет файлы комплектов, программы и новые таблицы в Calc.

`check:forbidden` проверяет исходники на запрещённые конструкции; `check:coverage`
сверяет фактический объём с минимумами текущего этапа. Например:

```bash
npm run check:forbidden
npm run check:coverage -- --phase=3
npm run check:coverage -- --phase=final
```

Проверка фазы 3 учитывает 58 подтипов, 24 кураторских набора и V01–V10.
Последняя команда пока ожидаемо завершается с ошибкой: уроки и интерактивы
последующих фаз ещё не реализованы. Базовые упражнения T1.8 не засчитываются в их минимумы.
Обычный verify проверяет текущую фазу 3. Форматы реестров, уроков,
правила и пределы проверок — [docs/quality-checks.md](docs/quality-checks.md).
Содержательные проверки фазы 3 описаны в [отчёте по генераторам](docs/generator-coverage.md).

Установка браузеров Playwright для полного прогона:

```bash
npx playwright install --with-deps chromium firefox webkit
npm run e2e
```

Для браузерных проверок нужен OpenSSL: тестовые production-серверы используют
HTTPS с временным локальным сертификатом в `.cache/test-tls` (см. `docs/security.md`).

Если в среде уже есть системный Chromium, можно проверить desktop и мобильный
экран без загрузки другого браузера:

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run e2e -- --project=chromium --project=mobile
CHROME_PATH=/usr/bin/chromium npm run lh
```

Это отдельный прогон Chromium, он не заменяет Firefox и WebKit. Локальные отчёты
остаются на машине; в CI следы браузерных ошибок и Lighthouse-отчёты сохраняются
в артефактах GitHub Actions на семь дней. Lighthouse измеряет главную, каталог
и все выпущенные уроки, поток, варианты, результаты, настройки и информационные
страницы: 59 URL ×3, список — в `lighthouserc.cjs`. Дополнительно выполняются
17 сценариев ×3 с настоящим вводом и INP ≤200 мс, а заполненные результаты
проходят ещё шесть холодных загрузок. Сценарии — `scripts/performance-scenarios.mjs`;
JSON/HTML и сводка — `.lighthouseci/reports/interactions/` (ADR-049/050).
В CI обе матрицы разделены на четыре обязательные группы с одинаковыми бюджетами.

## Структура

```text
src/pages/index.astro      Главная страница
src/pages/about.astro      О проекте и проверенные источники
src/pages/privacy.astro    Приватность и удаление темы
src/pages/404.astro        Неверный адрес и возврат к практике
src/components/Practice.tsx Интерактивная практика на React
src/components/ui/        Общие доступные компоненты интерфейса
src/lib/practice.ts        Задачи, подсказки, решения и проверка ответа
src/styles/global.css     Стили и Tailwind v4
src/styles/tokens.css     Общие токены светлой и тёмной тем
src/layouts/SiteLayout.astro Общая оболочка страниц
src/assets/fonts/         Локальные шрифты с кириллицей
src/dev/ui.astro          Страница оформления, только npm run dev
src/lib/site.ts            Адрес сайта и пути GitHub Pages
public/                   Файлы, копируемые в сборку
tests/e2e/                Браузерные проверки
.github/workflows/ci.yml   Автоматические проверки и публикация
dist/                     Результат сборки, вне Git
```

Astro рендерит страницу и краткую теорию, доступную без JavaScript. React отвечает
за интерактивную практику: 24 упражнения на объём текста, 32 на логику и 12 на
двоичную запись. После конца набора задачи повторяются. Счётчик учитывает каждую
правильно решённую задачу один раз и сбрасывается при перезагрузке страницы.
Шрифты размещены локально. Cookies, внешние скрипты и аналитика не используются.
Только выбор оформления сохраняется в localStorage. Принципы, лицензии шрифтов
и проверки описаны в [дизайн-системе](docs/design-system.md).
Кнопки, карточка и метки практики используют [UI-кит](docs/ui-kit.md).

## Публикация в GitHub Pages

Источник Pages — **GitHub Actions**. В Git отправляются исходники; результат сборки
`dist/` остаётся вне репозитория. Перед отправкой изменений:

```bash
npm run verify
npm run e2e
```

Workflow **CI and Pages** проверяет push и pull request: verify, все браузеры
Playwright с axe, Lighthouse, npm audit и Gitleaks. При успехе на `main` он
публикует проверенный `dist` по прежнему адресу. Ошибка блокирует новую публикацию,
предыдущая версия сайта остаётся доступной. Ветки и pull request сайт не публикуют.
Проверки кода/учебных файлов и браузеров идут параллельно; публикация ждёт обе группы.

Новые страницы Astro включаются в артефакт автоматически. Копировать HTML и
`_astro` в корень или запускать прежний `pages:prepare` больше не требуется.
Файлы из `public/` попадают в сборку обычным способом.

[Запуски CI](https://github.com/Exy100/test-oge-app/actions/workflows/ci.yml),
права, диагностика и проверка отказа описаны в [docs/ci.md](docs/ci.md).
Повторный запуск возможен через Actions → CI and Pages → Run workflow → main.

Серверный ИИ ещё не развёрнут; ключи не помещаются в статические файлы.
Ограничения хостинга — ADR-001; переход на Actions — ADR-009.
