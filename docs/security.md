# Безопасность статической сборки

GitHub Pages применяет meta-CSP из каждой HTML-страницы и meta referrer.
Astro вычисляет SHA-256 для своих встроенных скриптов и стилей. Хук сборки
перемещает CSP сразу после charset, до первого скрипта. Внешние ресурсы,
неразрешённые встроенные скрипты и eval не разрешены политикой. Заголовок
frame-ancestors в meta не поддерживается и туда намеренно не добавляется.

`public/_headers` содержит все HTTP-заголовки spec §12. При сборке
`scripts/security-headers.mjs` добавляет в `dist/_headers` объединение хэшей
из CSP всех страниц. Небезопасный источник, отсутствие CSP или превышение
лимита строки Cloudflare прерывают сборку. Не редактировать выходной файл вручную.

GitHub Pages игнорирует `_headers`. Поэтому собственные HSTS, nosniff,
Permissions-Policy, COOP и запрет встраивания через frame-ancestors там не
гарантируются. Их наличие проверяется на локальном Cloudflare Pages runtime;
это не утверждение об HTTP-заголовках опубликованного GitHub-сайта (ADR-001).

## Проверка

`npm run build`, затем `npm run e2e` запускает также Wrangler Pages dev на
порту 4326. Временная копия `.cache/pages` воспроизводит базовый путь сайта;
она не публикуется. Cloudflare-аккаунт и токен для локальной проверки не нужны.
Wrangler закреплён в devDependencies. Playwright отключает его телеметрию.

Оба production-сервера e2e работают по HTTPS. Safari применяет
upgrade-insecure-requests и к HTTP loopback, поэтому проверка по HTTP блокировала
ресурсы вместо проверки поведения production. Директива CSP сохранена.
Скрипт `scripts/test-tls.mjs` создаёт через OpenSSL краткоживущий самоподписанный
сертификат для 127.0.0.1/localhost в игнорируемой `.cache/test-tls`.
Playwright принимает этот сертификат только в контекстах локальных тестов и
при проверке готовности серверов. Это не меняет проверку TLS при установке npm,
загрузке артефактов, в опубликованном приложении или системные настройки доверия.
Ключ не попадает в dist. Dev-галерея остаётся на HTTP; Lighthouse использует
Chromium, где HTTP loopback исключён из автоматического обновления протокола.

Сценарии проверяют реальные HTTP-заголовки, работу практики и темы без ошибок
CSP, а отдельно на Astro preview — блокировку внедрённого inline-скрипта
через meta-CSP. Галерея `/dev/ui` не входит в production: CSP Astro не работает
на Vite dev server, поэтому проверяется собранный сайт.

ClientRouter заменён обычными переходами с CSS `@view-transition`: встроенная
CSP Astro не поддерживает этот маршрутизатор. При отсутствии поддержки API
переход остаётся обычным; reduced motion отключает анимацию. Theme-скрипт
работает до появления body и обновляет тему при возврате из bfcache.

## Сплошная проверка T9.3

Сборка проверяет обязательные директивы CSP целиком: обращения только к своему
origin, `object-src 'none'`, локальные шрифты и разрешённые `data:`/`blob:` из
spec §12. Пропуск, дубликат или неожиданный источник прерывает сборку.
Для каждого встроенного блока `script` и `style` SHA-256 вычисляется заново по
его реальным UTF-8 байтам и сверяется с соответствующей директивой страницы.
Регрессия проверяет, что изменение даже одного пробела без нового хэша отклоняется.

`tests/fixtures/security-browser.ts` подключён к полному обходу HTML в
`a11y-site.spec.ts`: все страницы sitemap, noindex-страницы и реальная 404,
светлая и тёмная темы, Chromium/Firefox/WebKit/mobile. Наблюдение начинается
до навигации, остаётся активным при смене темы, раскрытии материала и загрузке
всех отложенных 2D-интерактивов. События `securitypolicyviolation` передаются
в тестовый процесс; переход на другую страницу не стирает обнаруженное нарушение.
Также проверяются сообщения CSP, запросы контекста, WebSocket и отсутствие cookies.
Заблокированный политикой сторонний ресурс — ошибка теста, даже если запрос
не дошёл до сети. CSP для прохождения проверки не отключается.

`security-journeys.spec.ts` дополнительно загружает сохранённые полные фиксированный
и случайный варианты через настоящий Worker, раскрывает все 16 разборов и готовит
результат к печати. HTML-подобная запись ученика остаётся текстом. Пять 3D-игр
проверяются после включения объёмного режима и смены уровня/темы: Chromium/mobile
рисует настоящий WebGL через SwiftShader, другие движки могут использовать
штатный fallback. Это лабораторная проверка загрузки ресурсов, не физического FPS.

Отдельные отрицательные сценарии доказывают отказ того же контроля при внедрении
inline-скрипта, заблокированной внешней картинки, реальном внешнем запросе
из изолированного тестового документа без CSP и записи cookie. Ответ внешнего
сервера в контрольном запросе подставляет Playwright; запрос наружу не отправляется.

После сборки:

```bash
npm run check:security
gitleaks git --redact --no-banner --log-opts=--all
gitleaks dir dist --redact --no-banner
npm audit --audit-level=high
```

`check:security` проверяет все байты `dist/`, включая бинарные ресурсы: маркер
ключа OpenRouter и блоки приватных ключей запрещены. Публичные `.env*`, ссылки
на внешние файлы через symlink и пустая сборка также отклоняются. Ошибка содержит
только имя файла. Этот контроль дополняет Gitleaks с его полным набором правил;
оба сканирования остаются обязательными в CI. `verify` включает новый контроль
после сборки. High/critical в npm audit блокируют публикацию.

Ограничение GitHub Pages по HTTP-заголовкам из ADR-001 сохраняется. Тесты не
подтверждают безопасность ещё не развёрнутого Worker Фазы 6 и не закрывают
человеческие ревью Gate 9.
