# Файловые наборы и ODF

Ядро находится в `src/core/datasets/`, не зависит от DOM или Node API.
SHA-256 использует Web Crypto; ZIP и XML-библиотеки закреплены в lockfile (ADR-023).

## API

- `makeDocument(paragraphs)` → настоящий ODT.
- `makePresentation(slides)` → настоящий ODP; каждый слайд содержит заголовок и текст.
- `makeSpreadsheet(rows)` → настоящий ODS с прямоугольной таблицей. Числа — числовые
  ячейки; строки, включая начинающиеся с `=`, остаются текстом, не формулами.
- `createDataset(id, seed, generatorId, sources)` → Promise с `manifest`, `files`,
  `archive`. Входные байты копируются после проверки размеров. Манифест содержит
  формат, размер, SHA-256 и лицензию каждого файла, seed и версию генерации.
- `verifyDataset(manifest, files)` и `verifyArchive(manifest, archive)` проверяют
  состав, размеры, хэши и соответствие офисного формата содержимому.
- `packZip(files)` и `readZip(bytes)` работают со строгим профилем архивов проекта.

Поддержаны текст UTF-8, CSV, JSON, тексты Python/«Робота», ZIP, ODT/ODP/ODS.
Изображения и произвольные импортированные офисные документы требуют отдельной
реализации проверки. Текущий API отвергает неподдерживаемый формат.

`createExampleDataset(seed)` — авторский технический образец: 12 цен, CSV и ODS,
текст, ODT, два слайда ODP и вычисленный JSON-эталон. Все данные CC0-1.0, без данных
ученика. Это не экзаменационный генератор и не увеличивает предметное покрытие.

## Ограничения и воспроизводимость

- До 100 файлов, 1 МиБ на файл, 8 МиБ суммарно, ZIP до 10 МиБ.
- Относительные NFC-пути до 240 UTF-8 байт. Запрещены обход каталогов, URL,
  обратные слеши, управляющие символы, непереносимые имена и конфликты регистра.
  Файл не может одновременно быть каталогом для другого файла.
- Записи ZIP без сжатия и комментариев, с фиксированной датой 1980-01-01,
  стабильным порядком. В ODF первой идёт несжатая запись `mimetype` без extra-поля.
- Чтение проверяет центральные и локальные заголовки, фактические размеры,
  CRC-32, уникальность и отсутствие лишних данных. ZIP64, шифрование, символьные
  ссылки и сжатые сторонние архивы не входят в этот профиль и отклоняются.
- ODF 1.3: `content.xml`, `styles.xml`, `META-INF/manifest.xml`; корректный MIME,
  тип тела и записи манифеста. XML экранируется, DTD, сущности и внешние ссылки
  не используются. Это минимальный профиль, не универсальный валидатор стандарта.
- Таблица до 1000 × 50, документ до 1000 абзацев, презентация до 50 слайдов.
  Общие байтовые лимиты продолжают действовать. NaN, Infinity, отрицательный ноль
  и числа по модулю больше 10¹² не принимаются.

При одинаковых версии и seed весь образец, манифест и ZIP побайтово совпадают.
В ZIP лежат только файлы набора, манифест передаётся отдельно: хэш архива не
создаёт циклической зависимости с хэшами его содержимого.

## Проверка в LibreOffice

```sh
npm run sample:dataset
npm run check:office
```

Образец записывается в игнорируемую `.cache/dataset-sample/`.
Для второй команды нужны Python 3, LibreOffice Writer/Calc/Impress и `pdftotext`
из poppler-utils. Команда вызывает LibreOffice headless с временным профилем:

1. Независимо проверяет ZIP/ODF через Python zipfile/XML, хэши и состав манифеста.
2. Открывает ODT и сверяет экспортированный текст с исходным.
3. Открывает ODS, сверяет ячейки цен и вычисленную сумму с эталоном.
4. Открывает ODP, экспортирует PDF, проверяет два слайда и весь текст через pdftotext.

Отсутствие программы, тайм-аут, ошибка открытия или потеря содержимого дают
ненулевой код. CI устанавливает офисные компоненты и выполняет эту команду
перед браузерными тестами и публикацией. Образцы сохраняются в quality-reports.

Модульные тесты покрывают 20 разных seed, искажение CRC/размеров/хэшей,
traversal, конфликты имён, все лимиты, подмену расширений, неверный XML и манифест.
Связь будущего экзаменационного задания с файлами проверяется предметным тестом
генератора; данный шаг предоставляет файловое ядро, а не полный банк заданий.
