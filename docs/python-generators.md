# Задания №16: программы на Python 3

Четыре генератора создают собственные задания на написание программы, а не на
чтение готового кода. Формат ответа и максимум 2 балла сверены в
[описании экзамена](exam-format.md). Подтипы, ограничения, наборы тестов и критерии
этого тренажёра учебные; они не выдаются за официальный банк или рубрикатор ФИПИ.

| Подтип | Алгоритм | Результат |
|---|---|---|
| python-filter | Отобрать числа по кратности и включённому нижнему порогу | Количество и сумма; при отсутствии — 0 0 |
| python-digits | Обработать цифры обычной десятичной записи по кратности | Количество и сумма цифр; запись 0 содержит одну подходящую цифру |
| python-pairs | Просмотреть соседние, в том числе перекрывающиеся, пары | Количество подходящих пар и максимум суммы, включая отрицательный; при отсутствии — 0 0 |
| python-run | Сохранять длину непрерывной подходящей цепочки и максимум | Самая длинная цепочка, в том числе в конце; при отсутствии — 0 |

Для последовательностей вводится N от 1 до 1000, затем N строк с целыми числами
от −10000 до 10000 включительно. Для цифр — одно число от 0 до 999999999999
включительно без ведущих нулей. На каждой строке одно число. Делитель — от 2 до 9;
пороги генераторов и все параметры записаны в условии и source/parameters.json.
В выводе только целые числа результата, без приглашений. Все ожидаемые ответы
вычисляются из фактических входных данных; готовые ответы из примера в код не вставляются.

## Экспорт и локальный запуск

```sh
npm run --silent sample -- --task 16 --n 12 --seed python-review --files-dir samples/16-files > samples/16.md
npx prettier --write samples/16.md
npm run check:python
npm run verify
```

[Двенадцать примеров](../samples/16.md) содержат ссылки на архивы, Python-эталоны
и списки тестов. По три примера на подтип. В каждом архиве 27 файлов:

- README.txt и assignment.txt;
- source/parameters.json;
- reference/answer.py и check.py;
- criteria.json и tests/index.json;
- десять пар tests/NN.input.txt и tests/NN.expected.txt.

Все материалы CC0-1.0, UTF-8, без персональных данных. PY — настоящий исходный
текст Python. Манифест фиксирует формат, размер и SHA-256 каждого файла; ZIP и
виртуальный набор имеют одинаковое содержимое и воспроизводятся по seed.

После распаковки напиши answer.py и запусти из каталога набора:

```sh
python3 check.py answer.py
python3 answer.py < tests/01.input.txt
python3 check.py reference/answer.py
```

В Windows первая команда: `py -3 check.py answer.py`. В среде разработки
можно ввести строки из input.txt вручную. Каждый тест запускает отдельный процесс
Python с изолированными настройками `-I`, временным рабочим каталогом и лимитом
2 секунды. Проверяется нормальное завершение и числовой вывод; пробелы и переводы
строк между числами не влияют на ответ. Лишние слова, числа, ошибка исполнения,
ненулевой код возврата или таймаут делают тест непройденным. Сравнение ограничено
1024 символами вывода. Стандартный поток ошибок сам по себе не является ответом.

Это запуск выбранного локального файла с обычными правами пользователя, не
песочница. Запускать следует собственный или доверенный код. Полный движок Python
в клиентский бандл не добавлен. `assessProgramRuns` сравнивает явно переданные
сведения о внешних запусках: stdout, exitCode и timedOut; он не исполняет код
и не подтверждает происхождение этих сведений. Публичный редактор и сохранение
работы относятся к последующим задачам плана.

## Критерии и алгоритмы

Учебный балл 2 означает успех на всех десяти тестах, 1 — на части, 0 — ни на одном.
Сохранение файла не даёт баллов. Конечная выборка тестов не доказывает корректность
для всех допустимых входов и не заменяет экспертную оценку экзамена.

Эталоны последовательностей используют один проход и постоянную дополнительную
память. В отборе счётчик и сумма относятся только к уже прочитанным подходящим
числам. В обработке цифр после каждого шага число уменьшается целочисленным
делением на 10; ноль обработан отдельно. В парах максимум инициализируется первой
подходящей суммой, а не нулём; соседние пары не пропускаются. В цепочках максимум
обновляется при каждом подходящем числе, текущая длина сбрасывается на разрыве.
Так учитывается цепочка в конце ввода.

## Фактические проверки

Каждый подтип проходит общий харнесс на 500 различных seed четырьмя пакетами
по 125 с лимитом 30 секунд на пакет: схема, детерминизм, реальные файлы и архив,
CRC, независимый SHA-256, лицензии и независимый оракул для всех десяти входов.
На подтип записаны три золотых снимка задачи и манифеста. Все 12 сохранённых ZIP
воспроизводятся по байтам.

В отдельном процессе CPython эталоны всех 2000 seed выполняются на всех десяти
входах — 20000 запусков с независимым вычислением ответов. Тестовый исполнитель
принимает только доверенные эталоны репозитория, ограничен 20 секундами CPU,
256 MiB памяти и 30 секундами внешнего времени. Это не API для кода ученика.
Дополнительно перебираются 2001 небольшое число и 1089 коротких последовательностей.
Мутации кода проверяют включённую границу, особый случай нуля, отрицательный
максимум и сброс длины цепочки.

`check:python` независимо читает все 324 файла двенадцати наборов, проверяет
ZIP/CRC/SHA-256 и ответы своим Python-оракулом, затем запускает 120 эталонов
отдельными процессами. Проверены все 12 экспортированных check.py и их реакции
на синтаксическую ошибку, аварию, ненулевой выход, пустой/нечисловой вывод,
превышение времени и частичный успех. CI выполняет ту же проверку.
Браузерные тесты сравнивают данные/оценку с Node, скачиваемый ZIP, предпросмотр
Python и тестовых файлов, axe и мобильную ширину.
