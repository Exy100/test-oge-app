# Реестр и проверка генераторов

`src/core/generators/index.ts` экспортирует неизменяемый массив `generators`,
поиск `getGenerator(id)` и фильтр `generatorsForTask(number)`. Повторные id и
пары номер/подтип отвергаются. Runtime-импорты реестра используют расширение `.ts`:
так реестр доступен и проверке покрытия в Node 24 без сборки.

Первый генератор `text-volume-v1` создаёт авторские задачи №1 об объёме текста
в явно заданной условной кодировке. Ответ вычисляется; `verify` извлекает параметры
из условия и независимо суммирует объём символов в байтах. Версия включена в id:
при несовместимом изменении алгоритма нужно создать новый id.

## Подтипы №1 и №2 (T3.1)

| Номер | Подтип | Отличие и независимая проверка |
| --- | --- | --- |
| 1 | `text-volume-v1` | Прямой объём; суммирование байтов по символам |
| 1 | `removed-word-v1` | Восстановление слова по уменьшению объёма; удаление каждого кандидата из строки вместе с разделителем |
| 1 | `recoding-v1` | Число символов по приросту объёма; накопление старого и нового объёмов |
| 1 | `message-capacity-v1` | Максимальная длина при заголовке и остатке; проверка вместимости N и невозможности N+1 |
| 2 | `fixed-code-v1` | Равномерные группы по три бита; перебор сегментаций сигнала |
| 2 | `prefix-code-v1` | Неравномерные коды без разделителей; проверка префиксности и единственности расшифровки |
| 2 | `separated-code-v1` | Непрефиксные коды из точек и дефисов; границы букв определяет разделитель `/` |
| 2 | `missing-code-v1` | Восстановление элемента таблицы по известному сообщению; перебор всех кодов длиной 1–4 бита и обратное кодирование |

Подтипы авторские, для тренировки соответствующих навыков; это не копии заданий
ФИПИ и не исчерпывающий список экзаменационных формулировок. Единицы и условная
кодировка указаны явно. В №2 задан алфавит ответа и правило регистра; ведущие нули
сохраняются. Для удаления используются слова разной длины, поэтому ответ единственный.
Проверка кода учитывает весь сигнал; неполные и неоднозначные варианты отвергаются.

Каждый из восьми генераторов проверяется на 500 seed’ах и трёх золотых снимках.
Предметные проверки в `first-tasks.test.ts` используют перебор допустимых чисел,
прямой обход сегментаций и восстановление длины пропущенного кода; не вызывают
сам генератор для вычисления ожидаемого ответа. Отдельно проверяется совпадение
полных заданий и `verify` в Node, Workers и браузерах.

Материалы для просмотра: [№1](../samples/01.md), [№2](../samples/02.md) —
по 12 примеров, по три каждого подтипа. Воспроизведение:

```sh
npm run --silent sample -- --task 1 --n 12 --seed t3.1-review > samples/01.md
npm run --silent sample -- --task 2 --n 12 --seed t3.1-review > samples/02.md
npx prettier --write samples/01.md samples/02.md
```

Генераторы доступны через ядро и dev-галерею; публичный поток практики подключается
отдельно. Gate 3 остаётся открытым до выполнения T3.2–T3.13; минимумы не изменены.

## Подтипы №3 и №4 (T3.2)

| Номер | Подтип | Структура и независимая проверка |
| --- | --- | --- |
| 3 | `logic-and-v1` | Наименьшее целое в пересечении строгого и нестрогого ограничений; полный перебор области |
| 3 | `logic-not-or-v1` | Наибольшее целое после отрицания ИЛИ; проверка по закону де Моргана |
| 3 | `logic-divisibility-v1` | Подсчёт кратных первому делителю, но не второму; формула через НОК против перебора |
| 3 | `logic-exclusive-v1` | Ровно одна из двух делимостей; исключение пересечения из обеих групп против перебора |
| 4 | `route-length-v1` | Сумма длин дорог заданного маршрута; повторное чтение таблицы и проверка каждого участка |
| 4 | `shortest-route-v1` | Минимум среди простых путей; обход в глубину против динамического программирования по подмножествам |
| 4 | `route-via-v1` | Минимум среди путей с обязательным пунктом; состояние включает посещённые пункты |
| 4 | `route-without-v1` | Минимум после исключения закрытого пункта и всех примыкающих дорог |

В логике область конечна и указана явно; ноль, строгие границы и значение
исключающего ИЛИ разъяснены. Условия вычисляются без исполнения строкового кода.
В модели дорог таблица симметрична, единицы — километры. Повторные посещения
пунктов запрещены; возможные одинаковые минимумы разных путей допустимы, поскольку
ответ — единственная длина. Обязательный и закрытый пункты меняют обычный минимум
во всех сгенерированных задачах. Названия промежуточных пунктов переставляются,
меняются веса и наличие дополнительной дороги.

Тесты `logic-models.test.ts` используют собственный перебор целых значений и
всех упорядоченных подмножеств промежуточных пунктов, отдельно проверяют ноль,
общие делители, равные минимумы, несвязность, испорченные таблицы и повторные
посещения. Каждый подтип проходит 500 seed’ов и три золотых снимка. Общие проверки
Node/Workers/браузер автоматически включают все 16 зарегистрированных подтипов;
браузерная галерея проверяет доступность таблиц дорог и мобильную ширину.

Примеры: [№3](../samples/03.md), [№4](../samples/04.md) — по 12 задач.
Воспроизведение: команды раздела T3.1 с `--task 3`/`--task 4`, seed `t3.2-review`
и выходными файлами `samples/03.md`/`samples/04.md`.

## Подключение тестов

В тестовом файле достаточно одного вызова:

```ts
testGenerator(generator, { assertUnique, assertQuality });
```

Помощник из `tests/generator-suite.ts` проверяет 500 различных seed через fast-check
и три золотых снимка. `assertUnique` — независимая предметная проверка единственности
ответа, `assertQuality` — границы и удобство чисел, согласованность объяснения.
Их нельзя заменять вызовом самого generate/verify. Для первого генератора
перебираются все возможные ответы 0…1024 и проверяется ровно один подходящий.

Общие проверки: Zod-схема, метаданные, повторная генерация, независимый verify,
отсутствие мутации задания, типичные ошибки, недопустимые числа и ошибки KaTeX
в условии, подсказках и решении. Поддержаны дополнительные функции:

- `figures(task)` возвращает рисунки для проверки FigureSpec; предметную связь
  рисунка с условием проверяет assertQuality.
- `assertFiles(task)` проверяет реальные байты/архивы и возвращает манифесты.
  При datasetId этот обработчик и соответствующий манифест обязательны.
  Проверку структуры ZIP/ODF и открытие в LibreOffice добавляет T2.10.

Схема сама по себе не доказывает правильность рисунка или файла. Общий набор
не подменяет предметные проверки; отрицательные тесты демонстрируют отклонение
сломанных генераторов. Золотые снимки обновляются только после просмотра изменений.

## Выгрузка

```sh
npm run sample -- --task 1 --n 50
npm run --silent sample -- --task 1 --n 50 --seed lesson > sample.md
```

Вывод — готовый Markdown с условиями, ответами и решениями. До 1000 задач за вызов;
при нескольких подтипах выбираются по кругу. Seed каждой задачи — базовый seed
с суффиксом `:0`, `:1` и далее. Ошибки параметров и отсутствующий номер дают код 1,
без частичной выгрузки. Команда использует уже установленный Vite для загрузки TS.

Пример из tasks.md `--task 15 --n 50` станет доступен после реализации генераторов
«Робота». Сейчас он честно сообщает об отсутствии генератора (ADR-022).

## Галерея

После `npm run dev` маршрут `/test-oge-app/dev/generators/` позволяет выбрать
генератор и базовый seed и посмотреть 20 задач, ответы и решения. Маршрут
инжектируется только при Astro dev, имеет noindex и отсутствует в production.
Это инструмент авторинга; публичный каталог практики реализуется отдельно.

## Подтипы №5 и №6 (T3.3)

| Номер | Подтип | Отличие |
| --- | --- | --- |
| 5 | `executor-fixed-v1` | Единственная программа из заданного числа команд |
| 5 | `executor-shortest-v1` | Единственная кратчайшая программа |
| 5 | `executor-missing-v1` | Восстановление двух пропущенных команд |
| 5 | `executor-string-v1` | Обмен и циклический перенос символов |
| 6 | `program-assign-v1` | Последовательное изменение двух переменных |
| 6 | `program-branch-v1` | Подсчёт результатов десяти запусков с and/or |
| 6 | `program-for-v1` | Сумма кратных чисел с включённой верхней границей |
| 6 | `program-while-v1` | Отбор цифр числа, включая проверку равенства порогу |

№5 перебирает программы при генерации, проверяет ответ обратным поиском,
а тест использует отдельный прямой перебор битовых масок. Для кратчайшей программы
исключаются все более короткие пути. Длина — 3–5 команд; начальное число больше
слагаемого, чтобы первая команда сложения не совпадала с умножением. В строковом
исполнителе четыре различных символа. Все ответы однозначны, включая два пропуска.

№6 использует фиксированные шаблоны Python 3: исходный код не исполняется в браузере.
Проверка принимает только известный шаблон, извлекает входные данные из условия
и вычисляет ответ отдельно. В тестах настоящий Python 3 запускает по 500 задач
каждого подтипа (6500 запусков с учётом таблиц входов); этот тест требует `python3`.
Граничные случаи включены конструктивно: равенство строгим границам, последнее
значение range, цифра на пороге отбора и ноль в записи числа.

Каждый из восьми подтипов также проходит общий набор из 500 seed’ов и трёх золотых
снимков. Реестр содержит 24 подтипа; проверки Node/Workers/браузера охватывают все.
Примеры: [№5](../samples/05.md), [№6](../samples/06.md), по 12 задач.
Воспроизведение: `npm run --silent sample -- --task 5 --n 12 --seed t3.3-review`
(для №6 заменить номер), затем форматирование Prettier.

Подключение новых подтипов к публичному потоку практики остаётся отдельной задачей.

## Подтипы №7 и №8 (T3.4)

| Номер | Подтип | Отличие |
| --- | --- | --- |
| 7 | `url-root-v1` | Сборка URL файла в корне сервера |
| 7 | `url-directory-v1` | Сборка URL с каталогом |
| 7 | `url-select-v1` | Выбор семи фрагментов из девяти: лишние протокол и расширение |
| 7 | `url-move-v1` | Восстановление адреса после переноса и переименования файла |
| 8 | `search-union-v1` | Объединение двух множеств по отдельным количествам и пересечению |
| 8 | `search-intersection-v1` | Восстановление пересечения по объединению |
| 8 | `search-difference-v1` | Страницы с первым словом без второго |
| 8 | `search-three-v1` | Объединение трёх множеств с учётом тройного пересечения |

Адреса используют учебную зону `.example`, HTTP/HTTPS и явные условия о пути.
Ответ — метки фрагментов, заглавные латинские буквы. Проверка собирает адрес
по предложенному ответу и разбирает его через WHATWG URL: протокол, сервер,
путь должны соответствовать условию, скрытая нормализация и дополнительные
части адреса не допускаются. Тест независимо строит целевой адрес из условия
и перебирает разбиения по фрагментам, подтверждая единственность ответа.

Поисковые количества строятся из непересекающихся областей диаграммы множеств.
Это гарантирует согласованность исходных данных. В условии заданы единая база,
точные количества страниц и смысл И/ИЛИ. Verify восстанавливает области и
отвергает отрицательные количества. Независимый тест решает систему линейных
уравнений из таблицы, создаёт отдельные страницы с принадлежностью множествам
и пересчитывает запросы по этим страницам. Проверены пустое пересечение,
полное совпадение множеств, испорченные таблицы, метки и пути.

Для каждого подтипа — 500 seed’ов и три золотых снимка. Всего в реестре 32 подтипа
№1–8; совпадение Node/Workers/браузера проверяется для всех. Галерея дополнена
проверками URL и поисковых таблиц в обеих темах с axe и мобильной шириной.
Примеры: [№7](../samples/07.md), [№8](../samples/08.md), по 12 задач.
Воспроизведение: `npm run --silent sample -- --task 7 --n 12 --seed t3.4-review`
(для №8 заменить номер), затем Prettier. Публичный поток практики подключается
отдельно; Gate 3 этим шагом не закрывается.
