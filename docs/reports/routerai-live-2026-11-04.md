Дата: 2026-11-04, Asia/Novosibirsk. По прямому указанию владельца использован
переданный им тестовый ключ. Ввод — скрытый stdin, ключ передан только в память

## Дополнение: живая проверка Opus

По запросу «а опус?» выполнены четыре случая с `anthropic/claude-opus-5.5`
в качестве первой модели отдельного локального production Worker. Использован
тот же разрешённый тестовый ключ; основная пара в wrangler.toml не менялась.
Проверялись настоящие нативный fetch, лимитер, API-контракты и RouterAI;
веб-интерфейс для этой серии отдельно не открывался. Node egress фиксировал
только выбранную модель и HTTP-статус, чтобы не принять ответ Sonnet за Opus.

| Случай | Результат | Время |
| --- | --- | --- |
| Краткий верный ответ 85 | Opus HTTP 200, текст оборвался на полуслове; полноценного SSE/DONE нет | 13,044 с |
| Программа `print(1)` | Opus HTTP 200, затем вызвана Sonnet; итог API — 504 timeout, допустимый JSON не получен | 30,021 с |
| Офисная помощь | После Opus вызвана Sonnet; валидный criteria-help/null получен от резерва, не засчитывается как успех Opus | 21,543 с |
| Сводка | Opus HTTP 200, оборванный план без SSE/DONE; в тексте ошибочно указаны «остальные 18 номеров» при 16 заданиях ОГЭ | 28,294 с |

Итог: **0/4 случаев приняты как завершённый ответ самого Opus**.
Наличие HTTP 200 у RouterAI не доказывает успешное выполнение контракта приложения.
Проверка завершилась ненулевым кодом из-за отсутствия завершённого ответа;
это зафиксированный неуспех, а не зелёный прогон. Всего наблюдались шесть
исходящих обращений: четыре к Opus и два к резервной Sonnet.

Сохранены лимиты приложения: 700/500/1200 токенов по режимам, общий дедлайн
30 секунд, максимум две попытки. Лимиты и проверка полного ответа не ослаблялись.
Точная причина первого невалидного JSON Opus отдельно не установлена:
наблюдаемое свидетельство — переход на резерв, а не сохранённая диагностика
провайдера. С этой конфигурацией Opus пока не является рабочей заменой Luna/Sonnet.
Изменение промптов/лимитов для него и повторная приёмка этим прогоном не выполнялись.

## Повторная проверка Opus с диагностикой

По запросу владельца «попробуй еще раз» повторены четыре сценария через тот же
production Worker и RouterAI с разрешённым тестовым ключом. Конфигурация приложения,
лимиты 700/500/1200 токенов, общий дедлайн 30 секунд и пара в wrangler.toml не менялись.
Для разбора переданы numeral-sum-v2, seed live-routerai-case1 и ответ 85 без черновика;
остальные входы — programInput, officeInput и summaryInput из openrouter-data.ts.
Это повторная API-проверка; браузер отдельно не запускался.

Временный диагностический Node egress отправлял настоящие запросы и читал копию
ответа с ограничением размера, сохраняя finish_reason и usage отдельно от клиентского
потока. Запросы и ответы не подменялись. Ключ введён скрыто, в файлы не записывался.

| Сценарий | Время API | Opus: finish_reason / completion_tokens | Результат приложения |
| --- | --- | --- | --- |
| Верный ответ 85 | 13,991 с | stop / 594 из 700 | HTTP 200, полный SSE/DONE, расчёт 28 + 27 + 30 = 85 верен |
| Программа print(1) | 30,022 с | length / 500 из 500 | Невалидный JSON Opus, переход на Sonnet, итог HTTP 504 timeout |
| Офисная помощь | 28,429 с | length / 500 из 500 | Невалидный JSON Opus; Sonnet завершила criteria-help/null, HTTP 200 |
| Сводка | 20,854 с | length / 1200 из 1200 | HTTP 200 начинает поток, затем invalid-response; клиентского DONE нет |

**Итог повтора: 1/4 завершённых ответов самого Opus**, а с учётом резерва —
2/4 завершённых сценария API. Шесть исходящих запросов: четыре Opus и два Sonnet.
Диагностический прогон завершился кодом 1, поскольку не все сценарии прошли.
Ранее зафиксированные 0/4 относятся к первой серии, а не ко всем попыткам модели.

Причина незавершённости трёх ответов Opus в этом повторе подтверждена сообщением
провайдера length и достижением max_tokens. Для сводки провайдер прислал свой DONE,
но приложение правильно отклонило незавершённый текст: допустим только finish_reason
stop. План обрывается на пятом дне. Ошибка «19 заданий» в этот раз не повторилась.
Однако сводка делает из одного балла излишний вывод о владении переводом единиц;
завершение протокола само по себе не подтверждает педагогическое качество.

Есть несогласованность диагностических данных провайдера: при проверке программы
Opus сообщил 500 completion_tokens, но message.content содержит лишь три символа
начала JSON. Резервная Sonnet сообщила length и один completion_token, вернув
английское приветствие вместо оценки. Поэтому объяснение всех сбоев исключительно
многословием модели не доказано; наблюдения подтверждают сообщённое исчерпание
лимита, но не объясняют внутреннюю обработку ответа RouterAI. JSON офисного ответа
Opus также оборван (320 символов). При таймауте программы учитывается суммарное
время Opus и Sonnet, а не только Opus.

Повышение лимитов и настройка промптов в этом повторе не выполнялись. Opus пока
не принят как стабильная замена основной пары. Сервер с ключом остановлен,
временные скрипты и сырые диагностические результаты удалены после записи отчёта.
Изменена только документация; повторный полный verify не запускался.

## Обнаруженный дефект и исправление

Раньше production-транспорт передавал `redirect: error`. Нативный fetch
Cloudflare Workers принимает только follow/manual и отклонял запрос до
соединения с провайдером. Тесты с подставным fetch этого не выявляли:
даже прежние Workers-тесты подключали частный транспорт, а default entrypoint
проверялся лишь в выключенном состоянии.

Worker теперь использует `redirect: manual`; ответ 3xx отклоняется обычной
проверкой статуса, Location не используется. Ни основной, ни резервный запрос
не следуют редиректам. Клиентский браузер и Node-мост сохраняют поддерживаемый
ими режим error.

Локальный запуск использует настоящий production Worker в Miniflare и Node
egress-мост с унаследованным сетевым прокси и CA. Разрешён только фиксированный
POST endpoint RouterAI. Настройки читаются из того же wrangler.toml, секрет
передаётся отдельно; сохранены исходный SQLite-каталог и global-v1.
Ответ Node fetch передаётся потоково, заголовки уже распакованного тела
Content-Encoding/Content-Length удаляются. Дедлайн и отмена сохранены.

## Границы результата

ИИ проверен живыми запросами **локально**. Публичный флаг остаётся false,
внешний Worker и домен не размещались. Нет подтверждения денежного предела
ключа, отсутствия хранения/обучения у RouterAI, прекращения размещённого TCP
запроса при отмене и alarms размещённого DO. Нет 10 реальных ошибок учеников
и человеческого вердикта Gate 6. Технический прогон не заменяет эти проверки.

Все серверные процессы с тестовым ключом остановлены после прогона.
Решение и разрешение владельца — ADR-071.
