# T6.5 — лимиты IP и дневной бюджет

Дата: 2026-10-30 (Asia/Novosibirsk). ADR-063; локальный срез без ключа.

Публичный обработчик умеет включать OpenRouter только через точный серверный
флаг AI_ENABLED=true и полную конфигурацию. В репозитории false/лимит 0,
внешний Worker не размещён; ученик продолжает пользоваться локальным примером.
Настоящих обращений к провайдеру и денежных расходов этот шаг не создавал.

## Что реализовано

- worker/src/access.ts: доверенный CF-Connecting-IP, канонизация IPv6/mapped IPv4,
  HMAC-SHA-256 с отдельным секретом, IP-допуск до чтения JSON, резервирование
  бюджета перед каждым provider fetch, безопасный запрет при сбое.
- worker/src/quota-object.ts: один SQLite DO/global-v1, транзакционные
  скользящие окна 10/60 секунд и 60/24 часа, общий дневной счётчик попыток,
  UTC-сброс, alarm для истечения идентификаторов. Нет сырых IP и ученических тел.
- worker/src/index.ts и transport.ts: защищённый default, health по конфигурации,
  безопасные 429/503 и Retry-After. Прежние Origin, метод, raw 8 KB, zod,
  серверная пересборка и защитные заголовки сохраняются.
- worker/wrangler.toml: выключенный флаг, нулевой лимит, namespace и миграция
  SQLite-класса; ключей, HMAC-секрета и выбранных моделей нет.

Глобальный лимит считает попытки провайдера: fallback/повтор JSON требуют
ещё одного разрешения, IP-окно расходуется один раз. Отмены и ошибки не
возвращают потенциально потраченное разрешение. Это ограничение числа обращений;
денежный лимит OpenRouter настраивается отдельно владельцем перед подключением.
Неподтверждённая запись может уменьшить доступный остаток, но не разрешает обход.
Повторный запуск обработчика, eviction и изменение значения лимита не сбрасывают
счётчик. Смена namespace/имени или HMAC-секрета требует отдельной процедуры.

## Проверка

- 46 новых unit-сценариев: 11-й/61-й запросы, скользящие границы, midnight UTC,
  общий лимит разных IP, fallback и JSON-повтор, конкуренция, конфигурация,
  ошибки/повреждение DO, отсутствие возврата после отмены, нормализация адресов,
  приватность storage/логов/provider, alarm без возвращения клиента, позднее
  разрешение после дедлайна и отмена lookup.
- Один новый тест настоящего Workers runtime/SQLite DO: три режима совместно,
  11 параллельных запросов одного IP → 10 разрешений/один 429; fallback
  списывает два обращения; восемь разных IP конкурируют за два остаточных слота,
  после трёх eviction лимиты сохраняются. Провайдер целиком частный тестовый.
- Целевой регрессионный набор: 225 тестов / 8 файлов прошли, включая T6.1–T6.4
  и оба настоящих runtime-теста транспорта/лимитов. Typecheck: 574 файла,
  0 ошибок/предупреждений, два прежних hint XMLValidator.
- Wrangler dry-run собирает namespace/миграцию и выключенные переменные;
  сканирование двух файлов сборки — без секретных маркеров. Полный source CI,
  merged-main CI и Pages проверяются при доставке; итоговые ссылки — в PR.

Проверки и код сайта, браузерные сценарии, retries, таймауты, пороги качества
и зависимости не ослаблены. Экзаменационные форматы/материалы и оценивание не
менялись; «реши как ученик» здесь неприменимо, использованы существующие реальные
реестры заданий для трёх режимов HTTP.

## Трассировка и границы

§11.1/11.3 → configured default + прежний набор ai-worker;
§13 → HMAC/очистка/нулевые логи + приватностный unit-тест;

НЕ ПРОВЕРЕНО: реальный edge CF-Connecting-IP, внешний Worker/DO и доставка его
alarms, денежный лимит ключа, ответы настоящих моделей и сквозной TCP-разрыв.
Alarm может быть доставлен платформой позже времени истечения; сырых IP нет
в хранилище вообще. Один DO сериализует нагрузку, общий NAT делит IP-лимит;
выбранная архитектура требует preview на ожидаемой нагрузке в T6.10.
Человеческие Gates открыты, живой пилот отложен владельцем.
