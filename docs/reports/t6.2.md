# T6.2 — серверная пересборка задания

Worker сам получает условие, эталон, критерии и вердикт из существующего ядра
по generatorId+seed или полному bankId. Краткий ответ и практическая работа
проходят проверку соответствия реальному типу задачи. Внешнего обращения к ИИ
нет: health false и ответ 503 после успешной подготовки сохраняются.

## Реализация и границы

`worker/src/prepare-request.ts` проверяет строгий контракт и ищет идентичность
в существующем реестре генераторов/банка. Задача проходит TaskInstanceSchema,
совпадение generatorId/seed/номера и verify генератора. Эталон или условие
из тела запроса не принимаются. Краткий ответ проверяет checkTaskAnswer;
неверный формат отклоняется до подготовки обращения к модели.

Для банка требуется полный версионированный TaskInstance.id. Короткий P01,
неизвестная/устаревшая версия и противоречащий seed не принимаются. Обе работы
№13 поддерживают и идентичность карточки generatorId+seed. Результат отделён
от каталога глубокой валидацией-копированием; изменение контекста не портит банк
и следующие запросы.

№13–14 дают контекст criteria-help со score null, №15–16 — preliminary
с максимумом из серверных критериев. Численной оценки работы пока нет;
код ученика не исполняется и офисные файлы не принимаются. Тексты пользователя
остаются отдельным недоверенным input; содержательная проверка — T6.8.
Сводка сохраняет прежний агрегатный контракт без пересборки одиночной задачи.

HTTP-граница вызывает подготовку, затем возвращает 503 ai-disabled. Неизвестные
идентичности, неверный режим, формат и лишние поля дают 400. Внутренняя ошибка
генератора, неправильная идентичность результата или verify false дают 500
без исходной диагностики. Ни эталон, ни критерии, ни внутренний вердикт не
возвращаются наружу; защитные заголовки и отсутствие логирования сохраняются.

## Трассировка

| Требование | Реализация и проверка |
| --- | --- |
| spec §11.2 / T6.2: пересборка через ядро | prepareFeedback/preparePart2, реестры и TaskInstanceSchema; HTTP использует подготовку |
| Совпадение с клиентом на 200 случаях | 200 различных seed `ai-server-parity-v1:0`…`:199`, все генераторы №1–12, 100 верных / 100 неверных; сравниваются полные задачи и AnswerCheck |
| Настоящий Workers runtime | Тот же модуль подготовки в Miniflare; производственная HTTP-точка отдельно проверяется для всех маршрутов, неизвестного id, неверного режима и конфликтующего seed |
| Неподменяемые данные | Лишние statement/correctAnswer/verdict/criteria дают 400; смена seed создаёт другую задачу и заново проверяет прежний ответ |
| Практические ограничения | Все генераторы №14–16 и все 24 кураторские работы; офисные score null, программы/Робот с максимумом 2; короткие ответы не принимаются как практика |
| Приватность при сбое | Контролируемые сбои генерации, идентичности и verify дают безопасный 500; проверены заголовки, отсутствие fetch/console-вызовов и отражения входа |

Паритет использует общий проверяющий модуль ядра и не объявляется независимым
решением задач. Проверки математической правильности и форматов остаются в
существующих property-тестах и экзаменационных фикстурах. Проверочный Worker
в tests/fixtures не включается в production-сборку, диагностического API нет.

Генераторы, формат экзамена, оценивание и сохранённые данные не менялись.
Порядок локальной приёмки — ADR-060. T6.3–T6.10 и человеческие Gates открыты;
живой пилот отложен владельцем, наблюдения не подставлялись. Сервер в интернете
не развёрнут; статический сайт сохраняет демонстрационный источник ответов.

## Локальные проверки

Прошли 124 теста в пяти файлах: пересборка, контролируемые сбои, HTTP-граница,
прежние демоисточник и безопасный потребитель. 200 случаев отдельно проверены
через производственный HTTP-маршрут и приватный Workers-харнесс. В каждом
генераторе представлены оба вердикта; примеры имеют разные seed.

Astro/TypeScript: 553 файла, 0 ошибок и предупреждений, два прежних уведомления
XMLValidator. Общие ESLint и Prettier успешны. Forbidden: 592 файла, 0 нарушений.
Wrangler dry-run: 1352,09 KiB / gzip 223,89 KiB; два файла без секретных маркеров.
Gitleaks просканировал 3,54 MB без находок. Увеличение относится к серверной
сборке с ядром, клиентские JS-бюджеты не меняются.

Локальный Wrangler проверен HTTP-запросами: health 200/false; подготовка краткого
ответа и полного bankId — 503; неизвестный генератор, неверный режим, короткий
bankId и конфликтующий seed — 400. В ответах только error, без задачи и вердикта.
Сервер после проверки остановлен.

Полные CI точного исходного коммита и итогового main с публикацией Pages
обязательны. Результаты фиксируются в описании PR без коммита с результатом
собственного CI; Pages подтверждает статический сайт, а не размещение API.
