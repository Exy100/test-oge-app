# T6.4 — транспорт OpenRouter без внешнего подключения

Добавлены клиент OpenRouter и внутренняя фабрика Worker для проверки всей цепочки
HTTP → пересборка → промпт → тестовый провайдер → SSE/JSON. Публичный default
Worker создаётся без клиента, поэтому health false и 503 сохраняются даже при
передаче переменных ключа/моделей. Сайт продолжает показывать локальное демо.

## Трассировка

| Требование | Реализация и проверка |
| --- | --- |
| spec §11.5: серверные модели, приватность, атрибуция | openrouter.ts: две разные модели из серверной конфигурации, deny, temperature 0.3, фиксированный URL, redirect error, HTTP-Referer/X-Title; тесты запроса и отказа при неверной конфигурации |
| spec §11.4: 700/500/1200 токенов | Выбор только по пересобранному режиму; три проверки фактических тел запросов |
| 429/5xx → один fallback | Отмена тела первой ошибки, резервная модель из конфигурации, те же сообщения, максимум две попытки; 400/401/403/404 и сетевой сбой не повторяются |
| Общий таймаут 30 секунд | CallScope охватывает заголовки и тело; тесты зависшего fetch, JSON, SSE и fallback после 20 секунд не получают новый дедлайн |
| Отмена | AbortSignal и cancel читаемой части отменяют исходящий сигнал, reader и таймер; поздний ответ отменённого fetch отбрасывается; оба API проверены также внутри Workers runtime |
| Поток без полной буферизации | Первый delta получается до завершения провайдера; provider-stream.ts учитывает UTF-8, CR/LF, многострочное data, комментарии и usage; ошибки/обрывы/length не дают ложного DONE |
| JSON → один повтор → ошибка | Строгие поля, score/kind по assessment, нет дополнительного балла; невалидный JSON/схема повторяются один раз, в том числе тест 429 → invalid JSON без третьего запроса |
| №13–16 | Офис сохраняет null без балла; программа/Робот preliminary не более 2; неверный вид, дробный/строковый/null балл программы и 3 балла отклоняются |
| Приватность и HTTP-защита | Метаданные/заголовки и диагностики провайдера не передаются; логгеры не вызываются; прежняя граница и защитные заголовки работают для SSE/JSON; лишний client model даёт 400 до fetch |
| Настоящий Workers runtime | Частный openrouter-worker.ts с тем же createWorker/client: два SSE-режима, fallback, обе практические формы, неверный JSON, Origin-отказ, отмена потока и сигнала запроса |
| Ограничения ресурсов | 1 MiB сырого ответа, 65 536 символов кадра, 12 000 символов текста; тесты oversized/некорректного UTF-8 и освобождения потока |

## Локальная проверка и границы

Новый целевой набор: 61 тест транспорта и один набор настоящего Workers
runtime с восемью сценариями, все 62 проверки успешны. Общий набор транспорта,
промптов, HTTP-границы, пересборки и демоисточника: 212 тестов в восьми файлах.

- `npm run typecheck`: 568 файлов, 0 ошибок и предупреждений, два прежних
  уведомления XMLValidator.
- `npm run lint`: ESLint и Prettier успешны.
- `npm run worker:check`: 1401,39 KiB / gzip 232,97 KiB, два файла,
  секретных маркеров нет.
- `npm run check:forbidden`: 607 файлов, 0 нарушений.
- Локальный Gitleaks не запускался: исполняемого файла в этой среде нет;
  обязательное сканирование исходников и сборки выполняет CI.

Полный CI исходного коммита, main и публикация Pages фиксируются в описании PR.

Код ядра, матрица экзамена, форматы заданий и детерминированная проверка №1–12
не меняются. Тестовые запросы используют реальные зарегистрированные задания;
синтетический провайдер не выдаётся за модель и не оценивает ученика на сайте.

Внешние ключи и модели не использовались. Реальное соблюдение JSON/инструкций
моделью, её качество, счёт провайдера и сквозная отмена при разрыве TCP с
размещённым Worker — НЕ ПРОВЕРЕНЫ. Локальная попытка TCP-проверки через Miniflare
не наблюдала сигнал отключения; это не засчитанный успех. Флаг входящего
request.signal включён явно, API-отмена проверена внутри runtime; сквозной
сценарий обязателен на preview в T6.10, как и конфигурация настоящего аккаунта.

ADR-062 уточняет локальный порядок. T6.5–T6.10, Gate 6, живой пилот и человеческие
ревью остаются открытыми. Следующий шаг — T6.5: лимиты, бюджет и управляемое
включение сервиса. Внешнее подключение ждёт выбранных владельцем настроек.
