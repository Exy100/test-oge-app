# T6.13 — RouterAI и локальная проверка приложения

2026-11-04, Asia/Novosibirsk. Владелец выбрал RouterAI, подтвердил предложенную
пару Luna → Sonnet и сообщил, что домена/Cloudflare нет.

Последующий живой прогон по прямому указанию владельца выполнен с его
тестовым ключом. Он выявил и помог исправить redirect нативного fetch Worker;
[актуальный результат](routerai-live-2026-11-04.md). Ниже — первоначальная
инженерная приёмка, до живого подключения.

## Что изменилось

`npm run ai:local` запускает приложение и настоящий Worker на одном локальном
HTTPS-адресе без облачного аккаунта. Новый ключ запрашивается скрыто в терминале
и передаётся только локальному серверу. Запуск без модели — с `--disabled`.
Раскрытый владельцем ключ не сохранялся в проект и для запросов не использовался.

В серверной конфигурации выбраны RouterAI, `openai/gpt-6-luna` и
`anthropic/claude-sonnet-5.5`, лимит 600 попыток/UTC-день. Opus не добавляет
третью попытку. Публичный флаг остаётся `AI_ENABLED=false`.

Для RouterAI используется собственный секрет `ROUTERAI_API_KEY` и фиксированный
endpoint. OpenRouter сохранён как отдельный вариант с собственным ключом.
Модель и endpoint из тела ученика не принимаются. Пересборка, оценки,
атомарный бюджет, IP-лимиты, дедлайн и ограничения ответа сохранены.

Клиент показывает действительное имя сервиса в согласии и политике
конфиденциальности. RouterAI требует новое согласие; разрешение и кэш
OpenRouter не переносятся. X-AI-Provider связывает браузер с сервисом,
настроенным сервером: несовпадение отклоняется до лимитера и провайдера.
Проверки исходников и сборок дополнены форматом ключей RouterAI.

## Фактические проверки

- Выбранный набор ИИ и проверок секретов: **371 passed / 17 файлов**.
  Включает настоящий Workers runtime и SQLite Durable Object с обоими сервисами.
- Пять AI-файлов Playwright с `OGE_TEST_AI_PROVIDER=routerai`:
  **36 passed**, Chromium desktop/mobile, 1,3 минуты.
  Ответы моделей в этом наборе подставляются Playwright.
- Новая команда `npm run ai:check`: **6 passed**, 19,9 секунды,
  Chromium desktop/mobile. Это настоящий браузер → локальный HTTPS-прокси →
  настоящий Worker, без перехвата HTTP и без ключей/провайдера.
  Проверены health, работа заданий при выключенном ИИ, Origin, несовпадение
  сервиса, отсутствие заголовка RouterAI и фактическая политика конфиденциальности.
  Команда добавлена в обязательный browser job CI (shard 1); запуск изменённого
  workflow в GitHub в этой локальной сессии не выполнялся.
- Отдельный интерактивный запуск с **фиктивным** ключом: скрытый ввод не
  отражается в терминале; настоящий Worker возвращает `enabled:true`;
  браузер показывает согласие RouterAI, отказ не отправляет POST.
  Это проверка конфигурации и согласия, а не аутентификации у RouterAI.
  Фиктивное значение не найдено в `.cache/ai-local` и `.wrangler` после остановки.
- Проверка типов прошла без ошибок; два прежних сообщения о deprecated
  XMLValidator остались справочными замечаниями.

Полный `npm run verify` завершился с кодом 0: **2385 passed / 111 файлов**,
core lines **97,70%**, пороги сохранены. Прошли lint/форматирование, типы,
сборка/сканирование Worker, coverage, forbidden, контраст, сборка сайта,
контент и сканирование dist. Контент: 76 HTML, 326 исходников, 40 формул,
0 находок; dist: 315 файлов без секретных маркеров. Сами unit-кампании заняли
1154,64 секунды. После последних правок также отдельно прошли lint, typecheck,
worker:check и 20 тестов RouterAI/защиты CI. Проверка CI сначала упёрлась
в запрет spawnSync обычной песочницы; повтор с разрешённым дочерним Node прошёл.
Полный e2e и Firefox/WebKit в этом локальном прогоне не запускались.
Экзаменационные форматы и баллы не менялись.

## Что обнаружил реальный локальный прогон

Новый запуск проверялся отдельно от прежних тестов с перехватом HTTP.
Он обнаружил и помог исправить режим React/кэш Vite, обработку корневого
`/api/ai/` при base приложения, передачу HTTPS Origin через локальный HTTP-хоп,
фильтрацию HTTP/2 и hop-by-hop заголовков и передачу vars в текущем Wrangler.
Эти сценарии теперь воспроизводятся через `ai:check`.
Неуспешные первые прогоны не засчитаны как успешные.

## Сверка с RouterAI

Бесплатные GET к публичному каталогу 2026-11-04 вернули HTTP 200 и точные ID:

| Модель | Публичный endpoint |
| --- | --- |
| openai/gpt-6-luna | [Каталог](https://routerai.ru/api/v1/models/openai/gpt-6-luna/endpoints) |
| anthropic/claude-sonnet-5.5 | [Каталог](https://routerai.ru/api/v1/models/anthropic/claude-sonnet-5.5/endpoints) |
| anthropic/claude-opus-5.5 | [Каталог](https://routerai.ru/api/v1/models/anthropic/claude-opus-5.5/endpoints) |

В supported_parameters есть параметры лимита ответа и формата JSON;
temperature у выбранных моделей не заявлен. Для RouterAI это поле исключено,
для прежнего OpenRouter сохранено 0.3. Каталог подтверждает существование ID,
не доступ конкретного ключа и не качество ответа.

## Осталось проверить живым запросом

С новым ключом выполнить `npm run ai:local`, открыть напечатанный адрес,
проверить ответ в потоке и явно разрешить отправку в диалоге RouterAI.
После этого проверить практику и сводку по [сценарию Gate 6](../reviews/phase-6.md).
Инструкция и серверные настройки — [docs/deploy.md](../deploy.md).

Платных запросов в этом прогоне не было. Живые SSE/JSON, качество объяснений,
доступ моделей с ключом, денежный предел и фактическая поддержка
provider.data_collection=deny у RouterAI остаются **НЕ ПРОВЕРЕНЫ**.
Внешний preview, прекращение размещённого запроса при отключении браузера,
alarms размещённого DO и человеческий Gate 6 также не закрыты.
Домен нужен для внешнего размещения, а не для описанной локальной проверки.

Решения и отличия от прежнего OpenRouter — ADR-070.
