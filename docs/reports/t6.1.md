# T6.1 — локальная HTTP-граница Worker

Следующий плановый серверный шаг подготовлен без регистрации и платных запросов.
Каркас действительно исполняется в Workers и локальном Wrangler: четыре маршрута
принимают только разрешённые методы, Origin и ограниченные входы. Health сообщает
`enabled: false`; корректный POST получает 503 `ai-disabled`. На сайте остаётся
браузерный демонстрационный источник T6.0, сервер в интернете не развёрнут.

## Реализация

- `worker/src/index.ts`: маршруты, точный Origin, GET health без Origin при
  совпадении origin адреса, Allow/405, JSON/UTF-8, отказ от сжатия и ограничение
  исходного потока 8192 байтами. Content-Length проверяется, но не заменяет
  подсчёт фактических байтов; избыточный поток отменяется.
- `worker/src/contracts.ts`: прежний контракт краткого ответа и строгие
  входы практической работы/сводки. Эталон и условие не принимаются от клиента;
  сводка отклоняет тексты ответов. Максимумы баллов — из examConfig,
  самооценка null не заменяется нулём. Пересборка и соответствие типу задачи
  остаются T6.2/T6.8, а не объявляются выполненными синтаксической проверкой.
- Все статусы имеют no-store, CSP, HSTS, nosniff, X-Frame-Options, COOP same-origin,
  Referrer-Policy и Permissions-Policy с запретом платежей. Для JSON используется
  более строгая CSP default-src none (ADR-059). Ошибки не отражают частные данные
  или исключения парсера. Нет разрешающих CORS-заголовков, cookies,
  логирования входных данных или исходящих запросов к ИИ.
- `worker/wrangler.toml`: известный origin сайта, без публичного маршрута,
  workers.dev и preview URL, observability выключена. Команды `worker:dev`, `worker:build` и `worker:check`
  запускают локальный runtime, dry-run сборку и поиск секретных маркеров.
- Общий verify и обязательное CI-задание исходников включают проверку Worker.
  CI сканирует его Gitleaks и сохраняет `worker-bundle`; сервер не попадает
  в dist GitHub Pages. Новых зависимостей или ослабления проверок нет.

## Трассировка

| Требование | Реализация и доказательство |
| --- | --- |
| T6.1 / spec §11.3: четыре маршрута, 405/400/403/413 | `index.ts`, `contracts.ts`, `ai-worker.test.ts`; те же границы в настоящем Workers runtime |
| Размер до разбора JSON, недоверие к Content-Length | Потоковое чтение, отмена после второго избыточного чанка; ровно 8192 байта принимаются, 8193 и избыточные UTF-8 байты отклоняются |
| Строгие входы без клиентских эталонов | Лишние поля, две идентичности, отсутствующий seed, превышение длины, повторные номера и лишние баллы дают 400 |
| Приватность и отключённое состояние | Проверки отсутствия fetch и console-вызовов; приватные тексты ошибок чтения/JSON не отражаются в ответах; health false и POST 503 |
| Реальная сборка и локальная работа | Wrangler dry-run; запуск `worker:dev` и HTTP-пробы health, валидного/неверного POST, Origin, метода и размера |
| Защитные заголовки всех статусов | Проверяются у успеха health, ошибок 400/403/404/405/413/415/503 и в Workers runtime |

## Проверки и границы приёмки

Локальный набор HTTP-границы: 54 успешных теста, включая Miniflare с настоящим
runtime Workers и все четыре маршрута. Вместе с прежними проверками источника
и безопасного потребителя T6.0 прошли 88 тестов. TypeScript/Astro: 0 ошибок,
0 предупреждений, два прежних уведомления XMLValidator. ESLint и Prettier
прошли после форматирования таблицы команд README.

Wrangler dry-run: 787,43 KiB, gzip 124,28 KiB; JS и source map проверены,
два файла без секретных маркеров. Это серверная сборка; клиентские бюджеты
страниц не меняются. Локальная команда Wrangler отработала с ожидаемыми
HTTP-статусами: health 200/false, POST 503, лишнее поле 400, Origin 403,
метод 405, избыточное тело 413. Процесс после проверки остановлен.

Порядок локальной приёмки уточнён в ADR-059. Домен сервера, модели, бюджет
и размещение не выбраны; внешняя доставка Worker НЕ ПРОВЕРЕНА и этим шагом
не закрывается. T6.2–T6.10, Gate 6 и остальные человеческие Gates открыты;
наблюдения учеников не подставлялись. Официальные форматы задач и проверка
их решений не менялись, предметная приёмка этим инженерным срезом не заменяется.

Полные CI точного исходного коммита и итогового main с публикацией Pages
обязательны. Результаты и ссылки фиксируются в PR без коммита с результатом
собственного CI. Публикация Pages подтверждает статический сайт, а не хостинг API.
