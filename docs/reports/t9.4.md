# T9.4 — кроссбраузерность и мобильный экран

Начало: 2026-10-26, Asia/Novosibirsk. Основа — опубликованный main `776a250`
([PR №10](https://github.com/Exy100/test-oge-app/pull/10),
[CI/Pages 40355388184](https://github.com/Exy100/test-oge-app/actions/runs/40355388184)).
Доставка T9.4 требует полного успешного CI итогового SHA и повторного CI/Pages main.

## Реализация

- `playwright.config.ts`: три прежних desktop-профиля и три полных профиля
  360 × 800 с touch: Chromium, Firefox, WebKit. У WebKit — мобильный iPhone
  descriptor и `isMobile: true`; у Firefox узкий viewport и touch без флага
  `isMobile`, который этот движок не поддерживает.
- Во всех шести профилях выполняется весь обычный набор: полный экзамен №1–16,
  поток, восстановление, файлы, уроки, результаты, 2D/3D, axe, CSP и приватность.
  Визуальный проект и его эталоны сохраняются отдельно. Новый unit-контракт
  блокирует сокращение профилей, viewport/touch или release gate.
- В шести файлах сцен tap выбирается по `hasTouch`, а не названию `mobile`.
  Desktop сохраняет проверки клавиатуры; новые мобильные профили получают
  касания там, где они уже проверялись на Chromium.
- `mobile-journey.spec.ts`: два сквозных сценария с настоящим `locator.tap()`
  и подсчётом доверенных `touchstart`. Первый сохраняет условие, ответ и черновик
  при размерах 360 × 800 → 800 × 360 → 360 × 800, проверяет правильный ответ
  и переход дальше. Сравнивается полный текст DOM, включая MathML: визуальные
  пробелы innerText при перекомпоновке WebKit не меняют смысл условия.
- Второй сценарий запускает тренировку №13.2, проверяет №1, вводит №2,
  дожидается настоящего автосохранения, перезагружает и продолжает с теми же
  ответами/черновиком. Часы и хранилище не подменяются. В обоих сценариях
  проверяется отсутствие переполнения по горизонтали.
- Для узких Firefox/WebKit ограничены минимальные размеры grid-колонок:
  `.information-lab` и элементы формы dev-галереи больше не расширяются по
  intrinsic-ширине native select/кода. В Роботе длинный пример прокручивается
  внутри доступного `pre`, не растягивая всю страницу при тексте 200%.
  Это относится и к отдельной сцене лабиринта; её пример программы получает
  собственный клавиатурный фокус и подпись прокручиваемой области.
  Форма галереи использует ограниченные grid-колонки; длинные программы решения
  также прокручиваются локально и доступны с клавиатуры. Проверки галереи
  сохраняют строгое условие отсутствия переполнения и выводят размеры при ошибке.
  Выбранный текст native select обрезается многоточием внутри самого поля,
  чтобы WebKit не рисовал длинное название за его границей.
- Сдвиг кнопки при hover применяется только к fine-pointer с настоящим hover.
  На touch кнопка не перемещается под пальцем. Проверка 20 циклов ресурсов
  также выбирает tap по hasTouch, сохраняя mouse-click в desktop и все счётчики.
  При переполнении HTML-тест выводит размеры и элементы за краем viewport;
  условие `scrollWidth <= innerWidth` сохраняется без допуска.
- Полный набор расширен с 2870 до 4290 запусков. CI распределяет его на десять
  обязательных групп вместо шести; прежние 20-минутные лимиты, `retries: 0`,
  forbidOnly, все пороги, четыре performance-группы и проверки файлов сохранены.
  Pages требует успеха всех групп. Архитектура проверки — ADR-052.

  В каждом обычном профиле один и тот же полный набор, без testMatch/grep.
- Unit release-контракт: **5/5** проверок, включая новую матрицу и прежние бюджеты.
  Вместе с performance-контрактом — **11/11** целевых unit.

## Трассировка и ручные проверки

| Требование | Проверка |
| --- | --- |
| spec §17, T9.4: три движка и 360 px | шесть полных профилей, unit release-контракт, десять обязательных CI-групп |
| spec §16: основные сценарии на телефоне | весь набор в mobile-профилях, trusted touch, ввод, изменение размеров и восстановление |
| spec §9.4/9.6: ввод и сохранение работы | touch-поток и тренировка; прежние полные экзаменационные сценарии во всех профилях |
| spec §14: доступность | прежний axe/клавиатура/200% текста и полный обход всех HTML в обеих темах расширены на шесть профилей |
| spec §12–13 | защитный наблюдатель T9.3 также работает в новых mobile-профилях |

Матрица и воспроизведение: [docs/cross-browser.md](../cross-browser.md).
Новых зависимостей и отклонений от spec нет. Форматы №1–16 не меняются;
тесты используют настоящие генераторы и самостоятельную проверку ответа.
`currentPhase` остаётся 3. Фаза 6 отложена; человеческие Gates 3–5/7/8/9 открыты.
Эмуляция не подтверждает физический телефон, системную клавиатуру, акселерометр,
мобильный скринридер или физический FPS. Их проверяет человек по
[чек-листу](../a11y-checklist.md).
