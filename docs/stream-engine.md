# Движок адаптивного потока

T4.1 реализует чистое TypeScript-ядро в `src/core/stream/`. Оно не обращается
к DOM, часам, сети или хранилищу. Карточка, фильтры в URL и постоянное сохранение
подключаются следующими задачами фазы 4. Версия алгоритма — informatics-stream-v1.

## Сессия и задания

```ts
import {
  createStreamSession, nextStreamTask, recordStreamResult,
  configureStream, restoreStreamState,
} from '../src/core/stream';
import { streamSources, resolveStreamTask } from '../src/core/stream/catalog';

let session = createStreamSession('урок-1', { sources: streamSources() });
const active = nextStreamTask(session);
const task = resolveStreamTask(active.current.reference);
session = recordStreamResult(active, { kind: 'automatic', correct: true });
session = restoreStreamState(JSON.parse(JSON.stringify(session)));
session = configureStream(session, { numbers: [1, 11, 13], variant13: 'document' });
```

По умолчанию выбраны 1–10. №11–16 добавляются явно. Каталог содержит реальные
58 генераторов и два банка с 12 наборами каждый для №13. Источник №13 имеет
явную ветку presentation/document; возвращается только выбранная работа.
Ссылка задания — generatorId, seed, taskNumber; разрешение ссылки проверяет
номер и генератор либо существование кураторского набора. Копия задания №13
не изменяет общий банк.

Состояние проверяется строгими схемами, копируется и приводится к стабильному
порядку номеров, статистики, источников и их seed. Очередь сохраняет свой порядок.
Повтор nextStreamTask при активном задании возвращает ту же задачу. Изменение
выбора снимает активную карточку, сохраняя очередь и статистику. Вызов с тем же
набором номеров в другом порядке карточку не снимает.

Для случайных выборов используется версионированный Rng с именованными fork.
Счётчик draws растёт только при выдаче случайной задачи. Повторения его не
расходуют. Seed генерируемого задания содержит версию, hashSeed сессии и индекс
случайного выбора, укладываясь в ограничение 200 символов для ссылки. В пределах
сессии генерируемые ссылки не повторяются. Хеш учебный, не криптографический;
различные строки могут иметь один хеш, как и у основного RNG.

## Вероятности и оценки

streamDistribution возвращает точность, вес ошибок и вероятность каждого
выбранного номера. Для N номеров: `p = 0.5/N + 0.5*w/sum(w)`, `w = 1 - accuracy`.
Без наблюдений и при нулевых весах распределение равномерно. Одинаковая точность
даёт равные вероятности независимо от числа попыток. Статистика невыбранных
номеров на текущие веса не влияет.

У номера без наблюдений accuracy остаётся null. Для планирования он получает
средний вес ошибок изученных выбранных номеров; при отсутствии таких номеров — 0.
Так неизвестный результат не превращается в фиктивный успех или ошибку.

Статистика разделяет automatic (attempts/correct), self и aiAccepted
(attempts/credit). Оценённая практика добавляет `score / maxScore` к credit,
максимум берётся из examConfig. Общая точность — сумма верных автоматических
ответов и нормированных баллов, делённая на число оценённых попыток.
Баллы 1 из 3 и 1 из 2 имеют разный вклад. Практика без оценки и пропуск не меняют
статистику. Форматная ошибка сохраняет активную задачу, счётчики и очередь.
Ядро принимает уже проверенный вердикт/оценку: оно не исполняет программу,
не проверяет офисный файл и не объявляет самооценку автоматическим результатом.

## Очередь ошибок

dueAfter — количество **других завершённых задач до повтора**, не дата и не
абсолютный номер в сессии. Благодаря этому очередь можно переносить между
сессиями. После ошибки или неполного балла сохраняется конкретная ссылка,
step=3, dueAfter=3. После трёх других завершений она готова к возврату.
Полный успешный ответ при повторе переводит интервал на 10, затем на 30;
успешный ответ на третьем возврате удаляет запись. Интервалы отсчитываются
после каждого оценённого возврата, не все от первоначальной ошибки.

Повторная ошибка начинает цепочку с 3. Пропуск/практика без оценки на повторении
сохраняют ступень и откладывают его на три другие задачи. Одна ссылка имеет
одну запись: новая ошибка заменяет прежнее расписание. Случайный правильный
ответ на ту же кураторскую ссылку до её срока не закрывает запланированное
повторение. Конечный кураторский банк допускает естественные случайные повторы.

Готовая подходящая запись обслуживается до случайного выбора; при нескольких
записях используется порядок очереди. Отфильтрованные номера и другая ветка №13
сохраняются и ждут возвращения выбора. Другие завершения уменьшают их dueAfter
до нуля. Повторения ведутся отдельно от случайного распределения: правило 50/50
не обещает точных долей в коротком потоке с очередью.

Схемы ограничивают очередь 1000 уникальными ссылками. Переполнение очереди
или безопасного целого счётчика отклоняет переход целиком и сохраняет исходное
состояние. Интеграция хранения и уведомлений относится к T4.5; существующий
формат localStorage этим шагом не меняется.

## Проверки

Профильные тесты проверяют 500 наборов статистики независимой формулой,
три кампании по 5000 фактических выборов с границей шесть стандартных отклонений,
500 seed сессий с 20 переходами, неизменность входа и восстановление JSON.
Есть три золотые последовательности, точные интервалы 3/10/30, сбросы,
отсутствие оценки, оба банка, фильтрация, FIFO, дедупликация и неверные границы.
Все реальные генераторы и 24 ссылки банков разрешаются в задания; две сессии
по 100 выдач проверяют реальные ссылки обоих выборов №13.

Один сценарий на 64 перехода выполняется на одинаковых семи seed в Node,
настоящем Workers runtime и браузерах. Он включает ошибки формата, ошибки ответа,
частичные баллы, обе ветки №13, смену выбора и восстановление. Решения о
недоопределённых деталях — [ADR-032](../DECISIONS.md#adr-032-семантика-адаптивного-потока-и-повторений).
