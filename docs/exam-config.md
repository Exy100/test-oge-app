# Конфигурация экзамена T2.3

`src/core/exam/exam.config.ts` экспортирует readonly `examConfig` и
`practiceTaskNumbers`. Значения перенесены из [сверки формата](exam-format.md),
выполненной 2026-10-05; новой проверки окончательных документов этот шаг не заявляет.

- `format`: год 2027, статус draft, verification VERIFIED — проверен именно
  проект. finalApproval UNVERIFIED сохраняет отсутствие подтверждения утверждения.
  source содержит архив ФИПИ, имя PDF и печатные страницы спецификации.
- `taskCount`, `durationMinutes`, `maxScore`: 16, 150, 21.
- `parts`: №1–10 и №11–16; для второй части нужен компьютер.
- `recommendedTime`: 30/120 минут, именно рекомендация с отдельным источником,
  а не два обязательных таймера.
- `tasks`: Record по каждому TaskNumber. Описаны умение, КЭС, официальный уровень,
  часть, максимум, способ проверки и источник. Для практики указаны виды артефакта.
  №11–12 имеют short-answer при examPart 2. Конкретный краткий ответ и его алфавит
  определяет TaskInstance, а не общий номер задания.
- `task13`: выбор ровно одной альтернативы, 13.1/13.2, presentation/document,
  КЭС 4.3/4.1 и форматы ответа odp/odt. Они не добавляются в tasks отдельными номерами.
- `grading`: год 2026, статус recommendation, собственный source — письмо
  Рособрнадзора №04-44, физическая страница PDF 8, таблица 11. Диапазоны включают
  обе границы: 0–4/5–10/11–16/17–21 → отметки 2/3/4/5. Применимость к году формата
  и региональным правилам остаётся UNVERIFIED; notice содержит пояснение ученику.

`practiceTaskNumbers` связывает пять видов артефактов с четырьмя номерами;
оба вида №13 имеют одинаковый максимум. Схемы TaskInstance, PracticeEvidence
и Variant используют конфиг для проверки частей, видов работ, максимумов и
числа заданий. Функции подсчёта полученных баллов и отметки появятся в T2.5.
Python 3 и LibreOffice — учебные предпочтения проекта, не поля официального
формата и не требования ко всем участникам экзамена.

Тесты сравнивают все строки tasks с таблицей docs/exam-format.md, сверяют
источники с сохранённым JSON-манифестом, отдельно проверяют сумму 21, №13,
компьютерные краткие ответы и отсутствие пропусков/пересечений шкалы 0–21.
Изменение формата требует сверки источников и обновления этих проверок;
простая смена года не превращает проект или рекомендации в утверждённые правила.
