# Браузеры и мобильный экран

T9.4, spec §14, §16–17. Полный набор e2e работает в шести профилях Playwright.
В каждом запускаются все обычные сценарии, включая полный экзамен №1–16,
восстановление, файлы, результаты, уроки, 2D/3D, axe, CSP и приватность.

| Профиль | Движок | Экран | Touch | Эмуляция мобильного браузера |
| --- | --- | --- | --- | --- |
| chromium | Chromium | Desktop Chrome | нет по умолчанию | нет |
| firefox | Firefox | Desktop Firefox | нет по умолчанию | нет |
| webkit | WebKit | Desktop Safari | нет по умолчанию | нет |
| mobile | Chromium | 360 × 800 | да | Android, Pixel 7 descriptor |
| mobile-firefox | Firefox | 360 × 800 | да | узкий viewport; Firefox не поддерживает `isMobile` |
| mobile-webkit | WebKit | 360 × 800 | да | iPhone descriptor, `isMobile: true` |

Версия Playwright закреплена в package-lock; CI устанавливает соответствующие
Chromium, Firefox и WebKit. Mobile WebKit — движок в тестовой среде, а не Safari
на физическом iPhone. Изменение viewport воспроизводит размеры после поворота,
но не проверяет акселерометр, системную клавиатуру и реальное устройство.

## Touch и сохранение работы

`mobile-journey.spec.ts` задаёт 360 × 800 и `hasTouch: true` для каждого движка.
Нажатия выполняются через `locator.tap()`. Сценарий считает только доверенные
`touchstart` с `event.isTrusted`, поэтому мышь или искусственное DOM-событие
не могут формально заменить проверку касания.

- Поток: ввод ответа и черновика, размеры 360 × 800 → 800 × 360 → 360 × 800,
  неизменность видимого условия/ввода, отсутствие горизонтального переполнения,
  правильный вердикт и переход к следующему заданию.
- Тренировка: касанием выбрать №13.2 и начать, проверить №1, ввести №2,
  изменить размеры экрана, дождаться настоящего автосохранения, перезагрузить,
  продолжить с теми же ответами/черновиком и вернуться к проверенному №1.
  Часы и localStorage не подменяются.

В существующих сценах выбор между tap и клавиатурой зависит от `hasTouch`,
а не от названия проекта. Настольные профили сохраняют проверки клавиатуры;
все три touch-профиля используют касания на соответствующих шагах.

Узкие grid-колонки и поля формы ограничены доступной шириной, в том числе
native select Firefox/WebKit. Длинный код Робота прокручивается внутри своего
доступного блока, не растягивая страницу при тексте 200%. Программы решений
в галерее также имеют собственную прокрутку и клавиатурный фокус. Сдвигающий hover-эффект
кнопки применяется только при fine-pointer с hover; touch-кнопка остаётся на месте.

## Запуск и CI

```bash
npm ci
npx playwright install --with-deps chromium firefox webkit
npm run e2e
```

Узкая проверка новых touch-сценариев:

```bash
npx playwright test tests/e2e/mobile-journey.spec.ts --project=mobile --project=mobile-firefox --project=mobile-webkit
```

CLI `playwright test --list --reporter=json` обнаруживает 706 сценариев в каждом
из шести профилей и 54 прежние визуальные проверки в `figure-visual`: всего 4290.
Визуальный проект сохраняет свой размер и эталоны. Другие проекты исключают
только его файл; `testMatch`, grep и условия для сокращения общего набора не добавлены.

Десять обязательных CI-групп делят полный набор через `--shard=N/10`, без
пропусков, `retries: 0` и с прежним 20-минутным лимитом. Deploy ждёт все группы,
unit/coverage, файлы, безопасность и четыре performance-группы (ADR-052).
Трассы ошибок сохраняются в `quality-reports-1`–`quality-reports-10` на семь дней.

## Проверка человеком

Нужны реальные Android + Chrome/Firefox и iPhone + Safari: системная клавиатура
в ответе/Python, прокрутка при открытой клавиатуре, масштаб, поворот устройства,
скачивание ZIP/ODF, восстановление после ухода в фон и мобильный скринридер.
Результаты записываются по [чек-листу доступности](a11y-checklist.md).
Эти ручные проверки остаются открытыми; эмуляция их не закрывает.
