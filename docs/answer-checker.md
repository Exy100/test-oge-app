# Проверка кратких ответов T2.4

`src/core/checker/index.ts` экспортирует `checkAnswer`, `checkTaskAnswer`,
`normalizeAnswer` и типы результатов. Это чистое TS-ядро без сети и зависимости
от DOM. Эталон и список ошибок поступают из проверенных данных TaskInstance.

`checkAnswer(expected, raw, commonMistakes)` возвращает дискриминируемый результат:

- `correct`: `counted: true`, нормализованное значение и notices.
- `incorrect`: то же, плюс explanation при совпадении с типичной ошибкой.
- `format_error`: `counted: false`, reason и понятное сообщение. Потребитель
  не должен увеличивать счётчик попыток для этого результата.

`checkTaskAnswer(task, raw)` передаёт эталон и commonMistakes. №11–12 проверяются
так же, как остальные краткие ответы, независимо от части экзамена.
Артефакт №13–16 вызывает TypeError: числовой ответ не заменяет оценку работы.
Некорректный эталон также вызывает ошибку, а не обвиняет ученика в неверном вводе.

## Правила нормализации

Для всех форматов внешние пробельные символы удаляются по ECMAScript `trim`,
включая обычный/неразрывный пробел, табуляцию и перевод строки. Пустой результат
даёт format_error. Другие преобразования зависят от типа.

| Тип | Правило |
|---|---|
| integer | ASCII-цифры, необязательный один `+`/`-`; BigInt даёт точную десятичную запись. Ведущие нули разрешены, `-0` становится `0`. |
| word | Unicode NFC, регистр учитывается по caseSensitive; без учёта регистра применяется независимый от локали `toLowerCase` и повторный NFC. |
| sequence | Удаляются только внутренние U+0020/U+00A0, затем NFC и проверка алфавита; регистр — по caseSensitive. Порядок и ведущие нули сохраняются. |

Integer не принимает дроби, экспоненты, шестнадцатеричную запись, единицы
измерения, внутренние пробелы, Unicode-минус и не-ASCII цифры. Number/float
для сравнения не используется; числа больше MAX_SAFE_INTEGER не округляются.

Word не склеивает слова, не заменяет внутренний NBSP обычным пробелом,
не удаляет пунктуацию. Схема word не задаёт алфавит: непустой печатный текст
сравнивается буквально по указанным правилам. Чужой алфавит или лишняя запятая
дают incorrect, а не незаметное исправление. Управляющие/форматирующие
символы Unicode Cc/Cf внутри ответа дают format_error. Пробелы в допустимом
составном эталоне остаются значимыми. `е` и `ё`, латинская `A` и кириллическая
`А`, цифра `0` и буква `О` не отождествляются.

Sequence допускает digits 0–9, latin A–Z/a–z или cyrillic А–Я/а–я/Ё/ё.
Пробелы между символами принимаются с notice `sequence_spacing`: на бланке
нужно писать подряд. Notice возвращается и при неверном ответе, если его
формат допустим. Внутренние табуляции/переводы строк, запятые, чужой алфавит
и другие разделители дают format_error. NFC допускает канонически эквивалентные
`Е` + диакритика / `Ё`, но не подменяет похожие буквы разных алфавитов.

## Типичные ошибки и текущая практика

commonMistakes нормализуются теми же правилами. Совпавшее explanation возвращается
локально; запрос ИИ не выполняется. Неподходящие по формату записи ошибок
пропускаются. При нескольких совпадениях используется первое. Правильный ответ
проверяется раньше списка ошибок, поэтому ошибочная запись списка не может
превратить верный ответ в неверный.

`src/lib/practice.ts` уже делегирует проверку новой функции, сохраняя интерфейс
текущего UI (`invalid` вместо `format_error`) и прежний лимит 32 символа после
trim. Общее ядро не задаёт лимит строки; ограничения конкретного UI/API
применяются на соответствующей границе. Новые типы заданий этот шаг не добавляет.

## Проверки

97 табличных случаев покрывают все форматы, регистр, Unicode, порядок, ведущие
нули, большие целые и отклонение недопустимого ввода. Дополнительно проверены
уведомление о пробелах, типичные ошибки, приоритет верного ответа, №11–12 и
отказ для практических артефактов.

Пять property-тестов fast-check 4.10.2 выполняют по 500 случаев с seed 20261009:
эквивалентные целые до 256 бит, сохранение последовательностей, NFC/регистр,
идемпотентность нормализации и объяснения эквивалентных ошибочных чисел.
Это devDependency из стека spec §4.1; в клиентский код она не попадает.
Команда: `npm run verify`; практика дополнительно проверяется Playwright.
