# CI и публикация

Workflow `.github/workflows/ci.yml` запускается на push в `main`, на каждый pull request и вручную
через Actions → CI and Pages → Run workflow. Node берётся из `.nvmrc`, зависимости
устанавливаются через `npm ci`, npm-кеш привязан к `package-lock.json`.
Проверки ветки выполняются в её PR: отдельный push в ту же ветку не создаёт
вторую полную матрицу и не занимает исполнителей дубликатами. Ветку без PR
можно проверить вручную через Run workflow. Каждый PR и каждое изменение `main`
по-прежнему проходят весь обязательный набор проверок.

## Что проверяется

1. Gitleaks 8.30.0: полная история Git, включая доступные ветки. Бинарник скачивается
   из официального релиза и проверяется закреплённой SHA-256. Значения секретов
   не печатаются (`--redact`).
2. `npm audit --audit-level=high`: зависимости, включая инструменты разработки.
3. Формат, ESLint, типы, forbidden, инвентарь текущего этапа и production-сборка; после build — обязательный
   offline аудит языка, терминов и формул (`node scripts/check-content.mjs`);
   отдельно — все unit-тесты в трёх группах с общим покрытием ядра ≥90%.
4. `npm run check:office`, `npm run check:robots`, `npm run check:python` и `npm run check:variants`:
   реальные офисные файлы открываются в LibreOffice, программы Робота проверяются
   независимым исполнителем, Python-эталоны реально запускаются на граничных тестах.
   Полные варианты дополнительно проверяют вложенные архивы, программы и новые ODS в Calc.
5. `npm run e2e`: Chromium, Firefox и WebKit на desktop и 360px touch — шесть
   полных профилей, вместе с ними axe. Браузеры и системные библиотеки устанавливаются
   самим workflow, поэтому результат не зависит от набора браузеров облачной среды.
   Полный набор распределён по десяти обязательным группам, без фильтрации тестов.
   После T9.5 матрица содержит 4314 сценариев, включая 54 прежние визуальные;
   360px-профили Firefox/WebKit проходят весь набор. Нажатия в сценах выбираются
   по hasTouch, новые touch-сценарии проверяют ввод, поворот и восстановление.
   Публикация требует успеха всех десяти групп с прежним 20-минутным лимитом.
   [Матрица и ограничения эмуляции](cross-browser.md), ADR-052.
   Перед системными пакетами CI выбирает официальный Ubuntu archive вместо
   нестабильного Azure-зеркала (`scripts/ci-apt-mirror.sh`, ADR-051). Подписи
   пакетов и 20-минутные лимиты заданий сохраняются; это также применяется к LibreOffice.
6. `performance`: четыре параллельных запуска `npm run lh`, по три прогона каждого
   URL с бюджетами `lighthouserc.cjs`, на Chromium той же версии Playwright.
   После T9.2 это 59 URL ×3, шесть дополнительных холодных загрузок заполненных
   результатов и 17 сценариев ×3 с INP ≤200 мс по официальному `web-vitals`.
   Каждый замер INP должен существовать и пройти порог; контрольный медленный
   ввод обязан быть отклонён. Отчёты взаимодействий находятся в подкаталоге
   `interactions/` тех же артефактов. Матрица также сверяется с исходными `.astro`:
   новый шаблон требует сценария. Подробности — [отчёт T9.2](reports/t9.2.md).
   `OGE_LH_SHARD=1`–`4` делит URL без повторов и пропусков; локально без
   переменной проверяется весь список. Порогам не передаются переопределения.
7. `npm run check:print`: отдельная обязательная группа Chromium + Poppler
   экспортирует 94 настоящих A4 PDF в 49 сценариях: шпаргалки и справочные
   версии всех 45 уроков, полный каталог, памятка и два результата.
   Проверяются текст каждого видимого блока, поля 15 мм, отсутствие пустых
   страниц и обрезанных слов; PDF и PNG сохраняются в `print-reports` на семь дней.
   Состояние страницы и печатные стили также проверяются шестью обычными профилями.
   [Печать](printing.md), ADR-053.
8. Gitleaks по готовому `dist/`; `npm run check:security` в `quality` дополнительно
   проверяет секретные маркеры во всех байтах, `.env*`, symlink и пустую сборку.
   Полный обход HTML в обеих темах также проверяет CSP, сторонние запросы и cookies.
   Заполненные результаты, Worker, печать и все пять 3D-игр проходят отдельные
   сценарии безопасности; отрицательные пробы обязаны отклоняться тем же контролем.
   Подробности — [безопасность](security.md).

При ошибке следующие шаги этого задания и публикация не выполняются; независимое
параллельное задание может закончить свои проверки. Следы упавших браузерных
тестов и видео прохождения сохраняются в `quality-reports-1`–`quality-reports-10`,
Lighthouse-отчёты — в `lighthouse-reports-1`–`lighthouse-reports-4` на семь дней,
в том числе при неуспешном прогоне. Покрытие и проверенные офисные
материалы сохраняются отдельно в `source-reports` / `generated-file-reports` на тот же срок. Значения секретов не нужно
добавлять в отчёты или сообщения workflow. Аудит текста сохраняет `report.json`,
`samples.json` и `samples.md` в `content-reports` на семь дней, включая неуспешный
запуск. [Область проверки и ограничения](content-audit.md).

## Разделение проверок и публикации

На одном коммите работают `quality` (код и безопасность), `unit` (три группы),
`files` (независимые проверки файлов), `browsers` (десять групп всех браузеров,
axe и сканирование dist) `printing` (49 проверок A4 PDF) и `performance` (четыре группы Lighthouse). `coverage` объединяет три unit-результата
и применяет общий порог ≥90%. У каждой проверки лимит 20 минут и только `contents: read`.
Они не изменяют репозиторий и настройки Pages.
Проверки fork PR работают через событие `pull_request`, без `pull_request_target`
и без секретов. Действия закреплены commit SHA.

Первая успешная группа `browsers` из `main` загружает свой проверенный `dist` через `upload-pages-artifact`.
Отдельный `deploy` с `needs: [quality, unit, coverage, files, browsers, printing, performance]` ждёт успеха всех групп,
получает только права `pages: write` и
`id-token: write`, использует environment `github-pages` и публикует именно этот
артефакт. Пользовательский PAT и запись обратно в Git не нужны.

Deploy проверяет источник Pages read-only запросом. Однократно владелец выбирает
Settings → Pages → Build and deployment → Source → GitHub Actions: служебный
GITHUB_TOKEN не имеет права менять эту настройку (подтверждено HTTP 403).
При другом источнике workflow выдаёт явное сообщение со ссылкой на настройки.
После миграции красный CI сохраняет предыдущую опубликованную версию.

Для `main` прогоны не прерываются следующим push; для остальных веток устаревший
прогон отменяется. Дополнительная группа `github-pages` не допускает двух публикаций
одновременно. Новые маршруты Astro входят в артефакт автоматически.

## Проверка того, что ошибка останавливает CI

Негативная проверка выполняется только в отдельной ветке:

1. В `src/lib/site.test.ts` временно заменить ожидаемый результат для `/` на
   `/intentional-ci-failure/` и отправить ветку.
2. Открыть черновой PR и проверить, что `verify` упал именно на этом тесте, а deploy пропущен.
3. Вернуть исходное ожидание `/test-oge-app/`, отправить исправление и дождаться
   полного зелёного CI, включая браузеры и Lighthouse.
4. Перенести в `main` только исправленное состояние. Ссылки и фактические результаты
   первого прогона записываются в `STATUS.md`.

Ошибку нельзя подтверждать отказом загрузки зависимостей, неверным YAML или другой
неисправностью среды: красный результат должен быть следствием неправильного теста.

## Диагностика

- Unit-группы явно подключают встроенный репортёр Vitest `github-actions`
  вместе с `default` и `blob`: ошибка получает название теста, сообщение и
  позицию исходника в аннотациях GitHub. Явный список default/blob иначе заменяет
  автоматический GitHub-репортёр Vitest; без него виден лишь общий код выхода.
- При красном CI открыть первый упавший шаг и его лог. Для Playwright скачать
  `quality-reports-1`–`quality-reports-10` и открыть `trace.zip` через `npx playwright show-trace`.
- Для локального воспроизведения: `npm ci`, `npm run verify`,
  `npx playwright install --with-deps chromium firefox webkit`, `npm run e2e`,
  `npm run lh` с `CHROME_PATH`, указывающим на установленный Chromium.
- При отказе изменения источника Pages проверить Settings → Pages → Source:
  GitHub Actions. Старую корневую сборку удалять только после первой успешной
  публикации артефакта (ADR-009).
- Для исправления зависимостей обновить manifest и lock-файл осознанно и повторить
  проверки. Отключение audit или понижение бюджетов не является исправлением.
- После изменения workflow выполнить actionlint; в T1.3 проверена версия 1.7.7.
  Локальный сканер: `gitleaks git --redact --no-banner --log-opts=--all` и
  `gitleaks dir dist --redact --no-banner`.

Зелёный CI проверяет уже реализованные страницы и текущую фазу покрытия. Он не
означает готовность будущих генераторов, уроков, игр или прохождение всех gate проекта.
