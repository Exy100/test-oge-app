# Задания №14: обработка электронных таблиц

Четыре генератора создают собственные учебные массивы по 240 записей и три связанных
запроса к каждому массиву. Формат ODS и максимум 3 балла сверены в
[описании экзамена](exam-format.md). Сюжеты и правила самооценки авторские,
CC0-1.0; они не выдаются за официальный рубрикатор ФИПИ.

| Подтип | Данные | Три запроса |
|---|---|---|
| sheet-filter | Кружок, класс, баллы | Количество по двум условиям; сумма; максимум баллов |
| sheet-revenue | Категория, цена, количество | Количество по категории; суммарная выручка; максимум выручки строки |
| sheet-group | Команда, два результата теста | Количество участников; средний суммарный балл; максимальный суммарный балл |
| sheet-growth | Район, значения до и после | Количество улучшений в районе; суммарный положительный прирост; максимальный прирост |

ID обозначают вымышленные записи; имена и контакты не используются. Все значения
сгенерированы из seed. Заголовки находятся в A1:D1, записи — A2:D241 на листе
«Данные». Порядок строк перемешан. Равенство порогу включается в отбор по классу;
для улучшения требуется строгое увеличение. Средний балл округляется до двух знаков
после запятой, половина округляется вверх.

Исходные A:D сохраняются. Ответы записываются в H2:H4; вспомогательный столбец E
содержит построчные формулы IF с AND, умножением, сложением или разностью.
Итоги используют COUNTIF/COUNTIFS, SUM, MAX и ROUND. Это запись OpenFormula внутри
ODS; Calc может показывать локализованные имена функций. Сохранённый результат —
редактируемая ODS с исходными данными и вычислениями.

В каждом архиве семь файлов: README, условие, исходная ODS и её UTF-8 CSV-копия,
эталонная ODS, JSON ответов/ячеек/формул и учебные критерии. Статическая CSV-копия
содержит те же строки, а не заменяет офисный файл. ODS — настоящий ODF ZIP с XML,
числовыми ячейками, OpenFormula и манифестом. Контрольные суммы вычисляются из байтов.

Самооценка 0–3: один балл за каждый верный результат при открываемой ODS и сохранённых
исходных данных; неоткрываемый или отсутствующий файл — 0. Сайт не загружает офисный
файл ученика и не выполняет автоматическую экспертную оценку.

## Экспорт

```sh
npm run --silent sample -- --task 14 --n 12 --seed review --files-dir samples/14-files > samples/14.md
npm run verify
npm run check:office
```

[Двенадцать примеров с ZIP и эталонами](../samples/14.md) чередуют четыре подтипа.
Повторный запуск с тем же seed воспроизводит задания и файлы. В служебной галерее
генераторов можно создать набор и скачать его в браузере. Публичное рабочее место,
уроки и интерактивная диаграмма подключаются на следующих этапах плана.

## Проверки

Каждый подтип проходит общий харнесс на 500 различных seed: схема, повторяемость
задачи, исходные ячейки ODS, независимые расчёты, формулы, диапазоны и SHA-256.
На подтип сохранены три золотых снимка задач и манифестов; повторный экспорт
проверяется по байтам. Все 12 примеров воспроизводятся отдельными тестами.
Изменённые условия, ссылка на эталон, критерии и идентичность набора отвергаются.
Генераторы также участвуют в общей проверке одинаковых задач в Node, Workers и браузерах.

`check-spreadsheets.py` независимо решает задачи по CSV и проверяет ZIP/CRC/хеши.
Затем открывает 12 исходников и 12 эталонов в Calc. Перед открытием копии эталона
из неё удаляются все сохранённые результаты формул: ответ обязан вычислить Calc.
Проверяются все исходные ячейки и 36 результатов после пересчёта 2916 формул.
Обработка идёт пакетами по четыре файла с изолированным профилем. CSV после Calc
и проверяемые ODS сохраняются в `.cache/spreadsheet-office/`, артефакт quality-reports.
