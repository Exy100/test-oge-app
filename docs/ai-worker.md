# Локальный API — HTTP-граница и пересборка заданий

T6.1–T6.3 доступны без аккаунта и ключа. HTTP-граница проверяет вход и сама
пересобирает задачу по реестру ядра, не доверяя клиентскому эталону.
Сервер не обращается к ИИ. Опубликованный сайт продолжает показывать локальные
примеры T6.0. GitHub Pages серверный Worker не исполняет.

## Запуск

Нужны Node/npm из README и установленные зависимости:

```bash
npm ci
npm run worker:dev
```

Wrangler запускает локальный runtime на `http://127.0.0.1:8787`.
В другом терминале:

```bash
curl -i http://127.0.0.1:8787/api/ai/health \
  -H 'Origin: https://exy100.github.io'
curl -i http://127.0.0.1:8787/api/ai/stream-feedback \
  -H 'Origin: https://exy100.github.io' \
  -H 'Content-Type: application/json' \
  --data '{"generatorId":"numeral-sum-v2","seed":"local-check","answer":"12"}'
```

Первый запрос возвращает 200 и `{"enabled":false}`; второй — 503 с кодом
`ai-disabled`. Это ожидаемое отключённое состояние. `SITE_ORIGIN` в конфигурации
равен известному origin сайта; заголовок в примерах нужен, поскольку адрес
локального сервера имеет другой origin. CORS не открывается, браузерный сайт
не переключается на этот сервер. Для собственного локального origin можно
передать Wrangler `--var SITE_ORIGIN:http://127.0.0.1:4321`.

Остановка сервера — Ctrl+C. Облачное развёртывание команда не выполняет.

## Контракты и ошибки

| Маршрут | Метод и допустимый вход |
| --- | --- |
| `/api/ai/health` | GET; реальное состояние `enabled: false` |
| `/api/ai/stream-feedback` | POST; прежний строгий контракт generatorId, seed, answer ≤300, reasoning ≤1500 |
| `/api/ai/part2-grade` | POST; generatorId + seed либо bankId + необязательный seed, solution ≤3000, необязательный criteriaAnswers |
| `/api/ai/variant-summary` | POST; variantSeed, results `{n, score, timeSec}` и part2Self `{n, score}` |

Формы и ограничения уточнены в spec §11.3. Неизвестные поля, повторы номеров,
баллы сверх максимума и тексты ответов в сводке отклоняются. `null` в самооценке
остаётся отсутствием оценки. T6.2 проверяет существование generatorId/bankId,
версию, seed кураторского набора и соответствие режиму. Тексты ответов
на критерии остаются входом ученика; их содержательная проверка — T6.8.

bankId — полный id задачи, например `curated-presentations-v2:P01` или
`curated-documents-v2:D01`. Короткий `P01` не задаёт версию и отклоняется.
Для кураторской карточки допустимы также generatorId версии и seed набора;
при bankId необязательный seed должен совпадать с выбранным набором.
Краткий ответ относится только к №1–12. Офисные работы №13–14 получают
контекст помощи по критериям со score null; Робот и программа — контекст
предварительной оценки максимум на 2. Это выбор режима будущего запроса,
а не оценивание работы. Пользовательский код не исполняется.

Задача собирается существующим генератором, проверяется TaskInstanceSchema
и verify; эталон и критерии берутся с сервера. Краткий ответ проверяется
checkTaskAnswer. Эти данные не возвращаются диагностическим HTTP-ответом:
валидная подготовка по-прежнему завершается 503 ai-disabled. Неизвестный id,
старая версия, несовместимый режим и неверный формат ответа дают 400;
сбой внутренней проверки — безопасный 500 без деталей ядра.

Чужой/отсутствующий Origin у POST даёт 403; неверный метод — 405 с Allow;
неизвестный путь — 404; неподдерживаемый Content-Type/сжатие — 415;
неверный JSON/UTF-8/контракт — 400; размер свыше 8192 байт — 413.
Content-Length не заменяет подсчёт фактических байтов потока. На границе
поток отменяется; тело не читается целиком в неограниченный буфер.

Ошибки не отражают входные тексты или детали парсера; обработчик не логирует
IP, заголовки или тела запросов. Локальная консоль Wrangler показывает методы,
пути и статусы без содержимого работы ученика.
Все ответы имеют no-store, CSP, nosniff, защиту от встраивания, HSTS,
COOP same-origin, ограничения Permissions-Policy (включая платежи) и Referrer-Policy.
Observability в конфигурации выключена. Cookies и разрешающих CORS
заголовков нет. GET health без Origin допустим только при совпадении
origin адреса запроса с настройкой сайта.

## Сборка и проверка

После подготовки задания HTTP вызывает `worker/src/prompts/index.ts`.
Три шаблона имеют версии `stream-feedback/v1`, `part2-grade/v1`,
`variant-summary/v1`. System содержит правила и выбранные поля серверной задачи:
условие, рисунок, эталон/решение, критерии и разрешённый режим или вердикт.
Краткий ответ/черновик, решение и ключи/значения ответов по критериям находятся
в единственном user-сообщении как JSON внутри `<student_input>`.
Символы `&`, `<`, `>` экранируются; закрывающий тег из ввода не создаёт новое сообщение.
Seed, id, datasetId и referenceId не передаются модели даже после пересборки.
Сводка получает только агрегаты, сохраняя null; список доступных токенов уроков
построен из существующего каталога опубликованных материалов, фильтры — №1–16.

Промпты сейчас только собираются в памяти: HTTP не возвращает их, health false
и 503 сохраняются. Проверки структуры не доказывают устойчивость реальной
модели к инструкциям ученика; ответы и баллы модели ещё не принимаются.

```bash
npm run worker:check
npx vitest run tests/unit/ai-worker.test.ts
npx vitest run tests/unit/ai-reconstruction.test.ts tests/unit/ai-reconstruction-failure.test.ts
npx vitest run tests/unit/ai-prompts.test.ts
```

Wrangler `deploy --dry-run` собирает код в `.cache/ai-worker` без публикации.
Побайтовая проверка сканирует JS и source map на секретные маркеры.
CI дополнительно проверяет их Gitleaks и сохраняет артефакт `worker-bundle`;
обычные типы/lint/forbidden охватывают `worker/src`. Unit-тесты проверяют
контракты в Node и запускают настоящий модуль в Workers через Miniflare.

## Внешнее подключение

T6.4–T6.10 остаются открытыми. До настоящих запросов нужны
OpenRouter, ограничения и бюджет, согласие пользователя,
проверки ответов и деградация. Владелец должен выбрать модели, бюджет,
серверный домен и размещение Worker. Ключ вводится только как серверный секрет.
Локальные T6.1–T6.3 не закрывают развёртывание и Gate 6; ADR-001/059/060/061 действуют.
