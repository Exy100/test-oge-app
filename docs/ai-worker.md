# Локальный API — HTTP-граница и пересборка заданий

T6.1–T6.5 доступны без аккаунта и ключа. HTTP-граница проверяет вход и сама
пересобирает задачу по реестру ядра, не доверяя клиентскому эталону.
Сервер не обращается к ИИ. Опубликованный сайт продолжает показывать локальные
примеры T6.0. GitHub Pages серверный Worker не исполняет.

## Запуск

Нужны Node/npm из README и установленные зависимости:

```bash
npm ci
npm run worker:dev
```

Wrangler запускает локальный runtime на `http://127.0.0.1:8787`.
В другом терминале:

```bash
curl -i http://127.0.0.1:8787/api/ai/health \
  -H 'Origin: https://exy100.github.io'
curl -i http://127.0.0.1:8787/api/ai/stream-feedback \
  -H 'Origin: https://exy100.github.io' \
  -H 'Content-Type: application/json' \
  --data '{"generatorId":"numeral-sum-v2","seed":"local-check","answer":"12"}'
```

Первый запрос возвращает 200 и `{"enabled":false}`; второй — 503 с кодом
`ai-disabled`. Это ожидаемое отключённое состояние. `SITE_ORIGIN` в конфигурации
равен известному origin сайта; заголовок в примерах нужен, поскольку адрес
локального сервера имеет другой origin. CORS не открывается, браузерный сайт
не переключается на этот сервер. Для собственного локального origin можно
передать Wrangler `--var SITE_ORIGIN:http://127.0.0.1:4321`.

Остановка сервера — Ctrl+C. Облачное развёртывание команда не выполняет.

## Контракты и ошибки

| Маршрут | Метод и допустимый вход |
| --- | --- |
| `/api/ai/health` | GET; реальное состояние `enabled: false` |
| `/api/ai/stream-feedback` | POST; прежний строгий контракт generatorId, seed, answer ≤300, reasoning ≤1500 |
| `/api/ai/part2-grade` | POST; generatorId + seed либо bankId + необязательный seed, solution ≤3000, необязательный criteriaAnswers |
| `/api/ai/variant-summary` | POST; variantSeed, results `{n, score, timeSec}` и part2Self `{n, score}` |

Формы и ограничения уточнены в spec §11.3. Неизвестные поля, повторы номеров,
баллы сверх максимума и тексты ответов в сводке отклоняются. `null` в самооценке
остаётся отсутствием оценки. T6.2 проверяет существование generatorId/bankId,
версию, seed кураторского набора и соответствие режиму. Тексты ответов
на критерии остаются входом ученика; их содержательная проверка — T6.8.

bankId — полный id задачи, например `curated-presentations-v2:P01` или
`curated-documents-v2:D01`. Короткий `P01` не задаёт версию и отклоняется.
Для кураторской карточки допустимы также generatorId версии и seed набора;
при bankId необязательный seed должен совпадать с выбранным набором.
Краткий ответ относится только к №1–12. Офисные работы №13–14 получают
контекст помощи по критериям со score null; Робот и программа — контекст
предварительной оценки максимум на 2. Это выбор режима будущего запроса,
а не оценивание работы. Пользовательский код не исполняется.

Задача собирается существующим генератором, проверяется TaskInstanceSchema
и verify; эталон и критерии берутся с сервера. Краткий ответ проверяется
checkTaskAnswer. Эти данные не возвращаются диагностическим HTTP-ответом:
валидная подготовка по-прежнему завершается 503 ai-disabled. Неизвестный id,
старая версия, несовместимый режим и неверный формат ответа дают 400;
сбой внутренней проверки — безопасный 500 без деталей ядра.

Чужой/отсутствующий Origin у POST даёт 403; неверный метод — 405 с Allow;
неизвестный путь — 404; неподдерживаемый Content-Type/сжатие — 415;
неверный JSON/UTF-8/контракт — 400; размер свыше 8192 байт — 413.
Content-Length не заменяет подсчёт фактических байтов потока. На границе
поток отменяется; тело не читается целиком в неограниченный буфер.

Ошибки не отражают входные тексты или детали парсера; обработчик не логирует
IP, заголовки или тела запросов. Локальная консоль Wrangler показывает методы,
пути и статусы без содержимого работы ученика.
Все ответы имеют no-store, CSP, nosniff, защиту от встраивания, HSTS,
COOP same-origin, ограничения Permissions-Policy (включая платежи) и Referrer-Policy.
Observability в конфигурации выключена. Cookies и разрешающих CORS
заголовков нет. GET health без Origin допустим только при совпадении
origin адреса запроса с настройкой сайта.

## Сборка и проверка

После подготовки задания HTTP вызывает `worker/src/prompts/index.ts`.
Три шаблона имеют версии `stream-feedback/v1`, `part2-grade/v1`,
`variant-summary/v1`. System содержит правила и выбранные поля серверной задачи:
условие, рисунок, эталон/решение, критерии и разрешённый режим или вердикт.
Краткий ответ/черновик, решение и ключи/значения ответов по критериям находятся
в единственном user-сообщении как JSON внутри `<student_input>`.
Символы `&`, `<`, `>` экранируются; закрывающий тег из ввода не создаёт новое сообщение.
Seed, id, datasetId и referenceId не передаются модели даже после пересборки.
Сводка получает только агрегаты, сохраняя null; список доступных токенов уроков
построен из существующего каталога опубликованных материалов, фильтры — №1–16.

Промпты сейчас только собираются в памяти: HTTP не возвращает их, health false
и 503 сохраняются. Проверки структуры не доказывают устойчивость реальной
модели к инструкциям ученика; ответы и баллы модели ещё не принимаются.

```bash
npm run worker:check
npx vitest run tests/unit/ai-worker.test.ts
npx vitest run tests/unit/ai-reconstruction.test.ts tests/unit/ai-reconstruction-failure.test.ts
npx vitest run tests/unit/ai-prompts.test.ts
npx vitest run tests/unit/openrouter.test.ts tests/unit/openrouter-runtime.test.ts
npx vitest run tests/unit/ai-limits.test.ts tests/unit/ai-limits-runtime.test.ts
```

Wrangler `deploy --dry-run` собирает код в `.cache/ai-worker` без публикации.
Побайтовая проверка сканирует JS и source map на секретные маркеры.
CI дополнительно проверяет их Gitleaks и сохраняет артефакт `worker-bundle`;
обычные типы/lint/forbidden охватывают `worker/src`. Unit-тесты проверяют
контракты в Node и запускают настоящий модуль в Workers через Miniflare.

## Транспорт OpenRouter

`worker/src/openrouter.ts` принимает серверные OPENROUTER_API_KEY,
AI_MODEL_PRIMARY, AI_MODEL_FALLBACK и SITE_ORIGIN; модель из тела запроса не
принимается. Выбранных владельцем моделей в коде нет. Подстановка fetch позволяет
проверить транспорт без регистрации, настоящего ключа и исходящего обращения.
`createWorker(client)` использует ту же HTTP-границу, пересборку и промпты.
Начиная с T6.5 default — `createConfiguredWorker()`: при AI_ENABLED=false
использует отключённую границу, при точном true требует всю конфигурацию,
добавляет IP-лимит и разрешение бюджета перед каждым исходящим обращением.
`createWorker(client)` без защиты остаётся только внутренней фабрикой для
изолированных тестов транспорта; публичный default её без защиты не включает.

Общий дедлайн 30 секунд включает заголовки и тело всех попыток. Максимум два
запроса: основной и резервный после 429/5xx или невалидного JSON/оценки.
Стрим после начала не повторяется. Сетевые ошибки, таймаут и отмена не запускают
новую попытку. Поток клиента получает только текстовые delta и DONE; метаданные
и сообщения об ошибках провайдера скрыты. Ошибка стрима завершается безопасным
event error без DONE. Начатый текст не выдаётся за полный разбор.

JSON возвращается после строгой проверки полей и серверного assessment:
офис criteria-help/null, Робот и программа preliminary/0–2. После второго
неуспеха — ошибка, без искусственного балла. Все запросы имеют
provider.data_collection deny, temperature 0.3, max_tokens 700/500/1200,
атрибуцию сайта и фиксированный URL без перенаправлений. Тела ограничены 1 MiB,
кадры 65 536 символов, текст 12 000 символов; чтение не буферизует весь SSE.

При отмене request.signal или тела ответа транспорт отменяет исходящий сигнал,
освобождает чтение и таймер. enable_request_signal включён явно: у этого флага
нет даты автоматического включения в workerd. Unit-тесты используют native
AbortSignal и ReadableStream; в настоящем Workers runtime проверены оба вида
отмены внутри Worker с тестовым провайдером.

Сквозная TCP-проверка через локальный HTTP-мост Miniflare не подтвердила передачу
внешнего отключения. Это не считается успешным тестом. Реальный браузер →
preview Worker → OpenRouter, включая прекращение запроса при разрыве клиента,
ещё НЕ ПРОВЕРЕН: внешнего Worker и ключа нет. Это отдельная проверка T6.10.

## Лимиты и флаг включения

В `worker/wrangler.toml` зафиксированы AI_ENABLED="false" и
AI_DAILY_REQUEST_LIMIT="0". Ни ключа, ни HMAC-секрета в файле нет.
Настоящее включение не выполнялось. `createConfiguredWorker(testFetch)`
позволяет проверить тот же обработчик на частном провайдере без обращения к API.

Для включённого обработчика нужны серверные значения:

| Настройка | Назначение |
| --- | --- |
| AI_ENABLED | Только строка `true` включает клиент; всё остальное выключает |
| AI_DAILY_REQUEST_LIMIT | Целое 1–1 000 000, общий предел обращений к провайдеру за UTC-день |
| AI_QUOTA | Namespace SQLite Durable Object, класс AiQuota, объект global-v1 |
| AI_IP_HMAC_SECRET | Отдельный случайный секрет ≥32 символов, только секрет Worker |
| OPENROUTER_API_KEY | Ключ с денежным лимитом на стороне OpenRouter |
| AI_MODEL_PRIMARY / AI_MODEL_FALLBACK | Две разные модели, выбирает владелец |
| SITE_ORIGIN | Точный HTTPS origin сайта |

Нет настройки/ключа/namespace → health false и безопасный 503 configuration.
Health true означает корректную включённую конфигурацию, а не проверку
доступности провайдера/DO или остатка бюджета. Health не списывает разрешения.
Ошибки хранилища, его повреждение или неподтверждённое разрешение → 503 limits;
провайдер не вызывается. Ключ и модели не принимаются из пользовательского ввода.

IP берётся только из CF-Connecting-IP после доверенного Cloudflare edge.
Прямое размещение за иным прокси требует отдельной проверки доверенной границы;
X-Forwarded-For не используется. IPv6 нормализуется, mapped IPv4 совпадает с IPv4.
Нет корректного IP → 503 limits. В DO отправляется только HMAC-SHA-256(IP),
без тела запроса, сырых адресов и HMAC-секрета. Логи обработчика пусты;
observability выключен. Не включать внешнее логирование IP/тел при размещении.

Окна скользящие: 10 запросов за 60 секунд, 60 за 24 часа. Они общие для
трёх POST-режимов. Проверенные Origin/метод/медиа допускают к лимитеру;
неверные JSON/поля тоже расходуют IP-окно, но не бюджет провайдера.
За общим IP ученики делят лимит. Отказ → 429 rate-minute/rate-day и Retry-After
в секундах. Повтор после отказа не продлевает окно хранения. Для каждого
идентификатора сохраняется ≤60 времён; alarm удаляет просроченные записи
без возвращения ученика. Физическое удаление выполняется при доставке alarm;
платформа может доставить его позже времени окна.

Счётчик бюджета увеличивается в транзакции перед **каждым** исходящим fetch.
Резервная модель и повтор невалидного JSON требуют второго разрешения, но
не второго IP-запроса. Ошибки, таймауты и отмены не возвращают счётчик:
обращение могло уже стать платным. Отказ → 503 budget с Retry-After до полуночи UTC.
Лимит считает обращения, а не токены/деньги; обязательный лимит кредитов
OpenRouter остаётся последней границей. Изменение числа в env и пересоздание
Worker/DO не обнуляют число использованных разрешений.

SQLite-миграция v1-ai-quota объявлена, но внешне не применялась. При размещении
сохранять namespace и имя global-v1: создание нового счётчика сбросит историю.
Ротация HMAC-секрета меняет идентификаторы IP и обнуляет их окна, но не бюджет;
выполнять при выключенном ИИ с паузой 24 часа, если нужно сохранить гарантию
суточного IP-лимита. Реальная ротация/размещение описываются в T6.10.

Тесты проверяют границы окон, 61-й запрос, UTC-сброс, параллельные обращения,
fallback/невалидный JSON, отсутствие IP/секретов в storage/логах/провайдере,
alarm, сбой/повреждение хранилища и отмену/дедлайн. Отдельно настоящий workerd
с SQLite DO проверяет конкуренцию, общие режимы и сохранение обоих лимитов
после принудительного eviction. Прохождение этих тестов не заменяет preview.

## Внешнее подключение

T6.6–T6.10 остаются открытыми. До настоящих запросов нужны
выбор бюджета и моделей, согласие пользователя,
проверки ответов и деградация. Владелец должен выбрать модели, бюджет,
серверный домен и размещение Worker. Ключ вводится только как серверный секрет.
Локальные T6.1–T6.5 не закрывают развёртывание и Gate 6;
ADR-001/059/060/061/062/063 действуют.
