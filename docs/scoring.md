# Подсчёт баллов T2.5

`src/core/scoring/index.ts` экспортирует `scoreVariant`, `gradeForScore`,
`VariantResponsesSchema` и типы результата. Это ядро для будущего экрана
результатов; сам экран и сохранение попыток относятся к последующим шагам.

## Вход и проверка

`scoreVariant(variant, responses)` принимает неизвестные данные и разбирает
их через VariantSchema и VariantResponsesSchema. Responses содержит:

- answers: массив `{ taskId, answer }` для кратких ответов;
- practice: массив PracticeEvidence для №13–16.

Оба массива обязательны, но могут быть пустыми. Неизвестные поля, дубли taskId,
несуществующие задания, краткий ответ на артефакт или практика на короткий ответ
отклоняются. Вид работы обязан соответствовать заданию и выбранной ветке №13.
Старая оценка презентации после выбора документа вызывает отказ, а не молча
переносится на новую ветку. Баллы ограничивает уже существующая схема практики.

Краткие ответы перепроверяются через checker T2.4: передать готовый verdict
или балл вместо ответа нельзя. №11–12 проверяются так же, как №1–10, хотя
относятся ко второй части. Правильный ответ даёт 1, остальные — 0.
Отсутствующий/пустой ответ в итоговом срезе даёт 0 и answered false;
format_error сохраняет counted false. Подсчёт баллов не изменяет статистику
попыток и не превращает ошибку формата в засчитанную тренировочную попытку.

## Практика и происхождение оценки

Приоритет: явно принятая assessment → selfAssessment → отсутствие оценки.
Ноль обрабатывается как оценка, а не как пустое значение.
Принятое предложение ИИ может заменить самооценку; сохраняются и принятый
score/source, и прежняя selfAssessment. Если прежней самооценки не было,
явное принятие предложения также даёт оценку с source aiAccepted.
Офисные работы не принимают aiAccepted согласно существующей схеме §11.6.

Текст программы, ответы по критериям и даже успешный локальный запуск сами
по себе баллов не дают. Принятие ИИ означает выбор пользователя в будущем UI;
схема данных не доказывает правильность предложения. Практические баллы
в тренажёре не называются официальной экспертной оценкой.

## Результат

- rows: 16 строк по номеру, maxScore, score, результат автопроверки либо
  вид артефакта и происхождение оценки. У неоценённой практики score/source null.
- knownScore: сумма уже определённых баллов.
- pendingTaskNumbers: номера практических работ без оценки.
- possibleScore: минимум knownScore, максимум с добавлением максимумов только
  неоценённых работ. Краткие ответы считаются уже завершённым срезом, их нулевые
  баллы не расширяют этот диапазон.
- complete true: primaryScore и ориентировочная grade заполнены.
- complete false: primaryScore и grade равны null, даже если нижней границы
  уже хватило бы на некоторую отметку. Отсутствующая оценка не заменяется нулём.
- format и grading: независимые годы, статусы, источник и пояснение из конфига.
  Формат — проект 2027, шкала — рекомендации 2026 с ограничениями применимости.
- practiceNotice: официальные баллы практических работ выставляют эксперты.

Максимум 21, №14 допускает 3 балла, остальные практические работы — 2.
№13 всегда один номер независимо от ветки. Входные данные не изменяются;
строки результата сортируются по номеру.

`gradeForScore` — чистый поиск по шкале конфига. Принимает только целые 0–21,
отклоняет дроби, NaN/Infinity и отрицательный ноль. При отображении отметки
следует использовать вместе с ней метаданные grading из результата.

## Проверки

49 тестов нового модуля: все 22 первичных балла и границы 4/5, 10/11, 16/17,
недопустимые баллы, неполная практика, принятые оценки ИИ и явный ноль,
обе ветки №13, максимум №14, компьютерные краткие ответы, неизвестные/повторные
записи, подмена вердикта, сортировка и отсутствие мутаций.
Команда проверки: `npm run verify`.
