# RichText T2.6

`src/core/rich-text/render.ts` — общий рендерер Markdown → KaTeX → DOMPurify.
`src/components/RichText.astro` формирует HTML при сборке;
`src/components/RichText.tsx` поддерживает серверный React и обновление в браузере.
Формула объёма текста на главной уже использует Astro-компонент.

Поддерживаются абзацы, заголовки, списки, цитаты, выделение, код и Markdown-таблицы.
Исходный HTML экранируется через markdown-it `html: false`. Ссылки превращаются
в текст, изображения — в текст альтернативного описания. Активные ссылки,
картинки, формы, скрипты, SVG, inline style и опасные атрибуты удаляет DOMPurify.
Это политика содержимого RichText; навигация самого сайта остаётся обычной.

Формулы записываются `$...$` или `$$...$$`, в том числе многострочные без пустых
абзацев. Литерал доллара экранируется `\$`. В inline-коде и блоках кода формулы
не разбираются. Ошибка формулы показывает её экранированный исходник с пояснением,
остальная разметка продолжает отображаться.

KaTeX: trust false, strict warn, throwOnError true, maxExpand 1000, maxSize 20.
Выбран output mathml: нативное отображение браузером, семантические дроби/степени
и доступная разметка без исключений для inline CSS в CSP. HTML-позиционирование
KaTeX и его шрифты не требуются. Совместимость проверяется текущими проектами
Playwright, включая WebKit и Firefox в CI.

Стили используют токены проекта; таблицы и длинный код прокручиваются внутри
своего блока. Кнопка копирования появляется только для блоков кода и переносит
их текст в буфер, разделяя несколько блоков пустой строкой. Код не исполняется.
Без JavaScript серверное содержимое остаётся читаемым; копирование не предлагается.
Отказ или отсутствие Clipboard API дают инструкцию выделить код вручную.
Результат копирования сообщается через live region.

Служебная `/dev/rich-text/` существует только в режиме dev: редактор проверяет
React-рендер, рядом размещён статичный пример для проверки серверного копирования.
В production остаются четыре страницы.

Использованы markdown-it 15.0.2, KaTeX 0.19.0 и isomorphic-dompurify 4.5.0.
Последний выбирает DOMPurify браузера либо DOMPurify с jsdom на сервере Node;
серверная зависимость не импортируется в браузерный вариант пакета. Эта обёртка
описана в ADR-019. Рендерер не заявляет поддержку исполнения внутри Worker;
будущий Worker отдаёт текст ответа, который отображает клиент.

Проверки: 14 вредоносных строк (HTML, атрибуты событий, ссылки, вложенная разметка,
опасные команды KaTeX и код), таблицы, MathML, неверная формула, экранирование
доллара, React SSR. Браузеры проверяют ввод этих строк, отсутствие активных
элементов/выполнения маркера, копирование, отказ Clipboard, обе темы с axe и
формулу на production-странице без JavaScript. Команды: npm run verify и npm run e2e.
