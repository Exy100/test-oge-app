# Развёртывание сайта и ИИ

Текущее размещение: GitHub Pages, локальное демо, исходящих обращений к модели
нет. Pages не выполняет Worker. По запросу владельца 2026-11-04 подготовлен
RouterAI с основной `openai/gpt-6-luna` и резервной
`anthropic/claude-sonnet-5.5`. `anthropic/claude-opus-5.5` — вариант замены,
а не третья автоматическая попытка. Флаг включения остаётся false.
Каталог RouterAI подтвердил все три ID. Живая локальная проверка 2026-11-04
подтвердила ответы Luna во всех трёх режимах приложения и ответ Sonnet через
настоящий Worker. [Результаты и ограничения](reports/routerai-live-2026-11-04.md).
Opus также проверен: четыре случая не приняты при действующих лимитах
(обрывы SSE, таймаут или ответ резервной Sonnet; ошибка числа заданий в сводке).
Он пока не является рабочей заменой основной пары. Внешний сервис ещё не размещён.

## Проверка на своём компьютере без домена и Cloudflare

В корне проекта после `npm ci`:

```bash
npm run ai:local
```

Команда запросит ключ RouterAI скрытым вводом в терминале.
Не передавайте ключ в чат, аргументы команды или файлы проекта. Для серверной
среды также поддерживается заранее настроенный секрет `ROUTERAI_API_KEY`.
Ключ передаётся только локальному Worker в памяти процесса, не помещается
в vars репозитория и не доступен браузеру. Для подтверждённого владельцем
технического прогона использован его выделенный тестовый ключ.

Приложение открывается на `https://127.0.0.1:4328/test-oge-app/`.
Для локального тестового сертификата браузер может показать предупреждение;
это исключение относится только к своему loopback-адресу. API проксируется
на локальный Worker, работающий на 127.0.0.1:8788. Обе службы слушают только
loopback; размещения в интернете команда не выполняет. Остановка — Ctrl+C.

Старт не вызывает модель. В потоке проверь ответ, нажми «Получить разбор с ИИ»,
проверь имя RouterAI и отправляемые данные, затем разреши отправку. После этого
запрос платный. Пройди [сценарии Gate 6](reviews/phase-6.md), включая практику
и сводку варианта. Не используй личные данные детей для технической проверки.

Для запуска без ключа и без внешних запросов:

```bash
npm run ai:local -- --disabled
```

Для воспроизводимой автоматической проверки локального запуска:

```bash
npm run ai:check
```

Нужен установленный Chromium для Playwright. Проверка сама запускает приложение
и настоящий Worker в отключённом режиме, выполняет шесть сценариев desktop/mobile,
не подменяет HTTP-ответы и не обращается к модели. Если используется системный
Chromium, задай PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH с его полным путём.

Кнопка разбора объяснит, что ИИ выключен; обычная проверка ответов работает.
Счётчики локального Worker сохраняются в `.cache/ai-local/`. Лимит 600 и
ограничения IP действуют и здесь. При отсутствии заданного серверного
`AI_IP_HMAC_SECRET` локальный запуск создаёт новый секрет в памяти; перезапуск
меняет IP-идентификатор, но сохраняет дневной счётчик. Это локальный тестовый
режим, не конфигурация публичного сервиса и не проверка внешнего TCP-разрыва.

## Различия RouterAI и OpenRouter

`AI_PROVIDER=routerai` выбирает только фиксированный
`https://routerai.ru/api/v1/chat/completions` и секрет `ROUTERAI_API_KEY`.
`AI_PROVIDER=openrouter` выбирает прежний адрес и `OPENROUTER_API_KEY`.
При отсутствующем AI_PROVIDER сохраняется OpenRouter для совместимости;
неизвестное значение или отсутствие ключа выбранного сервиса выключает API.
Ключи разных сервисов не подменяют друг друга.

Клиентская сборка должна использовать соответствующий
`PUBLIC_AI_PROVIDER=routerai` или `openrouter`. Имя сервиса показано в согласии
и политике конфиденциальности. У RouterAI новая policy `routerai-feedback-v1`:
согласие OpenRouter не разрешает отправку RouterAI; кэши также разделены.
Заголовок X-AI-Provider связывает запрос с сервисом, названным клиентом;
несовпадение даёт 409 до лимитера и запроса к провайдеру. POST RouterAI без
заголовка также отклоняется. Заголовок не выбирает серверный адрес.

Транспорт сохраняет SSE/JSON, пределы, дедлайн, два обращения максимум и
проверку оценки. Для RouterAI temperature не отправляется: каталог выбранных
моделей не указывает этот параметр среди поддерживаемых. Для OpenRouter
сохранено 0.3. Отправляется `provider.data_collection=deny`, но документация
RouterAI не подтверждает поддержку этого параметра: отсутствие хранения,
обучения и маршрутизация только к подходящим провайдерам НЕ ПОДТВЕРЖДЕНЫ.
Проверь условия сервиса перед отправкой реальных учебных данных; совместимость
с форматом OpenAI API сама по себе этого не доказывает.

Источники: [Chat Completions](https://routerai.ru/docs/guides),
[маршрутизация](https://routerai.ru/docs/guides/overview/provider-selection),
[конфиденциальность](https://routerai.ru/terms/privacy).

Локальный production Worker исполняется в Miniflare. Для облачной среды его
исходящие запросы проходят через Node fetch с унаследованными прокси и CA;
прямой доступ к внешней сети не требуется. Разрешён только endpoint RouterAI,
модели и лимиты берутся из того же worker/wrangler.toml. Хранилище SQLite
остаётся в .cache/ai-local/v3. Нативный fetch Worker использует redirect=manual
с отказом при 3xx: режим error в Workers не поддерживается. Node-мост использует
поддерживаемый им redirect=error. Ни один слой не следует перенаправлениям.

Внешний preview, денежный лимит ключа, отключение внешнего
TCP-потока и alarms размещённого Durable Object остаются НЕ ПРОВЕРЕНЫ.
Для публичного размещения нужны домен и Cloudflare; локальная проверка выше
этих ресурсов не требует.

## Где менять настройки

Основное место — [worker/wrangler.toml](../worker/wrangler.toml), раздел vars.

| Настройка | Сейчас | Как менять |
| --- | --- | --- |
| AI_ENABLED | false | Включать true после проверки настроек, секретов и preview |
| AI_DAILY_REQUEST_LIMIT | 600 | Общее число обращений к провайдеру за UTC-день, целое 1–1000000 |
| AI_PROVIDER | routerai | routerai или openrouter; адреса фиксированы сервером |
| AI_MODEL_PRIMARY | openai/gpt-6-luna | Точный ID основной модели выбранного сервиса |
| AI_MODEL_FALLBACK | anthropic/claude-sonnet-5.5 | Точный ID другой резервной модели |
| SITE_ORIGIN | https://exy100.github.io | HTTPS origin настоящего сайта без пути и завершающего / |

Имена моделей взяты из примеров владельца и найдены в публичном каталоге;
доступ тестового ключа к Luna и Sonnet подтверждён живыми ответами.
С пустой/неверной конфигурацией health остаётся false даже при AI_ENABLED=true.
Смена модели/лимита требует публикации Worker. Это серверные параметры;
ученический экран настроек не может менять расходы или модели.
После размещения их также можно менять в Cloudflare Dashboard → Worker →
Settings → Variables and Secrets (тип Text). Секреты имеют тип Secret.
Следующий deploy из репозитория снова применит vars из файла: сохраняйте
изменения и там, чтобы не потерять выбранные значения.

Клиент включается отдельной **публичной** переменной сборки PUBLIC_AI_MODE=api;
для текущего сервиса также нужна PUBLIC_AI_PROVIDER=routerai.
Без неё используется демо. Это не секрет и не адрес провайдера. Новый origin
сайта также задаётся в [src/lib/site.ts](../src/lib/site.ts); при переезде
сохраните существующий base /test-oge-app/, пока отдельно не проверены все URL.

## Расчёт на 10 учеников в сутки

Плановая нагрузка: 10 учеников × 30 действий ИИ = 300 ученических запросов.
Каждый допускает максимум две попытки провайдера, включая резервную модель
или исправление JSON. Поэтому задан предел **600 попыток/UTC-день**. Ошибка
провайдера тоже расходует попытку; кэш завершённых ответов снижает нагрузку.
Это ориентир для десяти учеников, а не подсчёт людей: регистрации нет.
Действующие ограничения по IP — 10/минуту, 60/скользящие сутки; общий школьный
NAT делит их между учениками. Увеличение нагрузки меняется здесь, не в клиенте.

600 запросов не равны фиксированной сумме денег. Стоимость зависит от обеих
моделей и числа входных/выходных токенов. Максимум ответа: 700/500/1200 токенов
для разбора/практики/сводки; вход тоже платный. После выбора моделей рассчитайте
стоимость каждой попытки по их актуальным тарифам и задайте денежный предел
отдельного ключа выбранного сервиса, желательно с дневным сбросом. Серверный счётчик
и денежный предел ключа нужны одновременно; повтор и неуспех не возвращают квоту.

## Подготовка аккаунта и секретов

1. В RouterAI создайте отдельный ключ для этого сервиса с ограничением
   расходов. Проверьте возможности денежного лимита ключа, логирование,
   обучение и сроки хранения у сервиса и провайдеров моделей. Поддержка
   защитного provider.data_collection=deny у RouterAI не подтверждена.
   Если денежный предел ключа или необходимые условия обработки недоступны,
   публичное включение по требованиям проекта не считается проверенным.
   Для OpenRouter действуют его настройки приватности и лимит кредитов.
2. Выберите две разные модели, доступные с этими ограничениями. Основная и
   резервная должны поддерживать SSE и корректный JSON-ответ для практики.
   Впишите их ID в vars, оставив AI_ENABLED=false.
3. Создайте Cloudflare Worker с доступом к SQLite Durable Objects. Привязка
   AI_QUOTA и миграция v1-ai-quota уже в конфигурации. Нельзя удалять миграцию
   или заменять атомарный лимитер локальным счётчиком.
4. Передавайте секреты через Cloudflare Dashboard → Variables and Secrets,
   тип Secret, или интерактивно из терминала:

```bash
npx wrangler secret put ROUTERAI_API_KEY --config worker/wrangler.toml
npx wrangler secret put AI_IP_HMAC_SECRET --config worker/wrangler.toml
```

Ключ вводится только в скрытый запрос терминала/серверные настройки. Для HMAC
нужна независимо сгенерированная случайная строка не короче 32 символов.
Не передавайте секреты в чат, аргументы shell, клиентский env, Git или логи.
secret put сразу публикует версию Worker: на этом этапе флаг должен быть false.

## Статика и same-origin API

Нужен HTTPS-домен в Cloudflare DNS с проксируемой записью и работающей статикой
сайта. Можно разместить static build в Cloudflare Pages; это не заменяет
отдельный Worker и его Durable Object. Для проверки сначала используйте
отдельные preview-домен, Pages project и имя Worker, чтобы не менять текущий сайт.

1. Настройте реальный origin в site.ts и vars. Сборка для API:

```bash
PUBLIC_AI_MODE=api PUBLIC_AI_PROVIDER=routerai npm run build
node scripts/stage-pages.mjs
```

2. Публикуйте каталог .cache/pages в выбранный Pages project. Его структура
   сохраняет /test-oge-app/ и _headers. Подключите свой preview-домен в Pages.
3. В корень конфигурации Worker (перед разделом observability) добавьте маршрут
   на этот **же** домен; ниже приведён формат для замены на выбранные имена:

```toml
routes = [
  { pattern = "preview.study.example.org/api/*", zone_name = "example.org" }
]
```

Workers route требует домен зоны Cloudflare и проксируемую DNS-запись.
workers_dev и preview_urls в конфигурации выключены: отдельный workers.dev
не является same-origin API для сайта. Не меняйте connect-src на внешний
провайдер и не включайте CORS вместо маршрута.

4. Сначала разместите отключённый Worker, затем проверьте реальный origin:

```bash
npm run worker:check
npx wrangler deploy --config worker/wrangler.toml
npm run ai:smoke -- https://preview.study.example.org disabled routerai
```

Замените адрес в последней команде. Проверка отправляет только GET health,
проверяет строгий JSON и защитные заголовки; ученические данные не передаёт.
Она не доказывает доступность модели или остаток бюджета. Локально её можно
выполнить с worker:dev и --var SITE_ORIGIN:http://127.0.0.1:8787.

5. После секретов, моделей и денежного лимита включите AI_ENABLED=true,
   опубликуйте Worker и повторите smoke с аргументом enabled. Затем на сайте
   вручную проверьте отказ без POST, разбор верного/неверного ответа, Stop,
   отказ после исчерпания бюджета и отзыв из другой вкладки.
6. Проверьте №15–16 (предварительный балл только после принятия), №13–14
   (только criteria-help/null), сводку без ответов/кода, ссылки на уроки и
   практику. Не используйте реальные данные детей для технического smoke.
7. Отдельно подтвердите остановку размещённого запроса: отмена браузером должна
   прекращать чтение Worker и исходящий запрос модели; отсутствие новых
   данных в UI само по себе этого не доказывает. Просмотрите результат
   размещённого лимитера после простоя/eviction и очистку старых записей alarm.

После внешней проверки запишите дату, origin, версию Worker и фактические
результаты без секретов/IP/текста работ. До этого внешний запуск остаётся
НЕ ПРОВЕРЕНО. Для публичного включения сохраните полный CI/Pages и человеческий
Gate 6 с разбором реальных ошибок после отложенного владельцем пилота.

## Изменения, ротация и отключение

Для изменения лимита/моделей правьте vars и снова публикуйте Worker. Дневной
счётчик атомарный и не обнуляется повторным деплоем. Для немедленного запрета
новых обращений выставьте AI_ENABLED=false и опубликуйте; проверьте disabled.
Уже начатый запрос может завершиться. Для полной остановки расходов также
отзовите/отключите ключ у выбранного сервиса. Клиент покажет пояснение, задачи работают.

Ротация: сначала выключите сервис, создайте новый отдельный ключ с теми же
ограничениями, обновите Secret, проверьте preview, отзовите старый ключ и
только затем включите сервис. Смена AI_IP_HMAC_SECRET создаёт новые HMAC-ключи:
per-IP окно начнётся заново, глобальный дневной счётчик сохранится. Не вращайте
этот секрет для обхода лимитов. Raw IP/работы не должны появляться в логах;
observability в репозитории выключена.
