# Развёртывание сайта и ИИ

Текущее размещение: GitHub Pages, локальное демо. Pages не выполняет Worker.
По выбору владельца подготовлен RouterAI: простые краткие ответы используют
Luna → Sonnet, остальные задания, практика и сводка — Sonnet → Opus.
Три модели задаются только на сервере; на одно действие максимум две попытки.
AI_ENABLED=false. НЕ ПРОВЕРЕНО: настоящие ответы моделей и внешний preview.
Сеть рабочей среды пока отклоняет CONNECT к routerai.ru с 403; ключ не использован.
Домен и доступ Cloudflare для размещения ещё не заданы. Человеческий Gate 6 открыт.

## Где менять настройки

Основное место — [worker/wrangler.toml](../worker/wrangler.toml), раздел vars.

| Настройка | Сейчас | Как менять |
| --- | --- | --- |
| AI_ENABLED | false | Включать true после проверки настроек, секретов и preview |
| AI_DAILY_REQUEST_LIMIT | 600 | Общее число обращений к провайдеру за UTC-день, целое 1–1000000 |
| AI_PROVIDER | routerai | routerai или прежний openrouter |
| AI_API_BASE_URL | https://routerai.ru/api/v1 | Проверяется точное разрешённое значение, произвольные URL запрещены |
| AI_SIMPLE_TASK_NUMBERS | 1,2,3,4 | Уникальные номера №1–12 через запятую; пустая строка отключает простую ветку |
| AI_MODEL_SIMPLE | openai/gpt-6-luna | Основная модель простых разборов |
| AI_MODEL_PRIMARY | anthropic/claude-sonnet-5.5 | Резерв простой ветки и основная модель остальных запросов |
| AI_MODEL_FALLBACK | anthropic/claude-opus-5.5 | Единственный резерв остальных запросов |
| AI_REASONING_EFFORT | low | low, medium или high; расход рассуждений входит в бюджет генерации |
| SITE_ORIGIN | https://exy100.github.io | HTTPS origin настоящего сайта без пути и завершающего / |

Endpoint и точные ID моделей переданы владельцем. Начальный список №1–4 —
изменяемое правило маршрутизации, а не измеренная сложность каждого подтипа.
Выбор делается по задаче, пересобранной сервером. Практика и сводка всегда
используют основную ветку. При неверной конфигурации health остаётся false даже при AI_ENABLED=true.
Смена модели/лимита требует публикации Worker. Это серверные параметры;
ученический экран настроек не может менять расходы или модели.
После размещения их также можно менять в Cloudflare Dashboard → Worker →
Settings → Variables and Secrets (тип Text). Секреты имеют тип Secret.
Следующий deploy из репозитория снова применит vars из файла: сохраняйте
изменения и там, чтобы не потерять выбранные значения.

API-сборка требует **публичных** переменных PUBLIC_AI_MODE=api и
PUBLIC_AI_PROVIDER=routerai. Без первого флага используется демо. Health
возвращает посредника; несовпадение со сборкой запрещает отправку. Новая
policy routerai-feedback-v1 и отдельные ключи кэша не расширяют старое согласие
OpenRouter на RouterAI. Это не секреты и не адрес провайдера. Новый origin
сайта также задаётся в [src/lib/site.ts](../src/lib/site.ts); при переезде
сохраните существующий base /test-oge-app/, пока отдельно не проверены все URL.

## Расчёт на 10 учеников в сутки

Плановая нагрузка: 10 учеников × 30 действий ИИ = 300 ученических запросов.
Каждый допускает максимум две попытки провайдера, включая резервную модель
или исправление JSON. Поэтому задан предел **600 попыток/UTC-день**. Ошибка
провайдера тоже расходует попытку; кэш завершённых ответов снижает нагрузку.
Это ориентир для десяти учеников, а не подсчёт людей: регистрации нет.
Действующие ограничения по IP — 10/минуту, 60/скользящие сутки; общий школьный
NAT делит их между учениками. Увеличение нагрузки меняется здесь, не в клиенте.

600 запросов не равны фиксированной сумме денег. Стоимость зависит от обеих
моделей и числа входных/выходных токенов. Максимум ответа: 700/500/1200 токенов
для разбора/практики/сводки; вход тоже платный. После выбора моделей рассчитайте
стоимость каждой попытки по их актуальным тарифам и задайте денежный предел
отдельного ключа RouterAI. Тарифы прежнего агрегатора не являются тарифами RouterAI.
Серверный счётчик
и денежный предел ключа нужны одновременно; повтор и неуспех не возвращают квоту.

## Подготовка аккаунта и секретов

1. В RouterAI создайте отдельный ключ с ограничением расходов. Для теста
   используйте синтетические задачи. По политике RouterAI текст запросов
   обычно не сохраняется и не используется для обучения, но предусмотрены
   исключения служебного логирования. Провайдеры моделей обрабатывают текст
   по собственным правилам. Worker передаёт provider.data_collection=deny;
   выполнение этого ограничения RouterAI и апстримами НЕ ПРОВЕРЕНО. Это не ZDR-гарантия.
2. Три ID уже вписаны в vars. Проверьте доступность SSE и JSON на тестовом
   ключе, оставив AI_ENABLED=false. Для RouterAI используется reasoning.low,
   include_reasoning=false; temperature не навязывается reasoning-моделям.
   Пределы 700/500/1200 токенов и дедлайн 30 секунд сохранены. Если рассуждения
   исчерпают предел, обрыв не считается завершённым ответом.
3. Создайте Cloudflare Worker с доступом к SQLite Durable Objects. Привязка
   AI_QUOTA и миграция v1-ai-quota уже в конфигурации. Нельзя удалять миграцию
   или заменять атомарный лимитер локальным счётчиком.
4. Передавайте секреты через Cloudflare Dashboard → Variables and Secrets,
   тип Secret, или интерактивно из терминала:

```bash
npx wrangler secret put ROUTERAI_API_KEY --config worker/wrangler.toml
npx wrangler secret put AI_IP_HMAC_SECRET --config worker/wrangler.toml
```

Ключ вводится только в скрытый запрос терминала/серверные настройки. Для HMAC
нужна независимо сгенерированная случайная строка не короче 32 символов.
Не передавайте секреты в чат, аргументы shell, клиентский env, Git или логи.
secret put сразу публикует версию Worker: на этом этапе флаг должен быть false.

## Ограниченный тест провайдера

Команда не входит в verify или CI. Она использует существующий клиент,
настоящие синтетические задачи и максимум **три внешних HTTP-запроса**:
Luna/SSE для №1, Sonnet/JSON для №16, Opus/SSE для сводки. Для последней
пробы Opus явно ставится основным только в изолированной конфигурации теста;
ошибка провайдера не имитируется и производственная таблица не меняется.
Эта отдельная команда делает платные запросы даже при AI_ENABLED=false.
Резервные попытки тоже входят в предел трёх. При любой неудаче команда
завершается с ненулевым кодом и не утверждает, что все модели проверены.

В интерактивном Bash ключ можно прочитать без эха и аргументов команды:

```bash
read -rsp 'Тестовый ключ RouterAI: ' ROUTERAI_API_KEY
export ROUTERAI_API_KEY
npm run ai:provider-smoke
unset ROUTERAI_API_KEY
```

Node использует штатный --use-env-proxy и доверенные CA среды. Endpoint
разрешён только https://routerai.ru/api/v1/chat/completions, редиректы запрещены.
Выводятся только режимы, HTTP-статусы и счётчик запросов: без ключа, текстов
работ и ответов моделей. Среде нужен разрешённый исходящий доступ к routerai.ru.
При сетевом отказе меняются разрешённые хосты среды; прокси и проверка TLS сохраняются.

## Статика и same-origin API

Нужен HTTPS-домен в Cloudflare DNS с проксируемой записью и работающей статикой
сайта. Можно разместить static build в Cloudflare Pages; это не заменяет
отдельный Worker и его Durable Object. Для проверки сначала используйте
отдельные preview-домен, Pages project и имя Worker, чтобы не менять текущий сайт.

1. Настройте реальный origin в site.ts и vars. Сборка для API:

```bash
PUBLIC_AI_MODE=api PUBLIC_AI_PROVIDER=routerai npm run build
node scripts/stage-pages.mjs
```

2. Публикуйте каталог .cache/pages в выбранный Pages project. Его структура
   сохраняет /test-oge-app/ и _headers. Подключите свой preview-домен в Pages.
3. В корень конфигурации Worker (перед разделом observability) добавьте маршрут
   на этот **же** домен; ниже приведён формат для замены на выбранные имена:

```toml
routes = [
  { pattern = "preview.study.example.org/api/*", zone_name = "example.org" }
]
```

Workers route требует домен зоны Cloudflare и проксируемую DNS-запись.
workers_dev и preview_urls в конфигурации выключены: отдельный workers.dev
не является same-origin API для сайта. Не меняйте connect-src на внешний
провайдер и не включайте CORS вместо маршрута.

4. Сначала разместите отключённый Worker, затем проверьте реальный origin:

```bash
npm run worker:check
npx wrangler deploy --config worker/wrangler.toml
npm run ai:smoke -- https://preview.study.example.org disabled routerai
```

Замените адрес в последней команде. Проверка отправляет только GET health,
проверяет строгий JSON и защитные заголовки; ученические данные не передаёт.
Она не доказывает доступность модели или остаток бюджета. Локально её можно
выполнить с worker:dev и --var SITE_ORIGIN:http://127.0.0.1:8787.

5. После секретов, моделей и денежного лимита включите AI_ENABLED=true,
   опубликуйте Worker и повторите smoke с аргументами enabled routerai. Затем на сайте
   вручную проверьте отказ без POST, разбор верного/неверного ответа, Stop,
   отказ после исчерпания бюджета и отзыв из другой вкладки.
6. Проверьте №15–16 (предварительный балл только после принятия), №13–14
   (только criteria-help/null), сводку без ответов/кода, ссылки на уроки и
   практику. Не используйте реальные данные детей для технического smoke.
7. Отдельно подтвердите остановку размещённого запроса: отмена браузером должна
   прекращать чтение Worker и исходящий запрос модели; отсутствие новых
   данных в UI само по себе этого не доказывает. Просмотрите результат
   размещённого лимитера после простоя/eviction и очистку старых записей alarm.

После внешней проверки запишите дату, origin, версию Worker и фактические
результаты без секретов/IP/текста работ. До этого внешний запуск остаётся
НЕ ПРОВЕРЕНО. Для публичного включения сохраните полный CI/Pages и человеческий
Gate 6 с разбором реальных ошибок после отложенного владельцем пилота.

## Изменения, ротация и отключение

Для изменения лимита/моделей правьте vars и снова публикуйте Worker. Дневной
счётчик атомарный и не обнуляется повторным деплоем. Для немедленного запрета
новых обращений выставьте AI_ENABLED=false и опубликуйте; проверьте disabled.
Уже начатый запрос может завершиться. Для полной остановки расходов также
отзовите/отключите ключ у выбранного посредника. Клиент покажет пояснение, задачи работают.

Ротация: сначала выключите сервис, создайте новый отдельный ключ с теми же
ограничениями, обновите Secret, проверьте preview, отзовите старый ключ и
только затем включите сервис. Смена AI_IP_HMAC_SECRET создаёт новые HMAC-ключи:
per-IP окно начнётся заново, глобальный дневной счётчик сохранится. Не вращайте
этот секрет для обхода лимитов. Raw IP/работы не должны появляться в логах;
observability в репозитории выключена.
