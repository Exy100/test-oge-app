# Демонстрационный разбор и замена источника ответов

По решению владельца от 2026-10-28 (ADR-056, T6.0) сайт показывает локальные
заготовленные ответы до подключения настоящего ИИ. Регистрация, API-ключи,
домен сервера и платные запросы этому режиму не нужны.

## Где открыть

В потоке, упражнении на главной или тренировке варианта проверь краткий ответ
№1–12, затем нажми «Показать пример разбора». Панель помечена как
«Демонстрационный режим». Для верного и неверного ответа предусмотрены разные
заготовки. Это примеры оформления и поведения интерфейса, а не анализ ИИ.

Можно остановить получение и повторить его с начала. При смене задания или
черновика прежний разбор отменяется. Ответ не сохраняется после перезагрузки,
не меняет баллы и прогресс. У практических работ №13–16 нет демонстрационных
оценок; на экзамене с таймером этот блок не показывается.

После завершения примера появятся «Материалы по теме задания». Это подбор
опубликованных уроков по номеру, а не персональная рекомендация ИИ. Урок
открывается в новой вкладке; закрой её, чтобы вернуться к открытой карточке.
Ответ, черновик и текст примера остаются в исходной вкладке. В адрес урока
не добавляются ответ, черновик или seed.

Рядом доступна ссылка «Решать задания №…». Она открывает поток в новой
вкладке с фильтром текущего номера. Сам переход не засчитывает попытку.
Когда решишь новую задачу, общий прогресс обновится; исходный ответ, черновик
и разбор останутся в первой вкладке. Переход к следующему заданию в ней
не засчитывает старый ответ повторно. Сброс данных в настройках очищает
прогресс и принятую карточку, как и прежде.

## Разделение модулей

| Модуль | Ответственность |
| --- | --- |
| [contract.ts](../src/lib/ai/contract.ts) | `FeedbackProvider`, строгий запрос, ограничения и ошибки |
| [demo-provider.ts](../src/lib/ai/demo-provider.ts) | Два заготовленных текста; выбор по существующей локальной проверке; выдача фрагментов с отменой |
| [provider.ts](../src/lib/ai/provider.ts) | Выбор источника, его название и пояснение для ученика |
| [feedback.ts](../src/lib/ai/feedback.ts) | Получение фрагментов, предел ответа 12000 символов, проверка отмены и безопасный рендер |
| [AiPanel.tsx](../src/components/ai/AiPanel.tsx) | Состояния интерфейса, остановка, повтор и фокус |
| [TaskCard.tsx](../src/components/tasks/TaskCard.tsx) | Подключение общего блока после проверки краткого ответа |

`FeedbackProvider.streamFeedback(request, signal)` возвращает
`AsyncIterable<string>` с Markdown. В запросе только `generatorId`, `seed`,
`answer` до 300 символов и необязательный `reasoning` до 1500 символов.
Идентификатор и seed ограничены 200 символами, всё тело — 8 КБ. Лишние поля
отклоняются. Условие, эталон и решение не передаются через этот контракт.

Модули получения и рендера загружаются при нажатии кнопки. При ошибке импорта
повтор использует свежий URL через существующий `importFreshModule`.
Источник обязан учитывать `AbortSignal`; потребитель дополнительно отвергает
запоздалые фрагменты и закрывает поток при превышении размера.

Ссылки на уроки рисует `AiPanel` из существующего `preparationLessons` по
`taskNumber`, полученному от карточки. Этот контекст не добавляется в запрос
источнику. `sitePath` сохраняет базовый путь GitHub Pages, `noopener` изолирует
новую вкладку. Произвольные ссылки из Markdown по-прежнему удаляются общим
renderer; источник не выбирает адреса переходов.

Ссылка на практику использует существующий `lessonStreamHref([taskNumber])`.
В URL только фильтр номера: это тематическая практика, а не персональный
подбор ИИ. `Stream` обновляет счётчики от другой вкладки без размонтирования
открытой карточки. Уменьшение общего счётчика после сброса или восстановления
более раннего прогресса по-прежнему сбрасывает принятую карточку.

## Подключение настоящего API

T6.6 реализует `api-provider.ts`: тот же FeedbackProvider отправляет строгий
JSON на /api/ai/stream-feedback своего origin и читает нормализованный SSE.
Клиент не знает ключа/моделей, не отправляет cookies и не следует redirect.
30 секунд на весь ответ, обязательный DONE, пределы байтов/кадров/текста;
обрыв и event error не дают завершённого ответа. Ошибки HTTP/SSE показаны
без диагностик сервера. PUBLIC_AI_MODE=api выбирает этот адаптер в потоке,
на главной, в тренировке и завершённом варианте. Без флага сохраняется демо.
До отправки проверяется строгий health; false/ошибка не блокируют задачи.

`AiPanel` принимает отдельный API loader. Перед первым использованием показывает
условия передачи через наш сервер → OpenRouter → провайдер модели и точные
ответ/черновик. Отказ и Escape не создают запросов. Старое aiConsent.enabled
не является согласием: нужна policy openrouter-feedback-v1, выданная диалогом.
Импорт переносит предпочтение, но не разрешение отправки. Отзыв через настройки,
в том числе из другой вкладки, отменяет активный запрос и очищает вывод/кэш.
Изменение задания, ответа или черновика размонтирует старый запрос.

`render.ts` применяет узкий DOMPurify allowlist поверх общего Markdown/KaTeX
MathML. Только известные токены lesson/stream превращаются в ссылки каталога
с новой вкладкой/noopener; произвольные ссылки и картинки не создаются,
неизвестные токены удаляются. Код и формулы не интерпретируются как токены.

API-кэш использует существующий SessionCache: ≤30 записей/500 КБ. В нём только
завершённый Markdown, никогда готовый HTML. Ключ учитывает версию режима,
хэш generatorId+seed, ответ и черновик. Кэш заново санитизируется; ошибка,
остановка и недополученный ответ не записываются. При недоступном sessionStorage
кэш остаётся в памяти. Демонстрационный режим не использует этот кэш.
При изменении условий передачи/провайдера нужно обновить policy и версию ключа.

Страница /dev/ai/ существует только в Astro dev. Она проверяет настоящий клиент
с перехваченным same-origin API в e2e; сама dev-страница не входит в static dist.
Опубликованный сайт по умолчанию сохраняет заготовленные ответы и не обращается к ИИ.

В API-сборке завершённого варианта доступны предварительный разбор №15–16,
помощь по критериям №13–14 без балла и сводка только по агрегатам. Каждому
режиму нужно отдельное согласие modes; прежняя policy не расширяется на код
или сводку. Принятие предварительного балла явно пишет aiAccepted; офисный
null не становится нулём. Точные настройки и расчёт лимита для 10 учеников —
в [docs/deploy.md](deploy.md), серверные модели в клиент не передаются.

Переход к реальному сервису включает T6.1–T6.10: серверную пересборку задачи,
проверку запросов, OpenRouter, лимиты, бюджет, информированное согласие и
прочие требования spec §11. Ключ хранится только на сервере. Существующее
предпочтение `aiConsent` не разрешает отправку неизвестному провайдеру.
Локальный демонстрационный режим не закрывает эти задачи и Gate 6.

## Проверки

`tests/unit/ai-demo-provider.test.ts` проверяет заготовки и отмену без сети.
`tests/unit/ai-feedback.test.ts` использует заменяемые источники для проверки
границ запроса/ответа, безопасного вывода и запоздалых фрагментов.
`tests/e2e/ai-demo.spec.ts` проверяет опубликованные страницы, ошибки загрузки,
повтор, отсутствие API-запросов, сохранение прогресса и доступность панели.
`tests/unit/ai-client.test.ts` — 45 сценариев реального SSE-клиента, кэша,
согласия и XSS; `tests/e2e/ai-client.spec.ts` — диалог, отказ, повтор, безопасный
рендер/формулы/ссылки, кэш после reload, изменение черновика, остановка и отзыв
из другой вкладки. Обе темы, 200% текста, axe; шесть профилей в CI.
