# Вопросы и разбор требований

Дата: 2026-10-04. Разбор документов T0.1 завершён.

Прочитаны полностью `spec.md`, `tasks.md` и `PROMPT.md`.
Согласованные изменения хостинга и распределения задач внесены в `spec.md` и

## Вопросы, заданные владельцу

### Q1. Хостинг текущего этапа — ответ получен

- Основание: `spec.md §4.1`, `§11.1`, `§12`; существующий сайт работает на GitHub Pages.
- Спецификация требует Cloudflare Pages, отдельный Worker и API на том же домене.
  GitHub Pages сам по себе не исполняет Worker и не применяет файл Cloudflare `_headers`.
- Ответ владельца: «пока в пейджес» (2026-10-04).
- Решение: на текущем этапе размещать статическую часть тренажёра на GitHub Pages,
  включая будущую сборку Astro. Учитывать префикс `/test-oge-app/` в маршрутах и ресурсах.
- Временное решение не отменяет требования к ИИ и безопасности. Размещение API
  и заголовки, которые GitHub Pages не позволяет задать, требуют отдельного решения
  перед соответствующими этапами. Зафиксировано в `DECISIONS.md`, ADR-001.
- Статус: решён для текущего этапа; конечная инфраструктура ИИ пока не выбрана.

### Q2. Минимальная доля номеров в потоке — ответ получен

- Основание: `spec.md §9.4`, `tasks.md T4.1`.
- Можно выбрать номера 1–25, но нижняя доля 5% на каждый при 25 выбранных номерах
  требует 125%. Это невыполнимое ограничение.
- Ответ владельца на предложение распределять 50 % равномерно и 50 % по слабым
  темам: «нормально - вперед» (2026-10-04).
- Решение: 50 % вероятности поровну между выбранными номерами, 50 % — по весам
  ошибок. Нижняя доля — `0.5 / N`, при выборе всех 25 номеров — 2 %.
  Без статистики и при одинаковых результатах выбор равномерный.
- Статус: решён; актуализированы `spec.md §9.4` и `tasks.md T4.1`, см. ADR-002.

## Выявленные зависимости плана

Эти замечания не изменяют исходные требования и не означают согласованного отклонения.
Перед затронутой задачей нужно зафиксировать конкретное решение и его проверки.

- `T1.1` требует успешный `verify`, а входящие в него `check:forbidden` и
  `check:coverage` создаются в `T1.2`. Нельзя подменять их командами, всегда
  возвращающими успех. При подготовке Фазы 1 нужно согласовать порядок этих зависимостей.
- `T1.3` требует зелёный CI с e2e и Lighthouse до появления дизайна и страниц в
  `T1.4–T1.7`. Нужна реальная проверяемая страница уже к запуску CI; нельзя
  объявлять отсутствующие проверки пройденными.
- `PROMPT.md §3.5` требует `npm run verify` в конце каждой фазы, но npm-проект
  появляется только в Фазе 1. Gate 0 из `tasks.md` проверяет документы и ответы
  владельца. В отчёте Фазы 0 следует отдельно указать, что npm-проверки ещё недоступны.
- `T7.4–T7.10` допускают временную статическую SVG вместо интерактива до T8.10;
  `spec.md §10.2` требует интерактив в каждом уроке. Допуск промежуточного этапа
  следует учитывать в проверках по фазам; финальная проверка обязана требовать интерактивы.

## Объём, который нельзя незаметно сократить

- Нижняя граница 36 уроков не отменяет перечень обязательных тем:
  таблица `spec.md §10.1` и задачи `T7.4–T7.10` в сумме требуют минимум 45 уроков.
- Нижняя граница 16 двумерных интерактивов не отменяет задачи `T8.2–T8.6`:
  план включает все 18 перечисленных интерактивов.
- Трёхмерных игр минимум 5, у каждой минимум 3 уровня; шестая игра необязательна.
- Минимум 10 фиксированных вариантов. Генераторы проверяются на 500 seed'ах
  каждый; банки №24 и №25 содержат минимум по 12 задач.

## Что проверяется по официальным источникам в T0.2

- `spec.md §3.1`: наличие и статус материалов ФИПИ на 2027 год; при отсутствии
  использовать 2026 год с явной пометкой. Демоверсия, спецификация, кодификатор.
- `§3.2`: номера, содержание, модули, форматы ответов, максимальные баллы.
- `§3.3`: количество заданий, максимум баллов, длительность, калькулятор и
  разрешённые справочные материалы; их содержание для собственного справочного листа.
- `§3.4`: рекомендуемая шкала, минимальные баллы за геометрию, год и источник;
  региональные особенности не выдавать за единую обязательную шкалу.
- `§3.5`: сюжеты заданий 1–5 в открытом банке ФИПИ.
- `§5`, `§6.2`, `§11.6`: коды тем кодификатора и формат критериев оценивания
  развёрнутых решений; дальнейший контент должен опираться на сверенные документы.
- Производные значения в `§9.6–9.7`, `T2.3`, `T2.5`, `T3.13`, `T6.4` должны
  соответствовать результату сверки, а не несверенным числам из примеров.

Факты об экзамене на этом шаге ещё не сверены; `VERIFIED` не выставлен.

## Вопросы для будущих этапов

- Название и конечный домен сайта — перед настройкой публикации и метаданных.
- Основная и резервная модели OpenRouter, дневной бюджет и лимит кредитов —
  перед реальной интеграцией ИИ в Фазе 5. Секреты вводятся через настройки Worker,
  не в чат и не в репозиторий.
- Turnstile по спецификации по умолчанию выключен; включение требует отдельного решения.
- Кто проверяет математические решения и уроки перед публикацией —
  до приёмки математического контента.
